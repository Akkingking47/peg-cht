### 3.3 生成器缺陷 `gen_scn.py` W16-bis（尾部补位扫描容忍行尾分隔符）
- 旧逻辑 `for ch in reversed(orig): if CTL.match(ch): tail.append(ch) else: break` —— `CTL` **不含 `\x0d`**。
- `usvsussr10.txt:0` 是 `Allied Forces seize Vladavostok` + **NUL×470 + `\r`** ⇒ 倒扫第一个字符就是 `\r` ⇒ 一个 NUL 都没搬 ⇒ 报「控制字符个数不一致」，**整文件被拒**。
- 新逻辑：`if CTL.match(ch) or ch in "\r\n\t ": tail.append(ch) else: break`。下游 `nb = (lead + zh.strip() + trail).encode("gbk")`，`lead/trail` 取自 `orig.lstrip()/rstrip()` ⇒ 不会重复补位。
- 顺带修正 3 个文件（原文是 `句号+空格+NUL`，旧逻辑丢空格）：`BoB_BoB04_i.txt:27`、`DAK_DAK8_i.txt:8`、`DAK_DAKTU02_i.txt:5`。

### 3.4 「译文＝原文」的自等行：`Viel Glück!`
`ww2-scn-map.tsv` 行 4597 是 `Viel Glück!` → `Viel Glück!`（**en 与 zh 完全相同**、标 `人工确认`）⇒ `DAK_SP1_i.txt:6`、`Fi04_i.txt:6` 两处一直是德文原句。
- 规范形取同表 ASCII 兄弟行 `Viel Gluck!` → `祝好运！`（词库已有）⇒ 改为 **`祝好运！`**，src 归 `词库`。工具 `work\glossary\fix_self_identity_rows.py`（备份 `backup\before-vielgluck\`）。
- **教训（重要）**：英文原件由 `gen_scn.py:180` 用 **latin-1** 解码（1 字节 = 1 码位，`ü`=0xFC → U+00FC 仍是 `ü`）。先前用 **UTF-8** 读原件做「这一行是否真存在于原件里」的核查，把含高位字节的行误判成「映射表遗留死行」⇒ **任何针对原件的核查都必须与生成器同用 latin-1**。
