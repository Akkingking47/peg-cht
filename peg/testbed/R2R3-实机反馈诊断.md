## 二、根因：引擎给**每一次**文字绘制都强制加了 `DT_WORDBREAK`

反汇编 `PeG030.exe`（全部文字只有 2 个 `DrawTextExA` 调用点，均在文本 helper 内）：

```
helper @VA 0x47170C
  ...
  0x4717E2   or  al, 0x10          ← ★ DT_WORDBREAK = 0x10，强制或入调用方传入的标志
  0x4717E7   push 0                ; lpDTP = NULL
  0x4717E9   push ecx              ; format = [ebp+0x1c] | 0x10
  0x4717ED   push &rect            ; 调用方给的矩形（helper 内再叠加 dx,dy 偏移）
  0x4717F4   push [ebp-8]          ; cchText
  0x4717F8   push [ebp+0x18]       ; lpchText
  0x4717FC   push DC
  0x4717FD   call DrawTextExA
另有一处 @VA 0x4701D1 传 flags = 0x410 = DT_CALCRECT|DT_WORDBREAK（量高用）
```

**为什么英文没事、中文出事**：
- 英文有空格，`DT_WORDBREAK` 只在**词间**断行 → 单词再长也不折；
- **中文没有空格，GDI 允许在任意字间断行** → 只要矩形比整串窄，就**逐字折行**。

## 三、离线复现（决定性证据）

`peg\testbed\wrap-experiment.py`：用与游戏**完全相同**的字体与 `DT_WORDBREAK`，
把 `购买单位` 画进不同宽度的矩形（高 14px ≈ 一行）：

| 矩形宽 | 实际画出 | 读数 |
|---:|---|---|
| 16–20 px | `购` | 每行 1 字，第二行被高度裁掉 |
| 24–32 px | `购买` | 每行 2 字 |
| 36–44 px | `购买单` | 每行 3 字 |
| 48+ px | `购买单位` | 完整一行 |

**★ 关键**：当矩形**高度只够一行**（截图里的情形），第二行的字只露出**上半截** ——
在 12px 宋体上，一个汉字的上半截看起来就是一个**小方块**。
⇒ 截图里的「洋红方块」＝ **折行后第二行首字的残影**，不是缺字、也不是乱码。
（证据图 `out/wrap-experiment.png`，右列 W=36/H=20 一格与你截图里的形态一致。）

---

## 四、由此得到的硬规则

> **按钮/短标签的可用宽度只有「2–3 个汉字」**（视具体矩形而定），
> 超出的字会折到第二行；而矩形高度只留一行 ⇒ 多出的字**看不见**（只剩残影）。

这同时解释了用户感到的 **「文字漂移 / 英文对不上号」**：
标签被截成半截后，读出来的字**不再等于**原本的译文 ⇒ 看起来就像「贴错了标签」。

⇒ **这不是译错，也不是编码错，是「译文比格子宽」。**

## 六、如果不想改翻译口径，还可改 exe（有风险，暂不推荐）

| 方案 | 改法 | 风险 |
|---|---|---|
| A 全局去折行 | `0x4717E2` 的 `or al, 0x10` → `or al, 0x20`（DT_SINGLELINE） | ❌ **会让简报/长文本不再按 CRLF 换行**，破坏战役简报 |
| B 全局不折行 | 把该 `or` 指令 NOP 掉 | ⚠️ 同 A，取决于各调用方是否自传 `0x10` |
| C 按调用方区分 | 需先查明哪些调用方传了什么 flags | 最干净但工作量大 |

⇒ **推荐先走「翻译层适配」**（零风险、可复算）：按探针测出的每格容量给字数预算。
若后续确有少数格子放不下关键术语，再考虑 C 方案的单点补丁。
