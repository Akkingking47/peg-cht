## 一、已确证的事实（可复算）

### 1.1 「英文错配」的根因 = 加载器把 `0x80–0xFF` 判为「行尾」→ 整表错位

- 加载器 `Text.c`：`sub_46E85C`（VA `0x46E800`），逐**字节**扫描，用类别表判行尾：
  `cls = table[byte] & 0x157`，`cls==0` ⇒ 断行；**行长 == 0 的行被跳过、不占行号**。
- 类别表指针 `[0x4ABA80] = 0x4ABA8A`（已核对，两版 exe 一致）；`[0x4ABC8C] = 1` ⇒ 走内联表分支。
- 原版表：`0x80–0xFF` 共 128 项 class = `0x0000` ⇒ 全是「行尾」。
  ⇒ 中文行的**每个字节都断行** ⇒ 该行整体消失、**其后行号整体错位**。
- **离线模拟对照**（同一份现网文件，两张表）：

| 表 | 解析出的行数 | 行 40 | 行 46 | 行 64 |
|---|---:|---|---|---|
| 原版表（`PeG030.exe` 原始） | **643** | `Air Transport` | **`Additional Options`** | `Helo or naval target` |
| 补丁表（`PeG030zh.exe`） | **653** | `下一单位` | **`购买单位`** | `检视部队` |

⇒ **原版表下场「行 46 变成 Additional Options」正是「英文选项不是原按钮功能」。**

### 1.3 文本绘制的真实管线（反汇编实证）

```
绘制：sub_47170C(rect*, xOff, yOff, surface, str, flags)
      → surface->GetDC() → SetTextColor/SetBkMode(1)/SelectObject(font)
      → DrawTextExA(hdc, str, strlen(str), rc={rect.left+x, rect.top+y, rect.right+x, rect.bottom+y},
                    flags | 0x10 /* 强制 DT_WORDBREAK */, NULL)
      → surface->ReleaseDC()
测量：sub_47010B(str, &a, &b, &nLines, rect)  = DrawTextExA(..., DT_CALCRECT|DT_WORDBREAK, ...)
      → 就地改写 rect 为实测包围盒；返回 行数 = 高/14
取子串：sub_46FEDD(str, idx, rect)  ← 二分查找【字节偏移】mid，返回 str+mid（DBCS 不安全）
UI 元件：几何表 VA 0x4A96E8，271 条 × 15B = {x1,y1,x2,y2 (int16), f8 (int16), flags (u16)}
       flags & 7 = 对齐（2=居中 3=右对齐 其它=左），flags & 4 = 带阴影
       sub_4704D2(elemId, fmt, ...) —— 主画字 API（233 处调用）
```

## 二、根因：`sub_46FEDD` 用【字节】二分查找来「丢前 N 行」

```
sub_46FEDD(str, idx, rect):
  n = 该串在这个 rect 里需要几行   ← sub_471696 → sub_47010B → DrawTextExA(DT_CALCRECT|DT_WORDBREAK)
  if (idx <= 0 || idx >= n) return str;      ; ★ 装得下 ⇒ 原样返回
  二分查找 byte offset mid 使 lines(str+mid) == n-idx
  return str + mid                            ; ★ 装不下 ⇒ 从第 mid 个【字节】开始画
```

**分水岭（这就是「英文没事、中文乱」的原因）：**

| | 换行行为 | n | 结果 |
|---|---|---:|---|
| 英文 | 只在**空格**处断行 ⇒ 标签一般 1 行 | 1 | `idx >= n` ⇒ **原样返回，永不错位** |
| 中文 | 可在**任意字间**断行 ⇒ 框窄就多行 | >1 | 落进「丢前 N 行」，而 mid 是**字节**偏移 ⇒ **落在半个汉字上** ⇒ 掉字 / 显示成别的字 / 方块 |

**实测量**：`sub_47010B` 的出口（VA `0x4701F1` 起）确认 —— `*out1 = rect.right-left`（**实测宽**）、
`*out2 = rect.bottom-top+3`、返回值 `= rect.top/14`（**行数**）。都是 GDI 测的，**DBCS 正确** ⇒ 量宽本身没问题，
**问题在「丢掉前 N 行」这一步是按字节做的**。

> 调用者的 `idx` 都来自常量 `0` 或全局 **`[0x4AF5B8]`**（行偏移全局量）。

## 三、治本补丁 #2（已产出并校验）

```
0x46FF0D  movsx eax, word [ebp+0xc]   ; idx
0x46FF11  test  eax, eax
0x46FF13  jle   0x46FF1E              ; idx<=0 ⇒ 返回原串
0x46FF15  movsx ecx, word [ebp+0xc]
0x46FF19  cmp   ecx, [ebp-0x24]       ; n
0x46FF1C  jl    0x46FF26     ◀── 改这里： 7C 08 → EB 00（jmp 0x46FF1E）
0x46FF1E  mov   eax, [ebp+8]          ; 返回原串
0x46FF21  jmp   0x470052
```

**`7C 08` → `EB 00`**：`jl`（条件）改为 `jmp`（无条件跳到「返回原串」）⇒ **永不丢前 N 行**。
同长度、同位置、不破坏指令边界。

**副作用**：极度超宽的标签由「显示尾部」变成「显示头部」（矩形仍会纵向裁剪）。英文本就 `n=1`，不受影响。

**产物**：`PeG030zh.exe`（含补丁 #1 + #2），md5 `1505906716…`；与原版差异 **恰好 130 字节**（128 + 2）✅
脚本：`peg\testbed\patch-labeldrop.py`（`patch` / `verify` / `remove`）。
