## 一、为什么 PeG 适合做这个研究对象

已实测的三条结构性事实，本身就是「文化渗透」的机制证据：

| # | 事实 | 实测来源 | 机制含义 |
|---|---|---|---|
| 1 | **文本 100% 外置**：exe 只硬编码文件名 stem（`gui030/Equip30/misc030/name030/tips030`），界面/装备/人名/简报全为可编辑纯文本 | `PeG030.exe` 字符串表；`Text.c` 模块 | 语言外壳与游戏内核解耦 ⇒ **换语言、换立场几乎零成本** |
| 2 | **阵营是「可换壳的槽位」**：同一 20 个槽位，在不同 e-file 里被重标为完全不同的阵营 | `Gui030.txt` 行 1–20 vs `GUI98.TXT` / `GUISA.txt` / `GUISP.TXT` 同行 | 不是「国别表」而是**阵营模板**，同一引擎可装进任意地缘叙事 |
| 3 | **二进制层零文本**：`.scn`×213 每文件仅 2 个文件名引用；`.map`×46 可打印串 0；`.eqp` 仅图标码 | `work\peg\census_text.py` | 文案与数据的彻底分离，使本地化/改写成为**纯文本作业** |

补强事实：**官方即做过德/法两套文本包**（`GUI97.DEU` / `GUI97.FRA`），exe 内仍保留
`lang.cfg` + `LoadLanguageConfigFile` + `german`/`french` 比较路径 ⇒ 多语言是**厂商原生设计**，
社区俄语 MOD 只是在既有机制上加了一层。

## 三、观察主表 `observations.tsv`

**列定义**

| 列 | 含义 | 填写方 |
|---|---|---|
| `obs_id` | 观察点编号（`O1-01` … `O5-08`） | 已预填 |
| `分类` | O1 阵营槽 / O2 叙事立场 / O3 多语言实践 / O4 外置化程度 / O5 符号层 | 已预填 |
| `原文` | 原始文本（英/德/法/俄，原样，不改写） | 已预填 |
| `出处文件` | 精确到文件 | 已预填 |
| `定位` | **行号 / VA / 图形索引**，可当场复算 | 已预填 |
| `观察要点` | 该条能说明什么（结构性机制，非评价） | 已预填 |
| `中文译文` | 汉化译文（**保真直译，不作立场修正**） | **待填** |
| `译者` | 译者/批次 | 待填 |
| `状态` | `待填` → `已译` → `已核` | 待填 |

**当前进度**

| 分类 | 条数 | 含义 |
|---|---:|---|
| O1 阵营槽 | 20 | PeG 3.0 的 20 个固定槽位（`Gui030.txt` 行 1–20 ＋ exe 内置表 VA `0x492FEC` 起，步长 20 B） |
| O1 槽位复用 | 7 | 同槽位在 `GUI98.TXT`/`GUISA.txt`/`GUISP.TXT` 被重标 ⇒ 阵营模板化的直接证据 |
| O2 叙事立场 | 12 | 14 个 `.ply` 场景简介＋用户场景（含 `RetStal27.ply` 525 B 例外） |
| O3 多语言实践 | 4 | 英/德/法三套官方文本包、exe 内 `lang.cfg` 路径、社区俄语标题 |
| O4 外置化程度 | 5 | 5 个 stem、GUI/装备/人名/场景各层的规模 |
| O5 符号层 | 8 | 胜利分级（Brilliant Victory … Loss）、荣誉榜、勋章界面、`Flak` 兵种 |
| **合计** | **56** | |

**填证规范**

1. **原文一律不改写**，包括其中的专名与表述；只在 `中文译文` 列做语言转换。
2. `定位` 列给出的行号/VA 必须能复算命中；改过原文则同步更新定位。
3. 每条只标注**能由文件直接支撑的机制**，不写评价性判断（评价留给你在论文/笔记里下）。
4. 状态流转 `待填 → 已译 → 已核`，`已核` 表示「按定位复算过、译文与原文一一对应」。

## 四、关键定位速查

| 对象 | 定位 |
|---|---|
| 国家槽表（exe 内置，20 × 20 B） | VA `0x492FEC` ~ `0x493168`（FO `0x907EC` ~ `0x90968`） |
| 兵种表（exe 内置，20 B 步长） | VA `0x492C2C` 起（Infantry / Tank / Recon / Antitank / **Flak** / Fort / Truck / Artillery / Air Defense / Fighter / Tac Bomber …） |
| 月份名 | FO `0x8B47C` ~ `0x8B500` |
| 天气 | VA `0x4931B0`（Fair）/ `0x4931D8`（Rain）/ `0x4931EC`（Snow） |
| 移动类型 | FO `0x90720` ~ `0x90784`（Wheeled / Leg / Air / Deep Naval / Amphibious / ASW） |
| 图形打包档 | `CWGEN.dat`：`u32 n`(3367) ＋ `u32 目录末` ＋ N ×（13 B 名 ＋ u32 偏移） |
| `.s16` 索引项 | 40 B：`w, h, startX, startY, fullW, fullH, starts, nbytes, comp, loadAddr` |
| `.s16` 压缩 | RLE ＝ `重复次数(u8) ＋ 颜色(u16)`（16bpp RGB565）；`comp=0` 为原始流 |

## 五、复算方式

```bash
cd <本仓库克隆目录>
PY=python        # 你自己的 Python 3；或先 `call env.cmd` 注入 PY
$PY work/peg/extract_research.py    # 重建 evidence/ 全部素材
$PY work/peg/gen_observations.py    # 重建 observations.tsv（预填列）
```

⚠️ 所有素材文件均为**只读导出**；`%PEG_GAME%`（游戏目录）内**原文零改动**。
