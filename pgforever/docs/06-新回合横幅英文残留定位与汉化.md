# 06 - 新回合横幅英文残留的定位与汉化（P5）

> 起始问题：进入战役后，新回合横幅显示
> `Axis 回合 1` / `September 1, 1939` / `Clear(Dry)` / `剩余 10 回合`
> —— **半中半英**：`回合`、`剩余` 已是中文，`Axis`、`September 1, 1939`、`Clear(Dry)` 仍是英文。

## 一、这个画面在哪里？

### 1.1 模板层（静态文字，已汉化）

```
D:\PGForever1.021\Default\UI\newturn.htm      ← 全局默认模板
D:\PGForever1.021\<Game>\UI\newturn.htm       ← 各 game 级覆盖（如 Cyber General）
```

模板结构（模板里的 `回合` 是**静态文本**，所以早就显示中文了）：

```html
<span id="Side" /> 回合 <span id="CurrentTurn" /><br />
<span id="Time" /><br />
<span id="Date" /><br />
<span id="Weather" /><br />
<span id="TurnsRemaining" />
```

### 1.2 运行时注入层（英文残留的真正来源）

6 个 `<span id=...>` 的内容**不在 htm 里**，而是 exe 运行时注入：

```
PGForever.exe  0x4074A0  横幅渲染函数
  │
  ├─ 0x407509  mov ecx, 0x482BDC          ; "newturn.htm"  加载模板
  ├─ 0x40757E  mov ecx, [ebp+0x60]        ; 游戏状态
  ├─ 0x407581  mov eax, [ecx+0x4C]        ; 阵营标志
  ├─ 0x407584  mov ecx, 0x482A08          ;   "Axis"     ← 默认(flag==0)
  ├─ 0x40758D  mov ecx, 0x482A14          ;   "Allied"   ← flag!=0
  ├─ 0x4075A1  mov ecx, 0x482BF4          ; id="Side"          → SetElementInnerText16
  ├─ 0x40760F  mov ecx, 0x482C00          ; id="CurrentTurn"
  ├─ 0x40765B  mov ecx, 0x482C18          ; id="Time"
  ├─ 0x4076D5  mov ecx, 0x482C24          ; id="Date"
  ├─ 0x407757  mov ecx, 0x482C30          ; id="Weather"
  └─ 0x4077D8  mov ecx, 0x482C40          ; id="TurnsRemaining"
         │
         └─ 0x4016E0  宽字符 InnerText 设置（0x4014C0 的宽字符孪生版）

日期串生成  0x406C95  push 0x482B24   → sprintf("%s %d, 19%d")  via 0x403470
             0x406C8C  mov eax,[edx*4 + 0x482AF0]   ← 月份指针表
天气串生成  0x404ADA  push 0x482A24   → sprintf("%s(%s)")      via 0x403470
             0x404ACA/0x404AD1  从两张标志表取天气名 / 地面状态名
```

**结论**：改 `newturn.htm` 对这些残留**完全无效**——模板里只有 `回合` 两个字，其余全是 exe 注入的。

## 二、为什么汉化不了？

`L7` 批次（`work\exe\translations.json`，77 条）**只覆盖了单位类别、战斗结算、场景设置、提示、错误信息**，
**没有包含**阵营名、月份名、天气名。这批常量从未被提取进译表，所以一直是英文。

### 日期格式串

| VA | 原文 | 字符数 | 译文 |
|---|---|---|---|
| `0x482B24` | `%s %d, 19%d` | 11 | `%s%d日, 19%d` |

参数顺序（由 `0x406C8B` 起的压栈确认）：

原文 `%s %d, 19%d` → `9月 1, 1939`；译文 `%s%d日, 19%d` → `9月1日, 1939`。
**恰好 11 字符，等长替换。**

## 四、安全性核查

对全部 22 个目标串做了「字节模式重复检查」：

- 7 个天气名 + `Allied`：**严格唯一**（加 NUL 终止符后全 exe 仅 1 处）
- `Axis` 与 12 个月份名：有 3~8 处**子串命中**，但**全部是更长字符串的内部片段**
  （如 `Axis` 出现在 `AxisVictory` 之类里）。
  加上 **NUL 终止符**后再查，每个都**恰好只剩 1 处** → 精确边界替换，不会误伤。

月份指针表 `0x482AF0` 也一并校验：索引 1~12 逐一指向上述 12 个月份串，索引 0 为空槽，与代码 `[edx*4+0x482AF0]` 完全吻合。

## 八、经验教训

1. **HTMLayout 的 UI 有三种文字来源**，改文件无效时先辨别：
   ① htm 静态文本　② **exe 按元素 id 运行时注入**（本 case）　③ 图片烘焙标题
2. **「已汉化一半」是最有价值的线索**：同一画面里 `回合` 中文而 `Axis` 英文，
   说明两者来源不同——模板 vs 运行时注入。
3. **查重必须加 NUL 终止符**：短串（`Axis`/`May`/`Dry`）必然作为子串出现在长串中，
   只按裸字节查会误判为「多处命中」而放弃汉化。
4. **格式串的参数顺序要压栈确认**，不要靠猜：`%s %d, 19%d` 的三参数顺序由 `0x406C8B` 起的
   `push` 序列直接读出。
5. **VA→file 换算必须按节表**：`.rdata` 是 `−0x400E00`，但 `.data` 是 `−0x3F3C00`，
   混用会把数据读成中文乱码（本次踩过）。
