### 3. `.pgcam` 战役定义（★ 本轮最重要的结构发现）
经实证解剖，`.pgcam` 是**按位置解析**的定位格式，**只有 3 类文本会显示给玩家**：

| 可译项 | 位置 | 唯一内容数 |
|---|---|---|
| `entry_name` | `# Entry points` 段数据行 col 0 | 38 |
| `entry_desc` | `# Entry points` 段数据行 col 2 | 41 |
| `outcome` | `# Outcomes` 段每行 col 0 | 23 |
| **合计** | | **102 条**（覆盖 367 处） |

**以下经实证确认必须保留原文**（引擎内部键 / 文件名）：

- `# Entry points` col 1（`Label in campaign path`）—— 实证 **恒等于** `# Campaign path` 段 col 0
- `# Scenarios` 段 col 0（Label）—— 与 `# Campaign path` 段 col 0 同一键空间
- `# Campaign path` **整段** —— 12 列全部是 Label / `*.pgbrf` 文件名 / NextLabel / Prestige
- 其余所有段（`# Victory conditions`、`# Deploy hexes` 等）

佐证：exe 内命令协议串 `outcome %s for scenario %s`、`campaign path label %s` 表明这些名词是**匹配键**；
`# Campaign path` 段的 NextLabel 列里直接就是另一个 Label 名（如 `El Agheila`）。

> 初版提取脚本把 `scn_label`（1413 条）当可译项，属误判。修正后从"463 条"收敛到"102 条"，
> 避免了 1413 处内部键被破坏导致战役树断裂的严重事故。

另注：`AXIS VICTORY` / `ALLIED VICTORY` 在 exe 内以**写回模板**形式存在
（`# Victory conditions` 段的生成模板），说明它们既是显示值也是规范化值 —— 但 `.pgcam` 侧按位置读取，
翻译安全；`.pgscn` 侧若出现则不动。

回滚示例（以装备表为例）：
```python
import os, shutil
ROOT = r'D:\PGForever1.021'
BK   = r'D:\DSH\军事游戏汉化\pgforever\backup\eqpall-origin'
for dp, dn, fn in os.walk(BK):
    for f in fn:
        src = os.path.join(dp, f)
        shutil.copy2(src, os.path.join(ROOT, os.path.relpath(src, BK)))
```
