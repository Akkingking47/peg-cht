### 踩坑与铁律（`System.Drawing` 操作索引 PNG）
1. **`Graphics.FromImage()` 不支持索引位图** → `无法从带有索引像素格式的图像创建 Graphics 对象`
2. **`SetPixel()` 不支持索引位图** → `具有索引像素格式的图像不支持 SetPixel`
   ⇒ 正解：**画在 32bpp 临时图上**，再用 **`LockBits` + `Marshal::WriteByte`** 直接写调色板索引
3. **`new Bitmap(path)` 会锁住文件** → `Save()` 报 `GDI+ 中发生一般性错误` ⇒ **Save 前先 `Dispose()`**
4. 新造的索引位图**本来就是 0 填充**，而 index 0 正是背景色 ⇒ 无需 `Clear()` 铺底
5. **必须保持**：尺寸/步长一致、**调色板 index 0 的 RGB 与原图逐字节一致**、输出仍 8bpp 索引
   ⇒ 引擎按索引色键或像素色键都能继续透明（**实机截图确认无粉色块** ✅）
6. 文字型风格**关抗锯齿**，否则边缘像素落在色键外 → 地图上出现粉/品红毛边
7. 加了「**防重复转换**」护栏：成品调色板 256 项 vs 原图 8–17 项 ⇒ `SKIP: already converted`
   （**重跑前必须先从备份还原**，因为脚本读的是当前文件而非原图）

## ⚠️⚠️ 两个严重事故与教训（务必记住）

### 事故 1：`.xscn` 被截断成 2042 字节
`BinaryWriter.Write($keep)`，`$keep` 是 PowerShell 切片产生的 **`System.Object[]`** →
PowerShell 绑定到错误重载，**静默只写了 1 个字节**，40,455 字节前缀全丢。
- **教训：往 `BinaryWriter` 写数组必须显式 `[byte[]]` 强转**；写错长度**不会报错**
- 补救：从 `backup\ORIGINAL-EFILE_OLGWW2\SCENARIO\`（官方整包，187 个 .xscn 齐全）还原，MD5 一致
- 防复发：写入前断言 `outBytes.Length >= 前缀长度`；写入后立即回读校验

### 事故 2：备份被写进乱码目录 `D:\DSH\鍐涗簨娓告垙姹夊寲`
`.ps1` 被存为 **UTF-8 无 BOM**，PowerShell 5.1 按 **GBK** 解析 → 参数默认值里的中文路径变乱码 →
备份写到乱码路径，而 `Test-Path` 检查的也是同一个乱码路径，**所以断言没拦住**，真正的备份目录是空的。
- **教训：含中文的 `.ps1` 必须存 UTF-8 with BOM**（或脚本纯 ASCII、中文只走命令行参数）
- 事后已把原图取回正确位置并删除乱码树
