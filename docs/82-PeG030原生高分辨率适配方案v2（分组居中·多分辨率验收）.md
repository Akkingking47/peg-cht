## 0. 结论先行

**一句话**：v2 = v1 的缩放内核（不变）+ **一层"按窗口组各自居中"的平移修正（本轮新增）**。
组内仍是同一个刚性缩放，因此 v1 已经证成的「相对位置保持 / 等比」性质完全不损失，只补上了「每个子界面各自居中」。

本轮实测发现一个决定性问题（见 §7 证据）：

> 现有 P1 用的是**整张表的单一全局仿射**（屏幕中心 = 设计中心 400,300 的像）。
> 但按控件表的结构实测，**表 0x4A96E8 里没有一个面板记录是居中的**
> —— 各面板中心相对设计中心偏移最大 (−229,−156)、(+175,+9)；只有把「同一界面的全部控件」当作一组看时，
> 组外接框才接近居中。于是全局仿射会把这个偏移**按 s 放大保留下来**：
> 1920×1080 下 window 9 这一组仍偏离屏幕中心 **(−200,−119) px**，window 6 偏离 **(−149,−125) px**。
> ⇒ 这**正是用户抱怨的"子界面还在旧坐标"的残量**，单靠全局仿射治不掉。

而修正成本极低：**每组只是一笔常数平移** `Δx = (400 − cx)·s`、`Δy = (300 − cy)·s`，不需要重算任何缩放。

## 1. 判定标准（可测、可复现，v2 在 docs\80 §1 基础上新增 A8/A9）

对**每个目标分辨率** × **每一类界面**逐条判定。界面清单（暂定 9 类，实机补齐）：
主界面(战略地图+HUD) / 顶部菜单 / 单位采购 / 部队编成 / 外交-编制 / 场景选择 / 开局与回合简报 / 选项与存档 / 消息框与确认框。

| 编号 | 判定项 | 量化标准 | 探针 |
|---|---|---|---|
| **A1** | 元素**等比缩放** | 任一矩形 `w' = w·s ± 1`、`h' = h·s ± 1`（两端独立取整，误差上界 1 px 属正常） | V1 内存读表 |
| **A2** | **相对位置**保持 | 同一界面内任意两控件中心距 `|dist' − dist·s| ≤ 2 px`；控件相对本组外接框的归一化坐标偏差 ≤0.5% | V1 |
| **A3** | **命中一致** | 每个可见控件中心 + 四角点选命中一致率 100%；空白处点选不误触发 | V3 |
| **A4** | 无黑块 / 无拖影 | 非法黑像素 ≤0.5%；静止画面连续两帧**逐像素相等** | V4 |
| **A5** | **多分辨率**一致 | 六档（1024×768 / 1280×720 / 1366×768 / 1600×900 / 1920×1080 / 2560×1440）分别通过 A1–A4、A8、A9 | V6 |
| **A6** | 可回退 | 关补丁后与原生 800×600 逐像素一致；**母本 md5 恒为 `c462e897b3aa1c384870c857ce9e01df`** | V7 |
| **A7** | 稳定性 | 连续 ≥10 min 无崩溃；每个子界面进出 ≥20 次；**正常退出不卡死** | V5 |
| **A8** | 🆕 **界面居中** | 每个界面组的**外接框中心**与屏幕中心偏差 ≤2 px（纵向若有下锚定状态栏，允许该栏单独贴底，不计入组中心） | V2 截图像素 |
| **A9** | 🆕 **无组间碰撞** | 同一屏共存的界面组，彼此矩形不重叠（原设计里就不重叠的那些）；成正比修正后仍不重叠 | V2 |

> A1/A2 是「等比 + 相对位置」的形式化；A8 是「居中」的形式化；A9 是分组居中的**安全护栏**
> （万一分组切错，把两个同屏可见的组各自推向屏幕中心会撞在一起 —— A9 就是为此设的哨兵）。

## 2. UI 缩放与居中的计算方式（唯一权威定义）

### 2.1 空间与策略

- **设计空间** D = `800×600`，中心 `Cd=(400,300)`（这是引擎编译期写死的布局参考系，实测证据见 §7）。
- **目标空间** T = `W×H`，中心 `Ct=(W/2, H/2)`。
- 策略：

| 策略 | s | 用途 |
|---|---|---|
| **S1 等比** | `min(W/800, H/600)` | 保守底；任何比例都安全 |
| **S2 高度优先（默认）** | `H/600` | UI 盒 `800s × H` 居中，**地图视口横向吃满 W**；要求 `W/H ≥ 4/3`，否则退回 S1 |
| **S3 分轴拉伸** | `sx=W/800, sy=H/600` | **仅**整幅背景/过场；禁止用于控件与文字 |

### 2.2 单轴映射模式（五档，`layout_model.py` 已实现且自检通过）

```
center : T/2 + (v − D/2)·s      默认；屏幕中心是不动点
right  : T − (D − v)·s          右/下锚定（贴边元素的边距按 s 缩放）
scale  : v·s                    锚定设计原点（地图像素、图内坐标、滚动偏移）
stretch: v·T/D                  横跨/纵跨整屏（底栏、分隔线、全屏背景）
fixed  : v                      像素级真值（字体度量、遮罩位宽、结构大小）
```

**取整与一致性规则（硬约束）**
1. round-half-up：`floor(v+0.5)`；
2. 矩形**两端各自变换**，不用「起点 + 缩放后长度」，避免累积误差；
3. **相邻共边必须同一 mode**（同一设计坐标 ⇒ 同一目标像素），杜绝 1 px 缝被误判为黑线；
4. **命中测试与重绘登记必须复用同一 Layout 实例、同一份取整结果**（否则"看得见点不到"）。

### 2.3 🆕 分组居中的修正项（v2 新增）

对窗口组 `G`（见 §7.2 的分组依据），令其设计空间外接框为 `(gx0,gy0,gx1,gy1)`，中心 `cg=((gx0+gx1)/2, (gy0+gy1)/2)`：

```
X_G(v) = W/2 + (v − cg.x)·s   =  X(v) + Δx     其中 Δx = (400 − cg.x)·s
Y_G(v) = H/2 + (v − cg.y)·s   =  Y(v) + Δy     其中 Δy = (300 − cg.y)·s
```

性质（**这是它能安全落地的原因**）：
- `Δ` 是**每组的常数**，组内不引入任何形变 ⇒ A1/A2 自动继承；
- 组内所有控件**整体平移同一向量** ⇒ 相对位置、间距、层叠关系一字不变；
- 组外接框中心**精确落在屏幕中心** ⇒ A8 满足（±1 px 取整）。

**护栏**：
- 若某组触到屏幕边缘外（`∉[0,W)×[0,H)`），将该组的 `s` 退到 `s_G = min(s, 0.98·W/gw, 0.98·H/gh)`，**只降这一组**；
- degenerate 记录（1×1 哑元：idx 0、263–268）**不参与**外接框计算，但仍按其所属组平移；
- 原始即倒置的矩形（idx 98/99，**本就有负宽/负高**）**保持倒置**，不得"顺手扶正" —— 那会改变引擎行为。

## 7. 本轮新证据（全部实跑输出，脚本可复跑）

### 7.1 记录结构与合法性清点（`work\peg\relayout\_probe_groups.py` / `_check_p1.py`）

- 表 `0x4A96E8`，记录 15 B，**272 条**；前 8 B = 4 个 int16 矩形 `x1,y1,x2,y2`。
- 值域内（−64..864 / −64..664）**271 条**；**idx 271 是垃圾**（`y1=17664, x2=30065`）⇒ 丢弃。
- 其中 **7 条 1×1 哑元**（idx 0、263–268）；有效矩形记录 **264 条 = 1056 字段**。
- **idx 98/99 原始即倒置**（`(37,510,110,499)` 高 −11、`(218,510,110,568)` 宽 −108）——**不是本方案造成的**，保持原样。
- 六档分辨率下：全部新坐标落在屏内（屏外 **0**）；倒置 **2**（即上面这两条，与分辨率无关）。
- 1920×1080 不变量实测：组中心偏差最大 **0.4 px**，边长缩放误差最大 **0.8 px**（两端独立取整的理论上界 1.0）。

### 7.2 分组字段（决定 P1.5 能否自动施工）

- 记录尾部 7 字节：`byte@+0x0A` 只有 **7 个取值**（0/6/7/9/10/12/15），且**记录按该值成段连续存放**
  （`_probe_runs.py`：`idx[8] b10=0`、`[9..10] b10=7`、`[11..96] b10=0`、`[97..100] b10=12`、`[105..151] b10=12`、`[156..171] b10=6`、`[203..244] b10=10` …）
  ⇒ 形态高度像"每个界面一段"。
- `byte@+0x0B` = **记录种类**，`=4` 的 **11 条**恰好是全部"面板外框"（与纯几何包含分析 `_probe_containers.py` 的 12 个候选容器高度重合）
  ⇒ 交叉印证：这两个字节确是有语义的字段，不是噪声。
- **关键**：这 11 条面板外框**没有一条居中**，偏心最大 `(−229,−156)`、`(+175,+9)`；
  而把每个 win 组的全部控件合起来看，组外接框基本居中（偏差 ≤112 px）。
  ⇒ **居中的正确粒度是"组"，不是"面板"**：逐面板居中会把同屏共存的多块面板叠成一坨（这也是 A9 要卡的）。
