# docs\67 PeG 宽屏方案：分层策略与实施路线（停止盲测版）

> 目的：把当前「发现一个症状 → 静态找一个常量 → 打补丁 → 实机看看」的循环，换成**分层治理 + 运行时几何拦截 + 证据驱动验证**。
> 结论先说：**分辨率常量那一层已经成功（16:9 已实机跑通），不该再往里加常量；剩下所有问题都应该在「几何策略层」和「输入一致性层」用运行时拦截统一解决。**

---

## 1. 现状盘点：所有与画面显示有关的代码与运行路径

### 1.1 显示层（DirectDraw API 调用）
- 两个 IDirectDraw：`[0x6768FC]`（`DirectDrawCreate` @`0x4419BC`）、`[0x6761E0]`（`QueryInterface`，之后所有 SetDisplayMode / CreateSurface 都走它）；`[0x4AF26C]` 实际是 **IDirectDrawSurface**。
- 顺序：`DirectDrawCreate` → `SetCooperativeLevel(0x11)` → `SetDisplayMode(800,600,16)` @`0x441A91` → **9 次 CreateSurface**（`0x441B03`–`0x441FD3`）→ 4 次 `SetColorKey` → `Blt(COLORFILL)` @`0x44212E`；**全 exe 无 SetClipper / SetPalette**。
- 唯一上屏 Flip：`0x41FE4C`（`PresentFrame` @`0x41FE12`）；`RestoreAllSurfaces` @`0x456070` 依次 Restore 10 个面，**任一失败立即中止**。
- 色键：唯一写点 `0x441BB7`(0x7C1F, RGB555) / `0x441BCC`(0xF81F, RGB565) → `word[0x6769B0]`；消费点 `0x442005`/`0x442013`/`0x442024`/`0x442034`（画布 `SetColorKey`, flags=8）。

### 1.2 面表（Surface）
| 全局 | 尺寸 | 用途 |
|---|---|---|
| `[0x61F900]` | 主面 | Flip 目标（`PresentFrame`） |
| `[0x676904]` | 后备/后台缓冲 | **所有 UI、文字、叠加都画在它上面** |
| `[0x655574]` / `[0x622A10]` | **1920×1920** | 常驻地图面（母本本来就这么大，是宽屏可行的物理前提） |
| `[0x675538]` | 母本 800×600 → 产物 **1920×1080** | 画布（帧合成终点，`0x441FAF`/`0x441FB6`） |
| `[0x62CE10]` | 300×60 | 悬停提示面板（内容填色键色后再 KEYSRC 位块） |
| `[0x61F3E0]` | 300×60 | 提示框「背景保存面」 |
| `[0x686528]` / `[0x6633FC]` | 90×70 | 鼠标跟随后备 / 保存面 |
| `[0x681D0C]` | 420×200 | 简报/消息面板 |

### 1.3 每帧合成管线
`0x41EB33` → `0x41FF8A`（把视口窗口 BltFast 到后备缓冲 (0,22)）→ 叠加层 / GDI 文字 → 与画布互拷 `0x425BCB` → `Flip`。
两个**几何总闸**：
- **通用位块助手 `0x41EB70`**：`(x, y, srcSurface, RECT* rc, color, flags) → Blt(后备, dst, src, rc, flags, fx)`；内部按硬编码屏宽裁剪（`0x41EBF0`/`0x41EBF8`、`0x41EC73`/`0x41EC7B` 判定已补 0x780/0x438；减法 `0x41EC11`/`0x41EC2C`/`0x41EC94` 已补 −1920/−1080）。
- **视口设置器 `0x424C73`**：`(left, top, right, bottom, flag)`，末尾 `mov byte [0x4AF288],1` + `call 0x456AB5` 请求重绘。调用者：`0x41C59D`（已补 571→1052、799→1919）、`0x45A0AF`/`0x45A945`（**战略地图**，已补）、另有 `0x45A0F7`/`0x45A950` 姊妹站点。

### 1.4 UI 布局（两套数据表 + 一个文本函数）
- **控件记录表 `0x4A22F8`**：16 条 × 36 字节，`+0 flags / +2 x / +4 y / +6 right / +8 bottom / +0x10 回调`；绘制处理器 `0x44ACDA`。→ D 组已搬 29 处（工具栏列到 1882/1907，实机可见 ✓）。
- **面板布局表 `0x4A96E8`**：272 条 × 15 字节（`x1,y1,x2,y2` word）；**269 条运行期只读**（唯一写点 `0x45E4AE`，只能写最后 3 条）。→ I 组搬了 37 条右缘记录（**实机无变化** ⇒ 不是「更多选项」的控制点）。
- **文本唯一路径**：`0x4700C6` → `0x47010B`（`GetDC(后备)` → `SetTextColor` → `SetBkMode(1)` → `SelectObject` → `DrawTextExA(flags 0x410)` → `ReleaseDC`），排版矩形写死 `(0,0,800,600)`（`0x4700DD`/`0x4700E4`，已补 → **实机无变化**）。
- 另有 `0x43BBC4` 提示框 RECT `(100,10,700,590)`、`0x43BC97` 居中消息框（`0x43BCAE` right=400、`0x43BCF8` 居中基准 400，已补 → **实机无变化**）。

### 1.5 输入与命中（**当前最严重的问题所在**）
- 鼠标位置缓存：`[0x4AF2E8]`(X) / `[0x4AF2EC]`(Y)（`0x44C66E` 每帧更新用它算提示框跟随位置，**已确证**）。
- 视口全局：`[0x4AF2F8]`(x) / `[0x4AF2FC]`(y)；滚动量、格子尺寸 25 与之配套。
- 贴边滚动判定：`0x4567C4`/`0x4567DE`/`0x4568E2`/`0x4568FC`/`0x456984`/`0x456A3E`（G 组已补 799/599 → 实机**无变化**）。
- **用户实测（m02926）**：`x>800`（或 `y>600`）的地图区域，鼠标点中的单位/格子与看到的不一致，甚至点不中 ⇒ **屏幕→地图格子换算链里仍有 800×600 基准**。这是「能不能玩」的问题，优先级最高。

### 1.6 特殊画面
| 画面 | 入口 | 现状 |
|---|---|---|
| 战略地图 | 视口 `0x45A0AF`/`0x45A945`（已补） | 打开正常，**鼠标一动接续绘制就碎**（未解决） |
| 子界面（单位/装备/购买） | `0x43BC97` 区、文本矩形 | **仍按 800×600 居中**（未解决） |
| 简报/对话框 | `0x43BBC4` 区 | 位置未适配（未解决） |
| 悬停说明框 | `0x44C7BE`（门控 `[0x686540]`，位置 `[0x6769A0]`/`[0x6769A4]`，面板 `[0x62CE10]`） | 文字正常，**面板位置未解决** |

### 1.7 已经实机验证成功的部分（不要再动）
✅ 16:9 铺满（地图/画布 1920×1080）｜✅ 工具栏按钮列到 x=1882/1907｜✅ 强制重绘（消灭增量重绘黑空洞）｜✅ 裁剪算术（−1920/−1080，修复「画面破碎」）｜✅ 显式文字矩形、右键滚动阈值等 G/H 站点均已写入并回读一致。
⚠️ 但 G/H/I/K 四组**对四个目标症状都无可见效果**（K 组还造成左栏文字右移 + 大黑洞，**已回退为默认不打**）。⇒ 教训：**这三类症状的控制点不在「常量」上，而在「函数行为」上。**

## 2. 社区经验对照：哪些适用、哪些不适用

| 社区方案 | 做法 | 对 PeG 是否适用 | 结论 |
|---|---|---|---|
| **DDrawCompat**（v0.7.1，我方已收档） | 完整模拟 DirectDraw（色键、裁剪、GDI-on-16bpp、表面丢失恢复） | ✅ 适用：我们的痛点正是「引擎用法在 API 层、旧 wrapper 语义不全」 | **用它当默认显示层**，把色键/透明/拖影一类问题整类消灭，且**零 exe 改动** |
| **cnc-ddraw** | 同上，另一实现（7.1.0.0 已收档） | ✅ 适用（备选） | 备份方案 |
| **MultiCAD（突袭）** | 替换游戏自带的图形模块 `cad640.dll`/`cad1024.dll` | ❌ 不适用：PeG 引擎直接调 `ddraw.dll`，分辨率常量散在 `PeG030.exe` 内 259+ 处，**没有可替换的靶子** | 只借它的**产品形态**：generic 产物 + 配置选分辨率（＝我们的启动器） |
| **OpenGen** | 重实现整个引擎 | ❌ 不适用（要保留原引擎与汉化） | 但它证明「宽屏 + 无 UI 缩放」是社区接受的权衡 |
| VCMI / HoMM3 HD / nGlide | 重实现或封装 | ❌ | — |
| **宽屏修复 DLL / ASI 插件**（大量老游戏） | **hook 引擎自己的投影/视口/布局函数**，一处策略覆盖全部同类元素 | ✅✅ **最贴合我们** | **本方案 L3/L4 的核心思路** |
| 十六进制改常量 + 启动器 | 直接改常量 | ⚠️ 只能解决「常量类」问题；每遇到新基准就得再找一轮 | 保留为 L2，不再作为主策略 |
| Wine / DOSBox / DGVOODOO2 | 换平台/换 API 时代 | ❌ | — |

**关键教训（来自我们自己的 5 轮）**：老游戏扩展分辨率，社区通用做法是「**在运行时拦截引擎的几何/布局函数**」，而不是「把每一个坐标常量揪出来改」。我们已经在打常量这条路上遇到天花板。

## 3. 分层方案

### L1 显示层（换 ddraw.dll，零 exe 改动）
- 默认使用 **DDrawCompat v0.7.1**（`26275ed572a4df16141b26e952b50106`，i386 ✓，已收档 `archive\ddraw\`）。
- 启动器加 `--ddraw <path>`：启动前换入、退出后**自动还原**，并保留 `ddraw-svens.dll.bak`；另给一个 `还原显示层.cmd`。
- 验收：品红/透明/拖影一类症状消失；不引入新问题（帧率、窗口、文字）。
- 为什么先做：它是**唯一能整类消灭「色键/透明」症状且不碰 exe** 的手段，而且社区已验证过千万台机器。

### L2 分辨率常量（保持现状，冻结）
- 继续用启动器已实机验证的站点（默认 **236 条**：96 尺寸 + 10 代码侧 + 4 A + 1 B + 2 D + 3 F + 14 G + 4 H + 74 I）。
- **新症状一律不再往这里加常量**，除非 trace 证据指明某常量确实是控制点。

### L3 几何策略层（**核心新增**）：运行时拦截几何函数
不再找常量，改为在**函数入口**拦截并改写实参，把「元素类别 → 新几何」的策略集中到一处：

- 拦截点（都是我们已确证语义的函数）：
  1. `0x41EB70` 通用位块助手 —— 统一放宽裁剪、按类别改写目标矩形；
  2. `0x424C73` 视口设置器 —— 统一把视口扩展到新画面（含战略地图等所有调用者）；
  3. `0x4704D2` 布局表读取（`0x4A96E8`）—— 按记录类别重定位（右缘 / 左锚 / 全宽 / 居中）；
  4. `0x44DAxx`/`0x44ACDA` 控件记录绘制（`0x4A22F8`）—— 右栏统一位移；
  5. `0x4700C6` 文本排版矩形 —— 统一 1920×1080（并让居中基准 960/540）；
  6. `0x41FF8A` 视口窗口上屏 —— 校验源/目标矩形。
- 元素类别策略（唯一的「真相表」，一处维护）：
  | 类别 | 判定依据 | 策略 |
  |---|---|---|
  | 右栏元素 | 记录 x ≥ 700（母本） | `x += 1120`、`right += 1120` |
  | 左锚元素 | x 小且贴左 | **不动** |
  | 全宽元素 | 宽度 ≥ 500 且横跨 | 右端拉到新宽度（**不整体平移**） |
  | 居中元素 | 以 400/300 为中心的 | 改用 960/540 |
  | 面板容器 | 含子按钮的容器 | 容器与子项**同组**一起按父锚重排 |
- 两种实现：
  - **α（先做）调试器式拦截**：`CreateProcessW(DEBUG_ONLY_THIS_PROCESS)` + 在目标 VA 写 `0xCC` + `Wow64GetThreadContext` 读写寄存器/栈；策略用 Python 写。**不需要汇编、不需要注入、exe 零改动**，而且天然带日志。
  - **β（α 性能不够时）代码洞 detour**：`VirtualAllocEx` 分配桩 + 入口 5 字节 `jmp` + 桩内应用策略后回跳；用 Python 现场汇编少量机器码。
- 验收：每类元素一个独立开关（`--cls right|left|wide|center|panel`），一类一类开、一类一类留证。

### L4 输入一致性（修「点不中」，最高优先级）
- trace 先取证三件事：①鼠标坐标写入者（窗口消息 / `GetCursorPos` / DirectInput）及其钳位；②屏幕→地图格子的换算函数（视口 `[0x4AF2F8]`/`[0x4AF2FC]` + 滚动量 + 25 像素格子）；③六角格选中的目标判定。
- 修复原则：让**输入换算与渲染使用同一套视口全局**（而不是把 800/600 换成 1920/1080 了事——那样只会把偏移搬到别处）。
- 验收：在 x>800、y>600 区域用**固定坐标网格逐点点选**，看到的单位＝点中的单位。

### L5 特殊画面（用 L3 的策略覆盖，不单独找常量）
战略地图（含拖动接续绘制）、子界面居中、简报/对话框、悬停面板位置——全部归入 L3 的类别策略表；若某类无法用统一策略覆盖，才退化为**该类专用常量补丁**，并在文档里写明理由。

### L6 证据驱动验证协议（消灭「盲测」）
1. 每次运行**自动留证**：启动器写 `work\peg\out\launcher-log.txt`（站点数、断点命中、拦截到的实参摘要、鼠标换算结果）；
2. **一次只改一个变量**（一组开关），改前说明预期；
3. 用户动作固定为「双击 → 做指定动作 → 回传日志/截图」；
4. 判定表：①一屏更多地图 ②点得中 ③战略地图/子界面/简报正常 ④无品红/黑洞/拖影。
   **凡是没有日志或截图证据的改动，不算完成。**

## 4. 实施路线

| 阶段 | 内容 | 需要用户做什么 | 交付物 |
|---|---|---|---|
| **P0** | 写 L3-α 拦截器骨架 + trace（**先只记录、不改写**）；用 32 位测试进程自测调试循环 | 无 | `peg_trace.py` + 自测报告 |
| **P1** | 开 L1（DDrawCompat）与 trace；采集真实矩形/记录号/鼠标换算 | 跑一次：进游戏→悬停按钮→开战略地图并拖鼠标→点 x>800 的格子 | 证据包（日志） |
| **P2** | 按证据实施 L3 类别策略（每类一次） | 每类跑一次 | 分类开关 + 截图 |
| **P3** | L4 输入一致性修复 | 跑一次，按网格点选核对 | 点选对齐结果 |
| **P4** | L5 特殊画面收尾 + 分发（快捷方式/还原脚本/md5/文档） | 终验 | 发布包 |

**决策点**
- D1：L1 是否整类解决色键/透明问题？→ 决定是否还需要 exe 侧动色键。
- D2：α 的性能是否可接受（<5% 帧损失）？→ 否则转 β。
- D3：某类元素无法统一策略时，退化为单类常量补丁（记录理由，不再全局扫常量）。

## 5. 风险与回滚
- 启动器**只改内存**，母本 `PeG030.exe`（`c462e897b3aa1c384870c857ce9e01df`）永不改动；每次启动前校验 md5。
- 每个元素类别、每组补丁都有独立开关；DDrawCompat 可一键还原为 Svens。
- 最坏情况的最小可用版：L2 的 236 条 = 一屏更多地图 + 可玩（前提是 L4 把点选修对）。
- 所有实验必须能从日志复盘（否则不予采纳）。

## 6. 运行时取证器 `work\peg\peg_trace.py`（P0 落地，取代盲测）

### 6.1 为什么需要它
236 条常量补丁连跑两轮实机，用户反馈**没有任何可感知变化**（`m02865`、`m02892`：「还是老样子」）；
说明「哪个常量对应哪个症状」靠静态推断已经猜不动了。按 §3 的 L6 证据协议，改为
**运行时拦截**：在已定位的几何函数入口下断，记录它每次拿到的**参数**与**当时的全局状态**，
用真实数据反推「x>800 的画面为什么错、点选为什么偏」。

### 6.2 机制（与启动器同源，但进程由本脚本创建）
1. `CreateProcessW(..., DEBUG_ONLY_THIS_PROCESS)` 创建游戏进程并接管为调试器；
2. `CREATE_PROCESS_DEBUG_EVENT` 时读 32 位 PEB 拿真实模块基址（事件字段不可信时回退 `wow64_peb_image_base`）；
3. 校验母本 md5 `c462e897b3aa1c384870c857ce9e01df`，按「先全量校验 → 再统一写入 → 回读一致」
   写好 236 条尺寸补丁（与 `peg_launcher.py` 共用 `build_plan`）；
4. 在探针函数入口写 `0xCC`（INT3），并在每次命中时快照关键全局；
5. 命中即记录「函数 / 调用方返回地址 `[esp]` / 栈上参数 / 当时的鼠标·滚动·视口值」；
   每个断点最多记 24 次（防热点拖慢），到顶自动撤销该断点；
6. 游戏退出后脚本自行收尾；日志 `work\peg\out\trace-log.txt`（UTF-8，按事件去重汇总）。

### 6.3 三个已实测确认的坑（避免重犯）
- **64 位调试器看 WOW64(32 位) 被调试进程时异常码不同**：INT3 命中是 `0x4000001F`
  （`STATUS_WX86_BREAKPOINT`）而不是 `0x80000003`；单步是 `0x4000001E`。
  不认这个码 ⇒ 看起来「断点没命中」，而我们继续执行时 `0xCC` 仍留在原地 ⇒ 死循环 + `0xC0000005`。
- **`DEBUG_EVENT` 在 64 位调试器下偏移与 32 位文档不同**：事件头 12 字节 + 4 字节对齐，
  联合体从 +0x10 起（`EXCEPTION`：`ExceptionCode`@+0x10、`ExceptionAddress`@+0x20）。
- **Dr（硬件断点）在本机 WOW64 下不可用**：`Wow64SetThreadContext` 与原生 `SetThreadContext`
  都返回成功、Dr 不触发，且会让被调试线程崩在 `0xC0000005`（证据 `work\peg\_dr_test.py`）。
  故默认不用 Dr，改为「INT3 + 周期性状态快照」。

### 6.4 探针清单（`POINTS`）与状态快照
| 探针 VA | 名字 | 记录内容 |
|---|---|---|
| `0x41EB70` | 位块助手 | x, y, src面, RECT*, color, flags（所有 UI 位块的漏斗） |
| `0x424C73` | 视口设置器 | left, top, right, bottom, flag |
| `0x43CDCE` | 屏幕→地图坐标（战斗图） | screenX, screenY；返回值 al=是否在图内 |
