## 2. 发现 B — 目录解析矩阵（本轮定论，推翻旧结论）

### 2.1 方法

`%sSCENARIO\%s*` 这类路径模板在 `.rdata` 里是普通立即数。用
`python _dirtrace.py <模板VA> ...`（`work\efile-poc\_dirtrace.py`）：
**① 找出该模板的所有 `push imm32` 站点 → ② 从站点向前回溯最近的「目录全局」赋值**。
三个全局（运行期实测内容）：

| 全局 | 名称 | 运行期值 |
|---|---|---|
| `0x11951A8` | GameRoot | `D:\OpenPG2\` |
| `0x11951AC` | EfileRoot | `D:\OpenPG2\EFILE_OLGWW2\` |
| `0x11951B0` | LangDir | `D:\OpenPG2\EFILE_OLGWW2\TEXT-ZH\` |

### 2.2 结果

| 模板 | 站点 | 目录全局 | 结论 |
|---|---|---|---|
| `%sSCENARIO\%s.xscn` | `0x725BC3` | `mov ecx,[0x11951AC]` = **EfileRoot** | **只认 EfileRoot** |
| `%sSCENARIO\%s.xscn` | `0x6DAC6A` | `mov ecx,[0x11951AC]` = **EfileRoot** | 同上（全库仅此两处） |
| `%sSCENARIO\%s.ply` | `0x7321B1` | `mov ecx,[0x11951B0]` = **LangDir** | **LangDir 优先** |
| `%sSCENARIO\%s.ply` | `0x75F82B` | `mov edx,[ecx+0x400]`（数据目录对象字段） | 语言目录 |
| `%sSCENARIO\%s`（通用） | `0x7E8C7A` | `mov ecx,[0x11951B0]` = **LangDir** | 首选 |
| `%sSCENARIO\%s`（回退） | `0x7E8CF1` | `mov ecx,[0x11951AC]` = **EfileRoot** | 打不开则回退 |
| `%sSCENARIO\%s.txt` | `0x757011` | `mov edx,[0x11951B0]` = **LangDir** | LangDir 优先 |
| `%sSCENARIO\*.xscn` | — | **0 处引用（死串）** | 不存在"按 LangDir 枚举场景" |

### 2.3 判据总结（本 efile 系）

> **数据类（`.xscn`）只认 `<efile>\SCENARIO\`；文本类（`.txt` / `.ply`）LangDir(`TEXT-ZH\SCENARIO\`) 优先、可回退 efile 根。**

⇒ **旧结论「引擎根本不查 `TEXT-ZH\SCENARIO\`」是错的**，但它对本轮的 `.xscn` 部分**恰好成立**。
⇒ 上一轮报告里的「发现 2（镜像遮蔽，241 个场景可能白干）」**证伪**：
`TEXT-ZH\SCENARIO\` 里那 241 个未汉化 `.xscn` 是**引擎永不读取的死文件**。

## 3. 发现 C — `.ply` 场景简报层全库漏译

`<efile>\SCENARIO\*.ply` = **场景开场简报**（可含 1–2 个语言块，`----` 分隔）。
截图证据（上一轮）：Canal Albert 弹窗标题中文、**正文整段西班牙语**且 `alemán`→`alem□`、`situación`→`situac□`
（`0xE1`+`n` 被 GBK 当作一个双字节字符 ⇒ **方块 + 吃掉后一字符**）。

| 项 | 值 |
|---|---|
| 全库 `.ply` | **156** |
| 501 B 全 `\x00` 空占位 | **40** |
| **实需翻译** | **116** 个，合计 **38,403 B** |
| 分布 | OPENPG 43、AO 25、BASEKORP 18、LUPO 7、KAISER 6、OLGWW2 5、OPENAK 5、OLGCW 5、AG 1、Clu 1 |
| 其中含高位字节（今天就在乱码） | **8** 个：`canalalbert_i`(hi=12)、`getteriver`(12)、`tiger05/06/07_i`、`tornio_landing`、`chaco1`、`uspanwar4_i` |

**部署位置（本轮定论）**：`.ply` 走 **LangDir 优先** ⇒ 译文必须落到
`<EFILE>\TEXT-ZH\SCENARIO\*.ply`；只改 `SCENARIO\` 会被 LangDir 里那份旧文件遮蔽。
**编码**：引擎按 `CP_ACP=936` 解码 ⇒ 必须写 **GBK**。工作量很小（38 KB）。

### 4.3 为什么必须走 exe 补丁

| 检查 | 结果 |
|---|---|
| 在 `strings-zh.txt` 里？ | **否** |
| 在官方 `strings-es/de/hu/pl.txt` 里？ | **否**（仅 `VH ` 一词命中，是别处的 `VH/SH 数据` 开关项） |
| 结构是否对齐？ | `strings-zh.txt` **917 行**，与 `strings-de.txt` 完全对齐；766 行含汉字 ⇒ 表本身完好，这批串**不在表内** |

⇒ 只能改 exe。风险点：GBK 中文比 ASCII 长（如 `'  Ammo:%d/%d '` 14 B → 加「弹药」需 15 B，**超 1 字节**），
且**含格式符的串不能原地改短**（本项目已有 `File: %s [%d scenarios]` 的事故记录）⇒ 需逐条核算长度，必要时"写副本到空洞 + 改指针"。

### 为什么漏了（与工具行为一致）

映射表 `xscn-all-map.tsv` 共 16,245 行，其中 **2,679 行（16.5%）是 `src == dst` 恒等映射**
（1840 缩写/型号 ＋ 9 非 ASCII ＋ **830 纯 ASCII**）。而 `xscn-patch.ps1` 的规则是
**「译文不含 CJK ⇒ 保留原字节」** ⇒ 这 2,679 条被"保留原字节"计入 2,762，**在统计里被算成"已处理"**。
"187/187 完成、英文残留 0"的结论因此**虚高**——真实口径应为 **84.3% 条目含汉字**。

> ⚠️ 同型问题在前一个 POC 已出现过一次：NASHORNPBEM 的标题 `UtopianParadox → UtopianParadox`。

## 7. 口径建议（待确认）

1. **括号别名**：别名有**独立通行中文名**且与主名不同 ⇒ 译（如 `Escaut (Schelde)`→`埃斯科河 (斯海尔德河)`）；
   否则**保留原语言**（`Gent (Gand)`）；**严禁译成与主名相同的重复串**。
   （同表内 `Kanaal Gent-Terneuzen (Canal Gand-Terneuzen)` 已按此处理，做法正确。）
2. **方括号军级标记**（`[XIII]`、`[DAF]`、`[XX]`）视为**符号**，按 `AT/FlaK/BB/ZOC` 同类处理 —— 保留。
3. **`.ply` 简报**与 `.txt` 简报同权，属"玩家可见正文"，必须译；部署到 `TEXT-ZH\SCENARIO\`。
