## 三、本轮新增静态事实（母本实读）

### 3.1 记录表 `0x4A22F8` 字段全解（`work\peg\peek_table.py`）
每条 **36 B（0x24）**，条数 = `word[0x4af460]`：

| 偏移 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `+0` | u16 | flags | idx0–12 = `0x1045`；idx13/14 = `0x1820`；idx15 = `0x0001` |
| `+2` | i16 | x | 目标 X |
| `+4` | i16 | y | 目标 Y |
| `+6` | i16 | right | 目标右 |
| `+8` | i16 | bottom | 目标下 |
| `+0xa` | i16 | **s1（在用）** | idx0–12：69…105；idx13 起 = `0xFFFF` |
| `+0xc` | i16 | **s2（在用）** | idx0–12：0…35；idx13 起 = `0xFFFF` |
| `+0xe` | i16 | **s3（在用）** | idx0–12：243…582（idx0=487、idx4=243）；idx13 起 = `0xFFFF` |
| `+0x10` | ptr | 回调 1 = `0x44ACDA` | 见 3.2 |
| `+0x14` | ptr | 回调 2 = `0x44889F` | idx15 为 `0x44889F` 同值 |
| `+0x18` | ptr | 回调 3 = `0x448A3A` | idx15 = `0x448E94` |
| `+0x1c` | ptr | 回调 4 = 0 | idx15 = `0x449B37` |
| `+0x20` | ptr | 回调 5 = `0x44C1E1` | idx15 = `0x44BFE1` |

⚠️ **`+0xa`/`+0xc` 不是空闲填充** ⇒ 原计划「借 padding 存位移」**作废**。

### 3.2 绘制处理器 `0x44ACDA(idx)` 完整语义（反汇编确证）
```
0x44acda  push ebp / mov ebp,esp / sub esp,0x20
0x44ace0  越界保护：idx < 0 或 idx >= word[0x4af460] → ret
0x44acfc  rec = [0x4cce2c] + idx*0x24
0x44ad11  rect.left   = rec.x            (存 [ebp-0x18])
0x44ad1b  rect.top    = rec.y − 1        (存 [ebp-0x14])
0x44ad28  rect.right  = rec.right + 1    (存 [ebp-0x10])
0x44ad35  rect.bottom = rec.bottom + 1   (存 [ebp-0xc])
0x44ad3f  rect.surface= [0x676904]       (存 [ebp-8])
0x44ad48  取 word[0x4c90e0]，(…>>1)&1
   ├─ 置位（0x44ad60）: 仅 idx==1 → 0x44ad75 画；仅 idx==4 → 0x44ad9c 画；其余 → ret
   │    画法：push (0x16 − rect.top) ; push (0x2ef − rect.left) ; push 1 ; push 0x663410 ; push &rect ; call 0x4235E5
   └─ 未置位（0x44adc3）: idx==0xd → ret ; idx==0xe → push 9 ; call 0x47097A ; 其余 → ret
0x44ade4  mov esp,ebp / pop ebp / ret
```
⭐ **关键**：`[ebp-0x18]`（=rect.left）与 `[ebp-0x14]`（=rect.top）**同时**是「目标矩形左上」和「源图偏移的被减数」⇒ **位置与取样被同一对局部变量耦合**，这是「挪记录＝拉彩带」的结构性原因；也说明**这个处理器只负责 idx 1 / 4（以及 0xe 的一个弹窗）**，屏幕上那一列按钮**不是它画的**。

### 3.3 工具栏/面板动画绘制（`0x4488C5` 段）
```
0x4488c5  movsx eax, word[0x4af32c]            ; 动画索引
0x4488cc  movsx ecx, word[eax*2 + 0x498d38]    ; 该索引的目标状态
0x4488d4  movsx edx, word[0x4af2fc]
0x4488db  cmp ecx,edx / je 0x448992            ; 已完成 → 跳过
0x4488ea  [eax*2+0x498d34] = word[0x4af2f8]    ; 记录当前 X
0x448900  [edx*2+0x498d38] = word[0x4af2fc]
0x44890e  push 0 / push word[0x4af2fc] / push word[0x4af2f8] / call 0x41FF8A   ; 通知动画量变化
0x448928  (word[0x4c90e0]>>1)&1 → 未置位则跳过绘制
0x44893e  push 0x16 / push 0x2ef / push 1 …     ; 与 0x448847 段同型：字面图集坐标 (751,22) + 同一 ctrl 0x663410
```
⇒ **右侧面板/工具栏的搬移量来自 `0x4af2f8`（X）与 `0x4af2fc`（目标 X）这对运行期动画量**，绘制用**字面图集坐标**，不是记录表坐标。**这是 v9b 真正应该下手的对象**（面板滑动基准，而不是记录表）。

### 3.4 地图视口 clamp / 滚动函数（`0x44C6F0` 段，本仓 16:9 配方已按 w/h 改过其中 6 处）
```
0x44c703  cmp dword[0x663380], 0 / jge …        ; 滚动 X 归零保护
0x44c724  cmp dword[0x663388], 0x320 / jle …    ; ← 我们改成 1920
0x44c730  mov eax,0x320 / sub eax,[0x663380] / mov [0x4a2730],eax / mov [0x663388],0x320
0x44c76b  cmp dword[0x66338c], 0x258 / jle …    ; ← 我们改成 1080
0x44c777  mov edx,0x258 / sub edx,[0x663384] / mov [0x4a2734],edx / mov [0x66338c],0x258
0x44c792  push 0 / push 0x1000000 / push 0x663380 / push [0x676904] / push 0x4a2728 / push [0x686528]
```
⇒ 地图目标矩形 **`0x4a2728` = (−sx, −sy, 800−sx, 600−sy)**（每帧重算，**代码驱动、与记录表无关**），源偏移直接传 `&[0x663380]`。这解释了「挪记录搬不动地图」，也说明地图铺满靠的是把 0x320/0x258 改成 1920/1080 这 6 处。

## 四、v9b 设计：把「目标位置」与「源坐标」解耦

三条候选实施路径，按侵入度排序：

**路径 B1（最小改动，需确认适用面）**：若某组控件的位移 Δ 固定，则「记录 +Δ」+「该组取样常量 `0x2ef`→`0x2ef+Δ`、`0x16`→`0x16+Δ`」成对改即可复原取样（`0x2ef` 全 `.text` 仅 5 处：`0x43AA47`/`0x448849`/`0x448940` 的 `push`，`0x44AD7E`/`0x44ADA5` 的 `mov edx`）。
⚠️ 限制：同一常量服务所有记录，**只适用于「整组同 Δ」**（右侧 13 按钮 Δx=+1120 可以；动作条 Δx=+560 与底栏需要各自独立路径）。

**路径 B2（推荐，路线 C）**：把位移写在**一张与记录表同长、同索引的位移表**里（新建 `.data`），并改写绘制的矩形构造：
`rect.left = rec.x + Δx[i]`、`rect.right = rec.right + 1 + Δx[i]`、`rect.top/bottom` 同理；
**取样仍用原始 `rec.x`/`rec.y`**。实现手段＝代码洞穴 + `jmp` 进自写 stub（本机无 C 编译器，可用 Python 直接写机器码字节，沿用现有「站点断言 + 回读校验」纪律）。

**路径 B3（兜底，运行期）**：DLL/注入 hook 在每帧绘制前改写记录或矩形（社区主流做法，见 `docs\58` §十一；需用户愿意装工具链）。

**硬约束（v9b 必须同时满足）**
1. 命中测试 `0x43FF28` 必须套同一 Δ，否则「看得见、点不到」（v9a 的另一半症状）；
2. 底栏/顶栏的**文字**（回合/日期/状态）与**面板背景**各有独立绘制点，需要逐个纳入；
3. 子界面（装备简介、单位信息、对话框）各有一套记录表（如 `0x490470` 40 条），要按同一机制处理。

## 五、彩带（跟随鼠标的彩色拉伸带）机制假设与判别

**当前假设排序**（详见 `docs\61` §彩带三假设）：
1. **源面越界采样**：视口/目标矩形已放大到 1920×1080，但源面（地图面或图集）只有旧尺寸/只有地图数据那么大 ⇒ 越界部分读到未初始化内存（16bpp 下典型呈绿色横带）；
2. **光标 save-under 缓冲按 800×600 写死**：鼠标移出老区域后，恢复时把未初始化内容 blit 回画面；
3. **主面从未被完整初始化**：只有老区域被填过，新区域保持未初始化，一次鼠标触发重绘就显形。

**判别实验（请用户跑，二选一即可）**
- **E1**：跑 `PeG030-1920x1080.exe`，把地图**滚动到真实地形覆盖右侧区域**，再在右侧移动鼠标。
  - 彩带消失 ⇒ 假设 1（越界采样）为主 ⇒ 修「目标/源矩形夹取」；
  - 彩带仍出现（盖在真实地形上）⇒ 假设 2/3 为主 ⇒ 修「光标 save-under 缓冲 / 主面初始化」。
- **E2**：同一版本下**不动鼠标**，先截图；再慢慢把鼠标移到右侧并截图。两张对比可确认彩带是否严格跟随光标轨迹。
