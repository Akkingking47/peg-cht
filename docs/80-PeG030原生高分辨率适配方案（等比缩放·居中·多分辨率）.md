# PeG030（modgen 引擎）原生高分辨率适配方案 —— 等比缩放 · 相对位置 · 居中 · 多分辨率

> 目标：**让游戏原生支持 1920×1080 及更高分辨率**，不是把 800×600 画面整体拉伸。
> 约束：母本 `PeG030.exe`（734,720 B，md5 `c462e897b3aa1c384870c857ce9e01df`）**一字节不改**，
> 所有改动以"挂起启动 + 内存补丁 + 回读校验"方式施加，可一键关闭并逐像素还原。
> 相关文档：`docs\72-PeG030坐标与呈现普查.md`（坐标来源普查）、`docs\74-pg-cht机制映射与modgen施行表.md`（机制级补丁路线）、
> `docs\73-PeG030反编译作业图（模块-工具链-路线）.md`（模块-工具链）、`archive\README.md`（显示层试验归档）。

## 0. 结论先行

PeG030 的界面不是"运行时按分辨率排版"，而是**编译期固定的 800×600 布局数据 + 少量内联算术**：

| 面 | 形态 | 实例（已实测） | 适配手段 |
|---|---|---|---|
| **数据面** | 布局记录表，**15 字节/记录** | 表基址 `0x4A96E8`，18 处读点形如 `imul reg, reg, 0xF` + `add reg, 0x4A96E8`（消费函数 `0x413932`、`0x41407A`、`0x430960`、`0x445FFF` …） | **按记录批量重写**（唯一可行的大量改动点） |
| **数据面** | 布局/屏幕记录内的 `800,600` 常量对 | 20 处 word 对 `20 03 58 02`：`0x48E202 0x48E4FA 0x48F556 0x48F7DA 0x490FA2 0x491CE2 0x492982 0x493B76 0x49481A 0x4973CA 0x498166 0x4A0046 0x4A137E 0x4A17BE 0x4A1A82 0x4A3B0A 0x4A60B2 0x4A9316 0x4A9616 0x4AB0D2`；另有 dword 对 `0x491118` | 同上 |
| **数据面** | 主布局表 `0x490470`，字段 `x@+0x02`、`y@+0x04`、`right@+0x06`；右对齐记录表 `0x4A96E8` 内 37 条 × 2 word | 已用于现有 I/K 组 | 同上 |
| **代码面** | 内联几何算术：居中 `(800-w)/2`、边界 `799/599`、钳位 `cmp …,0x780`、重绘区登记、25×25 剔除 | 现有 A / F / G / H / M / N 组共约 80 处 | **按站点替换**（站点表驱动） |
| **代码面** | 命中测试（鼠标 → 控件）与重绘失效登记 | 控件数组 `0x4CCE2C`（stride `0x24`，越界会踩到图层 B `0x4CCE40`） | **与布局用同一变换**（否则点选漂移） |

⇒ 因此适配方案的正确形态是：**一套按 (W,H) 计算的重排版引擎**（数据面批改 + 代码面站点替换），
而不是"对 1920×1080 硬编码 275 条新字节"（现状），也不是外挂拉伸。

## 1. 判定标准（可测、可复现）

对每个目标分辨率、每一类界面（主界面 / 场景选择 / 采购 / 编成 / 选项 / 简报 / 存档 / 战略地图 / 消息框），逐条判定：

| 编号 | 判定项 | 量化标准 |
|---|---|---|
| **A1** | 子界面整体**等比缩放 + 居中** | 子界面外框中心与屏幕中心偏差 ≤ 2 px；外框尺寸 = 原始尺寸 × s，误差 ≤ 1 px（取整） |
| **A2** | 控件**相对位置**保持 | 任意两控件中心距 `dist'` 满足 `|dist' − dist·s| ≤ 2 px`；控件中心相对外框的归一化坐标偏差 ≤ 0.5% |
| **A3** | **命中一致性** | 对每个可见控件中心 + 外框四角点选，命中控件与原始布局 100% 一致；空白处点选不误触发 |
| **A4** | 无黑块 / 无拖影 | 地图区采样网格中"非法黑像素"比例 ≤ 0.5%；静止画面连续两帧截图**逐像素相等**（拖影=失败） |
| **A5** | **多分辨率**一致 | 在 1024×768 / 1280×720 / 1366×768 / 1600×900 / 1920×1080 / 2560×1440 六档下分别通过 A1–A4 |
| **A6** | 可回退 | 关掉补丁后画面与原生 800×600 **逐像素一致**；母本 md5 始终 `c462e897…` |
| **A7** | 稳定性 | 连续运行 ≥ 10 min 无崩溃；进出每个子界面 ≥ 20 次无异常；**正常退出不卡死**（R/S 组每帧 `Lock`/`BltFast` 的教训） |

> A1/A2 是"等比缩放 + 相对位置 + 居中"的形式化：以**设计空间中心为不动点**做相似变换，天然满足"相对位置保持 + 自动居中"。

## 2. 坐标模型与缩放计算

### 2.1 空间定义

- **设计空间** D：`800 × 600`，中心 `Cd = (400, 300)`（原始布局的参考系）。
- **目标空间** T：`W × H`，中心 `Ct = (W/2, H/2)`。
- 界面盒（UI Box）：设计空间按 `s` 放大后的区域；其余区域留给**地图视口**或背景。

### 2.2 三种缩放策略

| 策略 | 公式 | 用途 | 备注 |
|---|---|---|---|
| **S1 等比（letterbox）** | `s = min(W/800, H/600)`，`Off = ((W−800s)/2, (H−600s)/2)` | 最保守：完整等比、四周留边 | 任何宽高比都安全 |
| **S2 高度优先（推荐）** | `s = H/600`；UI 盒 `800s × H` 居中；**地图视口横向吃满 W** | 16:9 玩法：视野更宽、UI 竖直方向满高 | 要求 `W/H ≥ 4/3`（16:9/16:10 均满足）；否则退回 S1 |
| **S3 分轴拉伸** | `sx = W/800`，`sy = H/600` | 仅用于**整幅背景位图 / 过场** | 会变形，禁止用于控件与文字 |

### 2.3 变换公式（以中心为不动点）

```
X(x)   = W/2 + (x − 400) · s          // 水平
Y(y)   = H/2 + (y − 300) · s          // 垂直
Xr(x)  = W   − (800 − x) · s          // 右锚定（贴右边界的面板）
Yb(y)  = H   − (600 − y) · s          // 下锚定（底栏）
Rect(x0,y0,x1,y1) = (X(x0), Y(y0), X(x1), Y(y1))    // 两端各自变换，不要用 x0+w'
W' = X(x1) − X(x0),  H' = Y(y1) − Y(y0)
```

**取整与一致性规则（重要）**：

1. 一律 `round-half-up` 到整数；`W'`、`H'` 至少 1。
2. 矩形的**两端分别变换**（而非"起点 + 缩放后的宽"），消除累积误差；
3. **相邻共边**必须由同一个 `X(x)` 算出（或共享同一取整结果），否则出现 1 px 缝 → 被误判为"黑线"；
4. **命中测试与重绘登记必须调用同一个变换函数**（同一份取整结果），否则出现"看得见却点不到"与"该重绘的区域没重绘"。

### 2.4 各分辨率实算（S2）

| 目标 | s | UI 盒 | 左右留白 | 说明 |
|---|---|---|---|---|
| 1024×768 | 1.28 | 1024×768 | 0 | 4:3，正好铺满 |
| 1280×720 | 1.20 | 960×720 | 160 | 16:9 |
| 1366×768 | 1.28 | 1024×768 | 171 | 16:9 |
| 1600×900 | 1.50 | 1200×900 | 200 | 16:9 |
| **1920×1080** | **1.80** | **1440×1080** | **240** | 主目标 |
| 2560×1440 | 2.40 | 1920×1440 | 320 | 2K |

**算例（1920×1080，s=1.8）**：某子界面记录 `(100, 80, 300, 200)` →
`X(100)=420`、`X(300)=780`、`Y(80)=144`、`Y(200)=360` ⇒ 新矩形 `(420,144,780,360)`，中心 `(600,252)`，
而屏幕中心为 `(960,540)`；若该子界面在原始设计里是**以 800×600 居中**的（`(250,200,550,400)`，中心 `(400,300)`），则 `X(250)=690`、`X(550)=1230`、`Y(200)=360`、`Y(400)=540` ⇒ 中心 `(960,540)` **= 屏幕中心** ✓。
⇒ 判定标准 A1 由此自动满足：**原始居中的子界面在新分辨率下依然精确居中，且外框尺寸 = 原尺寸 × s**。

## 3. 需要调整的渲染 / 布局逻辑（分类清单与规则）

| 类 | 位置 | 已知锚点（实测） | 处理规则 |
|---|---|---|---|
| **L1** 画布 / 后缓冲 / 离屏面 | DDraw 面创建、地图面 | 地图面 `[0x655574]`、显示面 `[0x676904]`、上屏例程 `0x41FF8A`（纯 `BltFast`，`push 0x10` = `DDBLTFAST_WAIT`） | 目标尺寸 `W×H`；地图面宽度用 4096 上限（现 M 组 31 处 `1920→4096`）。**禁止每帧整块重绘/上屏**（R/S 组教训） |
| **L2** 屏幕描述符 / 裁剪矩形 | 现有 A / F / G 组 | `799/599`、`-800→-1920`、战略地图视口 `799/571`、文本矩形 `800/600`、消息框居中 `400` | 全部换算为 `W−1 / H−1 / −W`、`X(400)` 等 |
| **L3** **布局记录表**（15 B/记录） | 表 `0x4A96E8` 等，18 处 `idx·15+base` 读点 | 消费函数 `0x413932`、`0x41407A`、`0x430960`、`0x445FFF` … | 按记录字段（x/y/right/宽高）套 §2.3 变换；右对齐字段用 `Xr`。**这是子界面/按钮整体缩放并居中的主战场** |
| **L4** 面板 / 视口矩形 | 底栏、右面板、地图视口 | `word[0x498d3c]=22`、`[0x498d40]=1919`、`[0x498d44]=1052` | 底栏：下锚定 + 横向拉伸；地图视口：拉伸到 UI 盒以外的剩余区域 |
| **L5** 内联居中算术 | Draw / Gui 模块 | `(800−w)/2` 形态的立即数（现 H/G 组覆盖了一部分） | 换算为新常量，或改为运行时读 `W/H` 的两个 dword（P2 起更彻底） |
| **L6** **命中测试 / 热点表** | Hotspot 模块、控件数组 | 控件数组 `0x4CCE2C`（stride `0x24`，越界会踩 `0x4CCE40` 图层 B） | **与 L3/L4 同一变换、同一取整**（A3 的根治点） |
| **L7** 重绘 / 失效登记 | Draw 模块（脏矩形、25×25 剔除、三层清除） | 脏标志 `[0x498d74]`（30 处清 0）；上屏标志 `[0x498d78]`；滚动缓存 `[0x4AF2F8]`/`[0x4AF2FC]` vs `[0x498d34]`/`[0x498d38]` | 用目标空间矩形重算，且**清除范围必须覆盖整个目标区域**（黑块根因）；"布局变更后一次性全屏重绘"（**不是每帧**） |
| **L8** 文字绘制 | 绘字例程 `0x4704D2`、`0x47097A` 等 | 16bpp GDI 文本路径 | 位置随 L3；字号单独决策（§5） |
| **L9** 位图 / 图标 / 光标 | 美术资源（Shp/S16）与程序化图形 | 遮挡/阴影层 `0x4CCE40`、`0x53D640` | 分两类：**程序化图形**（色块/线框/遮罩）按 `s` 缩放；**美术位图**保持像素尺寸只重定位（否则需 P4 重画素材） |
| **L10** 过场 / 简报 / 影片 | 整幅位图 + 居中 | — | 用 S3 拉伸或**居中 + 黑边**；单独列表，避免被 L3 误缩放 |
| **L11** 存档预览 / 缩略图 | — | — | 按目标尺寸重画或按 `s` 缩放 |

## 4. 实施架构（把补丁做成"参数化重排版引擎"）

### 4.1 现状与问题

`work\peg\peg_launcher.py` 现有 275 条站点是**对 1920×1080 写死的新字节**：换分辨率要重算全部 ✗；
且以"尺寸/坐标平推"为主（K/H/I 组），**没有"以中心为不动点"的居中语义** ✗ —— 这正是"子界面仍钉在 800×600 旧坐标"的直接原因。

### 4.2 目标结构

```
work/peg/relayout/
  layout_model.py     # 设计空间(800×600)、策略 S1/S2/S3、X/Y/Rect 变换 + 单元测试
  sites.tsv           # 站点表：VA | 类(L1..L11) | 锚定方式 | 设计空间坐标/字段 | 原字节 | 长度 | 指纹
  tables.tsv          # 数据表 schema：基址 | 记录数 | 记录长度(15) | 字段偏移 | 每字段的变换
  resolve.py          # resolve(W,H) → 全量补丁（新字节由变换算出）
  apply.py            # 挂起启动 + WriteProcessMemory + 回读校验（沿用现有实现）
  verify.py           # A1–A7 的自动探针（§6）
```

- CLI：`--resolution 1920x1080 --scale s2 --dry-run --selftest --verify`；
- **指纹校验**：每条站点记录原字节 hash，不匹配则整批拒绝并报告（防版本漂移）；
- **边界护栏**：数据面批改必须限制在表长范围内（`记录数 × 15`），避免历史上"越界遍历控件数组踩到图层 B"的事故；
- 应用层沿用已验证的"**挂起进程 → 写内存 → 回读 → 放行**"（`--selftest` 模式下打完即杀，游戏不执行任何指令）。

### 4.3 阶段计划

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| **P0 普查** | 把 `docs\72` 的坐标来源清单归类到 L1–L11，产出 `sites.tsv` + `tables.tsv` | 全部 `800/600/799/599/400/300` 立即数与全部布局表都入表，无遗漏 |
| **P1 单分辨率打通** | 1920×1080 + S2，实现**子界面居中 + 控件等比 + 命中一致** | A1/A2/A3 在 1920×1080 全界面通过 |
| **P2 多分辨率参数化** | 策略切换（S1/S2/S3）+ 六档分辨率回归 | A5 通过 |
| **P3 文字与图标缩放** | 字号档位 / 字形钩子 / 图标缩放（§5） | 文字观感与 UI 盒尺度匹配，A1–A4 不回归 |
| **P4 高分辨率素材** | 字体、UI 美术、地图资源重制 | 视觉质量验收（人工） |

## 5. 字体与图标：本方案唯一无法纯算术解决的部分

字体位图与美术资源是**固定像素尺寸**的，`s>1` 时"按钮变大、字没变大"会明显崩坏。四个选项：

| 选项 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **F1** 字号不动、只重定位 | 位置随 L3 变换 | s=1.8 时字相对偏小 | **P1/P2 先用**（先把几何做对） |
| **F2** 使用更大的内置字号档 | 普查游戏可选字号（`0x4704D2`/`0x47097A` 的字号参数），按目标 `s` 选档 | 档位离散，需重算居中 | P3 优先评估 |
| **F3** 钩文字绘制按 `s` 缩放字形 | 在绘字例程入口按 `s` 缩放目标矩形（整数倍最稳） | 非整数倍会有重采样毛边 | P3 备选 |
| **F4** 改走系统字体渲染 | DDrawCompat 的文字相关配置 | 风格改变、需处理编码 | 仅在 F1–F3 都不满意时 |

**规则**：UI 盒尺寸与字号必须**各自记录、成对验收**（A1 判几何、另加"文字占比"人工判据），避免"几何全对但观感崩坏"。

## 7. 与现有路线的关系

| 现有物 | 处置 |
|---|---|

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 数据表批改越界 → 踩坏相邻数据（历史事故：踩到图层 B `0x4CCE40`） | 表长护栏 + 指纹校验 + 逐表 dry-run 打印 |
| 命中与绘制变换不一致 → 点选漂移 | L6 强制复用同一变换函数；V3 全控件点选回归 |
| 重绘范围与画布不匹配 → 黑块 | L7 用目标空间重算 + 布局变更后一次性全屏重绘（**非每帧**） |
| 每帧整块重绘 → 退出卡死 | 禁止默认开启 R/S；L7 采用事件驱动而非每帧 |
| 字号与 UI 盒不匹配 | §5 的 F1→F2→F3 递进，成对验收 |
| 反调试/环境差异 | 静态 capstone + 只读内存采样（已在用），必要时 DynamoRIO（见 `docs\74`） |
| 法律 | 不修改、不重分发母本 exe；全部改动只存在于内存与本地脚本 |
