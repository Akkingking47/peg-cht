## 二、决定②：补视角（83% → 90%）

### 2.1 根因是「下划线」

`work/glossary/faction_place_audit.py` 的旧 `stem_of()` 正则
`(?i)(_i|_m|_u|_l|_bv|_tv|_v)$` **要求后缀前有下划线**，
而本作大量文件是无下划线的 `110bv.TXT` / `110l.TXT` / `110tv.TXT`：

```
STEM_TAIL     = re.compile(r"(?i)(?:_(?:i|m|u|l|bv|tv|v)$|(?<=[0-9])(?:i|m|u|l|bv|tv|v)$)")
STEM_TAIL_OLD = re.compile(r"(?i)(?:_i|_m|_u|_l|_bv|_tv|_v)$")          # 保留，只作对照
NO_VOICE      = re.compile(r"(?i)(?:_m$|(?<=[0-9])m$|_u$|(?<=[0-9])u$)")  # 同一处 bug
```

未剥成 `110` ⇒ **同场景继承与 `.scn` 查找双双失效**。
修后 `.scn` 命中 **0 → 183**，且它们的 `@22` 取值分布
（10→盟 78 · 4→苏 66 · 3→德 37 · 13→盟 2）**全部落在已知映射内**，独立印证修法正确。

同时补齐两处结构性缺口：

- `is_list_file(fn)`：名单类（`_m` / `_u`）**只接收视角、不当来源**（规则 3），
  另外 `NO_VOICE` 也漏了无下划线形态 —— 一并修。
- `resolve_sides()` 改为**两遍传播** `_propagate(data, side, origin, sources, pin, scndir, tag)`：
  第一遍来源＝口吻；第二遍来源＝全部已判定的**非名单**文件，origin 记 `战役族(二遍)`。
- 新增兜底 `family2_of()`：`FAMILY2 = re.compile(r"(?i)^(\d*[A-Za-z][A-Za-z]*)")`。
  旧 `family_of` 的 `^([A-Za-z]{2,})` 要求首字符是字母，`7Pzra717v_i.txt` 这类**永远进不了战役族**。
  `family2_of` 排在**最后**（`scn_side` 之后）⇒ 不抢任何既有归属，**32 条既有判定一条未变**。

## 三、决定③：复合标题（63 → 4）

「先剥限定后缀、只对地名部分判阵营」，实现为 `strip_quals()` ＋ 一套常量：

```
QUAL_RESULT  = 战果/结果类（决定性胜利/成功/失败/平局…）
QUAL_ACT     = 行动类（行动/战役/作战/攻势/撤退/突围/登陆/空袭…）
QUAL_FEATURE = 地理通名（河/山/岛/湾/海峡/桥/港/城/地区/平原/高地…）
_BRACKET     = 括号注记      (#15v)(RTB#5)(ZS#05)（港）(Nov44)
_JOINED      = 连字符拼接    哈尔科夫-哈尔科夫
_TAILNUM     = 尾部日期编号    - 1943 年 7 月 5 日 / 1944 / " 42"
_TAILTAG     = 尾部分区标记    PeG:WW2 / (2 players)
_QUOTES      = 成对引号书名号
```

判定处改为「原名与剥后名**任一**命中即算命中」：

```python
zp = strip_quals(z)
owners = [c[0] for c in ov if c[0] and (z in zs or zp in zs)]
ak = alias_kind(en, z) if (z in zs or zp in zs) else "其它写法"
... if ak in ("简称", "same"):
```

两处缺陷（首次跑只降到 49，未达预期）已修：

- `_TAILNUM` 原写成 `年…月` **必含「月」**且不容尾空格 ⇒ 改为
  `r"[\s\-—–,，、·]*#?\d+([\s]*年([\s]*\d+[\s]*月([\s]*\d+[\s]*日)?)?)?[\s]*$"`；
- `analyze()` 判阵营时**仍用未剥的原名**去查 `zs` ⇒ 改为用剥后名 `zp`。
- 另删除文件下部**旧的重复定义** `alias_kind`（后定义会覆盖新定义）。

结果：

| 项 | 修前 | 修后 |
|---|---|---|
| ✅ 唯一阵营接受（将来可升 error） | 18 | **43** |
| ⚠️ 多阵营接受（门里判不出谁对） | 7 | **27** |
| 🟡 简称（缺别名登记） | 9 | **23** |
| 🟠 复合标题 | 63 | **4** |

剩下的 4 条是**真复合**，不该自动剥（人工裁决）：

## 四、⭐ 决定性实测：修键的影响 = 0 条

按用户顺序（决定②完成后再修键），把对齐结果**喂给真实的门**测一遍：

| 口径 | 偏离总数 | 分类变化 | 新增偏离 |
|---|---|---|---|
| 现状 | 288 | — | — |
| 加 14 个新键后 | **288** | **0** | **0 → 0** |

**分类统计仍是清一色 `{'已登记': 288}`。**

### 为什么是 0

门的「已登记」判定是 override.tsv · scope-diff.tsv · faction-terms.tsv · 三层词库的**并集**，
faction 两表只是其中一支；而这 288 条偏离项**本身就都是「未登记」类**，
不是「阵营不对」类 ⇒ 多一支对齐上来，一条都扶不起来。

### 已修正的误导性数字

`faction_wire.py` 原本只拿 faction 两表按 ID 自算，报出「修键后放宽 **1** 条」——
**偏乐观的假象**。已改为以真实门为准：

- 新增 `aligned_authorized(rows, by)` 与 `predict_effect(rows, by)`（内部**惰性** `import layer_gate`，
  任何异常 ⇒ `None`，绝不影响门）；
- `analyze()` 返回值与 `summary()` 带上 `effect`；
- `report()` ③ 段改为并列两条口径，并在两口径不一致时明确写出原因；
- `layer_gate.wire_brief()` 现在打印**真实门**数字：

```
登记 65 ID（未解析 30）· 唯一阵营 43 / 多阵营 27 / 简称 23 / 复合标题 4 · 修键后放宽 0 条（真实门）
```

`evidence/faction-wire.txt` ③ 段同时留下两份：

```
本模块简化口径：未登记→已登记 1 · 已登记→未登记 0
⭐ 真实门 `layer_gate.compute()` 口径（以此为准）：
     新增对齐键 14 个 · 偏离 288 → 288 条 · 放宽 0 条 · 收紧 0 条
     ⚠️ 简化口径报 1 条、真实门 0 条 —— 简化模型漏算了 override.tsv / scope-diff.tsv / …
```

### 对齐细节（备查）

- 层表键的 `cat` 分布：`UNIT 25427 · PLACE 7120 · EQUIP 5761 · TEXT 4216 · LEADER 2701 · TERM 2121 · TITLE 514 · NATION 215`。
  不做 cat 准入时，前缀对齐会造 **63 条假命中**（`Crusader AA` / `Crusader I` 是坦克，被当成「十字军行动」）。
- 准入规则：places 只认 `{PLACE}`，ops 认 `{PLACE, TITLE, TERM}`（**不收 TEXT**）；
  再加「非整句」护栏 `"." in k or len(k) > 60` ⇒ 拒掉 63 个 UNIT 和整句。
- 「其它写法」种子再救回 **7** 个：`Chisinau` · `Citadel_ND` · `Hanko` · `Krakau` ·
  `Seelöwe→Sealion` · `Tarnopol→Ternopol'` · `Warschau→Warsaw`；仍有 23 个找不到键。
- 两个**误配**（即使修键也该挡，属种子质量问题）：`Citadel_ND → Nordwind`（错）、
  `Charkow → Kharkov River`（存疑）。

### 7.2 ⚠️ 踩坑（新增，编号顺接 W 系）：比对脚本必须先对齐「命名空间」

`deploy_tarnopol_6v.py` 的 ③ 步本意是「临时产物 vs 现有 `out` 逐文件 md5」，**首跑却报 3777 个文件全部不同**。

- **真因是脚本自己的 bug**：左侧根取 `_rebuild-tmp`（键＝`SCENARIO/x.txt`），右侧根取 `OUT`——
  而 `OUT` 已经是 `…\testbed\out\SCENARIO`（键＝`x.txt`）⇒ **两边键空间不交集**，每个键都「不同」。
- **它没有造成任何损害**：断言「预期只有 1 个文件不同」直接把它拦成 `⛔ 中止，未写任何正式文件`。
- **教训**：比对两个目录前，**先打印两侧文件数与 3 个键样例**确认命名空间一致；
  「总数不等 / 几乎全不同」这种**过于整齐的异常**，优先怀疑比对器本身，而不是怀疑数据。
- 修法：左侧改为 `os.path.join(TMPROOT, SUB)`，加 `--reuse-tmp` 复用已建产物（省一次全量重建）。
  修正后一次通过：**3777 vs 3777 · 内容不同 1 个 · 多出 0 个**。
