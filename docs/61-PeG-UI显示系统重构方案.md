## 二、本轮静态读穿的 UI 机制（可复用的结论）

### 2.1 绘制漏斗

```
绘制入口 0x4235E5(rect*, ctrl, index, dx, dy)
   → 0x47E0A0(rect, ctrl, index, dx, dy, flags, 0)        flags 常见 0x1008000 = DDBLT_WAIT|DDBLT_KEYSRC
       → 源表面 = ctrl->[+4] + index*0x1c + 0x18
       → 0x47E050(ctrl, index, &a, &b)                    从表项 +0/+4 读尺寸
       → 0x47E4E0(rect, ctrl, &out, index, dx, dy)        裁剪/构造最终矩形
           → dst.left = rect.left + dx (仅当 dx >= 0)，否则保留 rect.left
           → dst.top  = rect.top  + dy
           → 用 rect.bottom+1 夹取 dst 下边界
       → call dword ptr [ecx+0x14]                         IDirectDrawSurface::Blt（0x80004005/0x80004001/0x80070057/0x8876006E 有错误分支）
   → 0x4231DF(...) 画外框
```

- `0x4235E5` 的调用点共 **187 处**（`python find_calls.py 0x4235e5`）
- 调用约定：`(rect*, ctrl, index, dx, dy)`；`dx/dy` 是**图集内偏移**（取哪一块），`rect` 是**屏幕目标矩形**
- 常见写法：先把矩形写进全局工作矩形 **`0x676980`**（文件里全 0，运行期填写），再 `push 0x676980`

### 2.2 控件记录表

- `0x4A22F8`：16 条记录，步长 `0x24`，字段 `+0` 标志位、`+2` x、`+4` y、`+6` right、`+8` bottom、`+0x10` 绘制回调（这 16 条多为 `0x44ACDA`，另见 `0x4489BF`/`0x448B3A`）
- `0x490470`：40 条同类记录（另一组界面）
- `0x44ACDA(index)`：取 `rec = [0x4cce2c] + index*0x24`，构造 `rect = {x, y-1, right+1, bottom+1, surface=[0x676904]}`，再算 `dx = 751 - rec.x`、`dy = 22 - (rec.y-1)` → 调 `0x4235E5`
  - **`mov edx, 0x2ef`（751）在 `0x44AD7E`，`mov ecx, 0x16`（22）在 `0x44AD75`**（另有对应 push 版本 0x44AD9C/0x44ADA5）
  - ⇒ 这条路径的**源偏移是从记录位置推出来的**，所以粗暴移动记录会让 `751 - x` 变成大负数 ⇒ **源矩形反向/越界 ⇒ Blt 拉伸出彩色带**（v4/v7a/v8a/v8b 四轮实测的都是这个）
- `0x440794(table, index, flag)`：只改标志位（bit0/bit4/bit5），**不写坐标** ⇒ 记录里的 x/y/right/bottom 就是布局真值

### 2.3 运行期「缩放 + 居中」阶段（重要发现）

`0x420030`（工具栏绘制前在 `0x44882A` 调用）：

```
0x42003a  if ([0x4af334] != 0x1a) call 0x4489cc
0x420048  0x47047a([0x4af300], [0x498d3c], [0x498d40]+1, [0x498d44]+2, 0)
0x420078  call 0x42311b
0x42007d  w = [0x498d44] - [0x498d3c] + 1
0x420090  w = w * [0x686a90] / [0x64c700]
0x4200a7  h = [0x498d40] + [0x4af300] ; h = h * [0x64c700] / [0x686a90]
0x420109+ sar eax, 1        ← 除以 2（居中）
0x420126  结果写成 [0x6633e0]..[0x6633ec] 一组矩形
```

- **宽度按 `A/B`、高度按 `B/A` 缩放，再 `sar 1` 居中** ⇒ 引擎内部本来就有一套「按比例缩放 + 居中」的 UI 变换，这正是用户要的「等比居中」的现成机制
- `[0x686a90]` / `[0x64c700]` 在文件里是 0，运行期是**累加量**：`0x41f10f`/`0x41f118` 置 0，`0x41f284`/`0x41f2a2` 累加，`0x41f3ee` 处 `+0x28` 且 `cmp edx, 0x780`（**0x780 = 1920**，值得追）
- `[0x498d3c]=22`、`[0x498d40]=799`、`[0x498d44]=571` 是 **.data 里的矩形模板**（799=800-1 面板右缘，571=600-28 底栏上缘）；.text 中**没有写它们的指令**（只有读）⇒ 改 .data 就能改布局来源

### 2.4 鼠标位置来源

- 只导入 USER32（无 DirectInput）；`GetMessagePos`（IAT `0x6aa5bc`）**唯一调用点 `0x45012E`**，函数 `0x45011F` 把 `x=LOWORD`、`y=HIWORD` 连同消息参数打包进栈结构，受 `[0x4c90d8]` 控制
- `[0x4c90e0]` 不是屏幕尺寸，而是一个**UI 状态标志字**（bit0/bit1/bit3/bit4 等被反复测试与置位；`0x41c4a1` 把它拷进 `[0x4af270]`，`0x41c6f0` 写入）
- 工具类新增（本会话）：`work\peg\find_mem.py`（线性反汇编并按绝对地址找读写点，坏字节跳过；`python find_mem.py 0x4c90e0 30 --ctx 2`）、`work\peg\peek_va.py`（直接 dump 文件里某个 VA 的 word/dword）

## 三、彩色拉伸带的成因假设（待实测确认）

三条候选，按可能性排序：

1. **本轮 16:9 构建把矩形模板右侧值改成了 1919**（`0x498D40`：799→1919；tag `w-1`，见 `out\res_diff_v4.tsv` 第 136/137 行），而某个元素**把这个值当成 Blt 目标宽度**用，源精灵很小 ⇒ DirectDraw 把小块拉成一条彩带；鼠标移进新暴露的地图区域时才绘制该元素，滚动重绘后暂时消失。**v5c（1024×768，0x498D40=1023）没有此现象**，与「值超某缓冲上限」一致
2. 鼠标跟随元素（提示框/滚动箭头）的矩形在 800×600 以外算成反向（`0x47E4E0` 的 `dx<0` 分支 + `rect.bottom+1` 夹取）
3. 图集（源表面）宽度不足，`dst` 落在图集外

**验证实验（v9a）**：以 1920×1080 配方为基准，**跳过 `0x498D40`/`0x498D44` 两处**（保持 799/571），其余不变 ⇒ 若彩带消失，则成因 1 成立，随后按「布局来源」单独处理这两处，而不是当普通尺寸站点改。

## 四、路线与阶段（B 方案）

### 路线选择

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **S：静态站点补丁**（现有能力） | 扩展 `patch_res_wh.py` 的站点表：记录 x/y/right/bottom、`.data` 模板、`.text` 布局常量；同时按位移量同步改**成对的源偏移常量** | 无依赖、可复现、可批量 | 站点多（187 处调用点里的布局相关项 + 各子界面）；每处都要配套源偏移 |
| **C：exe 内代码洞穴注入** | 把自写的 x86 缩放入口（按比例缩放 + 居中 + 源矩形校正）写进 .text 空隙，把 `0x420030` / `0x47E4E0` 改成 `jmp 洞穴` | 一处改动覆盖全部界面；可实现「等比放大」；仍只改副本 exe | 需手写汇编 + PE 补丁工具；调试靠截图，成本高 |
| **D：运行期 DLL hook** | 注入 DLL 挂 `0x47E4E0`/`0x4235E5`/Blt，按分辨率重算矩形 | 最灵活、可热调参 | **本机无 C 编译器**（cl/gcc/tcc/link 全无，仅 dotnet）；需先装 MinGW 或走 .NET NativeAOT 导出 |

**建议**：先做 **S**（把 UI 布局来源与源偏移配对关系摸清），当「需要改的站点超过约 40 处」或需要「整体等比放大」时，升级到 **C**。D 只在 C 被证明不可行、且用户愿意装工具链时启用。

### 阶段

- **P0 定位**（进行中）：为每个界面建立「元素 → 记录/矩形 → 绘制调用点 → 源偏移」对照表；用截图测量确认落点（工具：`probe_btn.py`/`probe_widgets.py`/`diff_shot.py`）
- **P1 主战斗界面**：顶栏、底栏、右侧工具列贴新边缘；面板背景按新尺寸拉伸/重复；修复彩色带
- **P2 次级界面**：装备简介、单位信息、任务/存档对话框、菜单（走 `0x490470` 记录表与 `0x41f0xx` 布局函数）
- **P3 等比放大**：决定缩放因子（1920/800=2.4 与 1080/600=1.8 不等 ⇒ 若求「等比」需取单一因子，多出的宽度留给地图）；启用 `0x420030` 的缩放+居中路径
- **P4 验收**：分辨率自检、点击命中、存读档、中文显示、逐界面截图核对
