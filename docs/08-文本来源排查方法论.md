# 08 · 文本来源排查方法论（汉化经验固化）

> **为什么要写这份**：本项目的核心难点从来不是"翻译"，而是**"这段字到底从哪来"**。
> 一条文字可能来自 exe 内置表、RT_DIALOG 资源、`strings-XX.txt`、efile 的 `TEXT-XX\`、
> efile 的 `SCENARIO\`、**甚至一张 PNG 位图**。
> 找错来源 = 改了半天没反应（本项目在「地图地形标签」上就白折腾了很久）。
>
> 本文把**判断顺序**和**每一条的验证方法**固化下来。
> 新会话接手时：**先读 `00-工作空间导航.md`，再读本文，再动手**。

---

## 一、五套显示机制速查（含 2026 新增的第 5 套）

| # | 机制 | 位置 | 生效 | 负责的内容 |
|---|---|---|---|---|
| 1 | `STRINGS-XX` 文件名前缀 | `<游戏根>\OPENGUI\strings-<lang>.txt` | ✅ | **UI 文本**（见 §三：按行索引的 916 行表） |
| 2 | `TEXT-XX\`（efile 根目录） | `<efile>\TEXT-<LANG>\<同名文件>` | ✅ | `equip.txt` / `names.txt` / `nations.txt` / `strings_efile.txt` / `fronts.txt` |
| 3 | `TEXT-XX\SCENARIO\` | `<efile>\TEXT-<LANG>\SCENARIO\` | ❌ | **游戏根本不查这个路径**（只作译文存档） |
| 4 | 覆盖 `<efile>\SCENARIO\` 原文 | `<efile>\SCENARIO\*.txt` | ✅ | 场景文本（**必须先备份**） |
| 5 | **PNG 图形 atlas** | `<游戏根>\OPENGUI\*.png` | ✅（需**重绘图片**） | **地图地形标签**等"看起来像文字、其实是图"的内容 |

机制 1–4 的细节见 `06-efile语言机制与汉化要点.md`。机制 5 是本轮新发现，见 §四。

另有两条**引擎级**路径（需改 exe）：

- exe 内置 `.data` 字符串表 + `RT_DIALOG` 资源 → 见 `05-exe硬编码汉化可行性评估.md`
- efile 名与描述（`efile.xml` / `efile.txt`）→ **未做**

## 二、排查决策树（按性价比排序，务必按顺序走）

```
某段文字显示为英文，想改成中文
│
├─1. 全 exe 搜原文（ASCII）
│     ├─ 命中 → 看命中位置：
│     │    ├─ .rdata / .data 的字符串 → push 引用 / 内置表 → 走 exe 补丁（docs/05）
│     │    └─ 只在某张"步长 0x100 的表"里 → 那是内置默认表，先记下地址备用
│     └─ 未命中 → 继续
│
├─2. 查 OPENGUI\strings-XX.txt 的"对应行号"
│     （该文件是按行索引的表：第 N 行 ↔ exe 内置表第 N 项）
│     └─ 改完没反应 → 说明这段字不归它管 → 继续
│
├─3. 查 efile 目录
│     ├─ <efile>\TEXT-ZH\<file>     （机制 2）
│     └─ <efile>\SCENARIO\*.txt     （机制 4，注意 TEXT-ZH\SCENARIO 是死路）
│     └─ 改完没反应 → 继续
│
├─4. ★ 内存级排查（最快能一锤定音的一步）
│     游戏运行中，全进程扫原文的 ASCII 字节：
│     ├─ 命中 → 说明它确实是"内存里的文本"，去 dump 命中地址附近，
│     │          看被谁引用、属于哪块缓冲区，反推加载路径
│     └─ **0 命中 → 它根本不是文本，是图形！** → 直接跳到第 5 步
│
└─5. 找图形资源
      ├─ 在 exe 里 grep 图形名（连续的名字块，见 §四.1）
      ├─ 在 OPENGUI\ 里找对应 .png
      └─ 判定"文字型 atlas"还是"图标型 atlas"（见 §四.3），再决定重绘方式
```

**核心经验一句话**：

> **改了三处文本都没反应时，不要继续找文本 —— 先做内存扫描。
> 内存里搜不到，就一定是图片。**

## 三、`strings-XX.txt` 是按行索引的表（重要）

`OPENGUI\strings-de/es/hu/pl/zh.txt` 都是 **916 行**，行号严格对应 exe 内置字符串表：

| 行号 | 内容 |
|---|---|
| 1–21 | 以 `*` 开头的说明注释（**不能删、不能插行**） |
| 22–41 | **`[terrain]` 地形名**（Clear/City/…/Rails） |
| 43–45 | `[sides]` 阵营名（Axis/Allied/None） |
| 47–70 | `[classes]` 兵种类别名 |
| … | 其余 UI 文本 |

- **前 21 行是注释**，所以"行号 22 = 地形 0"。
- 官方德语/波兰语/西语包是**最好的对照物**：同一行号上是什么，就知道那行管什么。
- exe 侧对应的大表在 `.data`：起点 **`0x5857A0`（"Axis"）**，步长 `0x100`，VA `0x986DA0`。

> ⚠️ **改 `strings-zh.txt` 绝不能增删行**，错一行 = 整个 UI 串位。
> 正确流程见 `00-工作空间导航.md` 第四节（改 `work\map*.tsv` 再 `build-zh.ps1 -Deploy`）。

### 4.2 `hex_text.png` = 地图地形标签（已解决）

| 项 | 值 |
|---|---|
| 文件 | `OPENGUI\hex_text.png`（各 efile 可自带覆盖版 `EFILE_xxx\OPENGUI\hex_text.png`） |
| 尺寸 | `60 × 950`（19 格）或 `60 × 900`（18 格） |
| 分格 | **步长 50 px**，第 i 格 ↔ **地形 ID i** |
| ID 依据 | 与 `OPENTXT_SAMPLE\TerrainEx.txt` 的 `0=clear … 17=custom, 18=shallow waters` 完全一致 |
| 第 0 格 | 官方设计为**空**（Clear 不标注） |
| 标签位置 | 每格内距顶部 +4…+15 px，水平居中 |
| 透明 | **色键**：全局 `#F8E4D8`，OPENPG 等 `#FF00FF`。**两份原图都没有 `tRNS` 块** ⇒ 靠 `SDL_SetColorKey`，不是 alpha |
| 风格 A | 彩色底牌 + 黑/白字（全局图、SON） |
| 风格 B | **黑边彩色文字**（无底牌），按地形配色（植被黄/绿、水蓝、断崖红） |
| 风格 C | **图标**（`EFILE_Clu`：16×16 灰底圆形象形图）——**不是文字，不用翻译** |

### 4.3 判定"文字型"还是"图标型"

按格统计**非背景像素的外接矩形**：

- 文字型：宽 27–57 px、高 11–18 px（**明显扁而宽**）
- 图标型：约 16×16（**近方形**）

⇒ 判据：**所有格的外接矩形平均宽度 < 20 px ⇒ 图标型，跳过**。

另一条独立判据：**主色像素数 / 外接矩形面积**
- `≥ 0.55` ⇒ 该格是「**底牌型**」（有一块实心色块）
- `< 0.55` ⇒ 该格是「**文字型**」（只有笔画）

### 4.4 重绘要点（血的教训）

工具：`work/gfx/redraw-hextext.ps1`　标签表：`work/gfx/terrain-labels-zh.txt`

必须做到：

1. **尺寸、步长一模一样**（60×N、50 px 一格），否则 blit 坐标全错
2. **输出仍为 8bpp 索引 PNG**，且 **调色板 index 0 的 RGB 与原图逐字节一致**
   ⇒ 不管游戏按索引还是按像素值做色键，透明都继续有效
   （原图 4bpp 转 8bpp 是安全的：`SDL_image` 对索引 PNG 本来就统一给 8bpp 表面）
3. **文字型用「关抗锯齿」或"调色板里预置混合色"**：否则边缘抗锯齿像素落在色键色之外，
   地图上会出现粉色/品红毛边
4. `System.Drawing` 的坑（索引格式）：
   - **不能** `Graphics.FromImage()` 索引位图 → 改在 32bpp 临时图上画
   - **不能** `SetPixel()` 索引位图 → 改 `LockBits` + `Marshal::WriteByte` 直接写索引
   - `new Bitmap(path)` **会锁住文件**，必须在 `Save()` 前 `Dispose()`
5. 两道护栏（已内置）：
   - 外接矩形平均宽度 < 20 px ⇒ `SKIP: looks like an ICON atlas`
   - 成品调色板 256 项 / 原图 8–17 项 ⇒ `SKIP: already converted`（防二次转换）
6. **重跑前必须先从备份还原**（脚本读的是当前文件，不是原图）

### 4.4b 全库排查结论：**只有 3 张图**含烘焙文字

把全部 UI 图片过了一遍（全盘 18386 张，但 `UNITPEDIA`/`OPENDAT`/`SCENARIO` 都是单位图与地图；
UI 集中在 `OPENGUI` **624 张** ＋ `SUITE_UI` 21 张）。**结果**：

| 图 | 尺寸 | 内容 | 色键 | 格距 |
|---|---|---|---|---|
| `OPENGUI\hex_text.png` | 60×950 | 地图地形标签（详见 §4.2） | `#F8E4D8` / `#FF00FF` | 50 px |
| `OPENGUI\mouse_build.png` | 60×182 | 工兵/运输模式 **14 格** | **`#FFFFFF`** | **13 px** |
| `OPENGUI\mouse_missions.png` | 60×104 | 任务指派 **7 格** | **`#FFFFFF`** | **13 px** |

**其余全是纯图形**：象形按钮（`buttons*`/`menu_main`）、天气图标（`climate`）、
兵种剪影（`unitclass`/`uniticomoves`/`uniticotargets`/`menu_class2`）、徽章（`attachments*`/`unit_stats`）、
菜单图标列、**数字点阵**（`mouse_nums`）、数字格（`unitinfo`）、空框模板（`hex_types`）、
纯色矩形（`box_*`）、对话框底图（`dlg_*` 10 张）、六角格贴图与特效（`hex_*`/`fire_*`/`explosions`）。

**两条新增铁律**（`mouse_*` 这类「底色带 + 同行图标」的图）：

1. **只换字，不动框**（轮廓/图标/色键/尺寸/格距全保留）；**擦除区不能一刀切**——
   带图标的格若擦满全宽会把图标一起擦掉。正解＝**按列剖面自动检测图标**：
   统计该格「文字色」逐列像素数得连续段，若**末段与上一段空隙 ≥6 px 且末段起点 ≥42**
   ⇒ 末段是图标，擦除止于其前 2 px。（字母间距仅 1–2 px，不会误判；
   阈值定 8 px 时曾漏判 7 px 间隙 → 图标被擦掉。）
2. ⚠️ **PowerShell 大小写不敏感**：参数 `[string]$Labels` 与局部 `$labels = @(...)` 是**同一个变量**，
   赋数组时被参数类型约束**强制转成字符串** → 只处理了第 1 格。
   **参数名与局部变量名必须严格不同**（`$COLS`/`$cols` 同理）。
   —— 这也是「脚本纯 ASCII + 数据走外部文件」之外的另一条自保习惯。

> 工具 `work\gfx\localize-mouse-labels.ps1` ＋ `work\gfx\mouse-labels-zh.txt`；
> 细节见 `09-位图文字全库排查与鼠标标签汉化.md`。

### 4.5 本轮完整证据链（可复用为"如何证伪"的范例）

1. 全 exe 搜 `Escarpment`/`Bocage`/`Swamp`/`Ocean` → 只命中 `0x5842A0` 那张 21 项内置表
2. 该表已汉化，且**运行时内存中确认一致** → 它是"地形数据/工具提示"用的内置名表，**但地图标签不读它**

### 4.6 内存级扫描怎么做

`work/exe/mem-scan.ps1`、`work/exe/mem-dump.ps1`（P/Invoke）：

```
OpenProcess(0x0410)            // QUERY_INFORMATION | VM_READ
VirtualQueryEx 遍历区域        // 只看 State=MEM_COMMIT、有读权限的区域
ReadProcessMemory 读整块
逐字节找 needle
```

极简版（本轮用的）见对话记录里的 `MS` 类；关键是**先按区域读，再在块内匹配**，
输出命中地址 + 前 16/后 48 字节上下文，便于定位"这块内存是谁的"。

## 五、硬件参数备忘（反汇编常用）

### 5.1 段布局（`OpenGen.exe`，FileVersion 26.3.30.0，PE32，ImageBase `0x400000`）

| 段 | VA | 文件偏移 FO |
|---|---|---|
| `.text` | `0x00401000` | `0x00000400` |
| `.rdata` | `0x00878000` | `0x00477200` |
| `.data` | `0x00971000` | `0x0056FA00` |
| `.rsrc` | `0x012AB000` | `0x005BEC00` |

**`.data` 换算：`VA = FO + 0x401600`**

### 5.2 已定位的关键地址

| 地址（FO） | VA | 内容 |
|---|---|---|
| `0x5842A0` | `0x9858A0` | **引擎内置地形名表**：21 项，步长 `0x100`（`Clear/City/…/Shallow Sea`，已汉化） |
| `0x5857A0` | `0x986DA0` | **内置 UI 字符串大表起点**（`"Axis"`），步长 `0x100`，共 916 项，对应 `strings-XX.txt` 行号 |
| `0xB4D030` | — | `UserPreferences`（设置开关位，读写都在 `0x34D1xx` 一带） |
| `0xB4D034` | — | `UserPreferences2` |
| `0xBFF068` | — | 设置对话框控件结构基址（步长 `0x100`） |

### 5.3 编码链路

```
单字节文件 --MultiByteToWideChar(CP_ACP=936)--> UTF-16 --TTF_RenderUNICODE_Blended--> 屏幕
```

- 本机 `Active code page: 936`，所以出稿统一 **GBK(936) + 无 BOM + CRLF**
- 字体 `FONTS\Deng.ttf`；exe **只导入 `TTF_OpenFont`，不支持 `.ttc`**
- 对话框文本是 **UTF-16LE**，原地替换须满足 `新长度 ≤ 原长度`（UTF-16 code unit 计）
- **含格式符（`%d`/`%s`）的串一律"写副本到空洞 + 改指针"，不要原地替换**
  （曾把 `File: %s   [%d scenarios]` 原地改短，显示成 `[4[6]20456 个场景]`）

## 七、⚠️ 操作纪律（血泪教训，务必遵守）

1. **备份与覆盖放两条独立命令**，先验证备份（列目录 + 校验 MD5）再覆盖
   - 2026-09-20 事故：一条命令里同时备份+覆盖，PowerShell 语法错误（`"$D:\..."` 被当变量名）
     导致**整个脚本拒绝执行** → 备份没跑、覆盖跑了 → 807+190 个原始场景文本被无备份覆盖
   - 救回：从官网重下 `https://www.open-general.com/install/efiles_r/EFILE_OLGWW2.zip` /
     `EFILE_OPENPG.zip`，存档为 `backup\ORIGINAL-*`
2. PowerShell 里 `"$id:"` 必须写 `${id}`；DSH 传参会丢反引号，写 `"\r?\n"` 不写 `` "`r?`n" ``
3. 含中文的 `.ps1` 必须存 **UTF-8 with BOM**（PS 5.1 否则按 GBK 误读路径）
   —— 或者干脆**脚本纯 ASCII**，中文走参数/数据文件（本轮 `redraw-hextext.ps1` 就是这么做的）
4. 批量操作前先小范围（1 个文件）验证脚本跑得通
5. 改动后立即抽检；**先确认备份存在**再谈其他
6. `[Text.Encoding]::Latin1` 在 PS 5.1 不存在，用 `GetEncoding(28591)`；
   读 efile 单字节文本用 `GetEncoding(1252)` 或 `GetEncoding(936)`
