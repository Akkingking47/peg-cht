## 二、每帧调用链（已反汇编确认）

```
主循环
└─ 每帧界面分发器                     0x4489CC
   ├─ 读 word [0x498d74]（共享刷新标志）
   ├─ ≠0 且 byte[0x4af360]==0 → call 0x44AC45   「整屏刷新」
   │     ├─ 顶栏                        0x44C50A → 0x44C519
   │     ├─ 底栏                        0x44C57B → 0x44C547 → call 0x47047A(x,y,w,h,surf)
   │     └─ 控件循环                    0x423CD6
   │     然后 [0x498d74] = 0
   └─ 否则 → call 0x423CD6                「控件增量刷新」

滚动/已绘范围更新器                    0x41F2C0（无直接 call，经函数指针表调用）
   ├─ call 0x43D16E                     算 extent
   ├─ extent_w += 1 / extent_h += 1      0x41F2FD / 0x41F30F
   ├─ 格数钳位 45 / 40                   0x41F329 / 0x41F340
   ├─ 横向钳位 max = mapW − vpW − 1      0x41F374 处 cmp/jle → 0x41F397 写 scrollX
   ├─ 纵向钳位（同型）                   0x41F39E–0x41F3E7 → 写 scrollY
   ├─ mapW += 0x28，上限 0x780（M 组站点）0x41F3FA
   └─ call 0x41FA85                      「整块重绘」
         for i < extent_w: for j < extent_h:
            call 0x41F41C(i,j)            逐格地形
            call 0x41F685(i,j)            逐格叠加（单位/阴影/高亮）

地图上屏（每帧）                        0x41FF8A
   src = ( x, y, x + (vpRight − vpLeft) + 1, y + (vpBottom − vpTop) + 1 )
   BltFast(dst = 后备缓冲 [0x676904], dstX = vpLeft, dstY = vpTop,
           src = 地图面 [0x655574], &src, 0x10)
   ├─ 成功 → 地图出现在屏幕上
   └─ 失败 → 0x42000B: push 0x491308 / push 0x420 / call 0x437420（**只记日志，永不回退**）

单位/光标精灵 Blt / BltFast → 后备缓冲 → Flip
```

## 三、架构瓶颈（有证据）

1. **刷新信号是「单标志 + 多消费者」**（最关键）。`[0x498d74]` 在母本里有 40 余处消费者，每处都是「读到 ≠0 → 重绘自己负责的那部分 → 清零」。谁先跑到谁把信号吃掉，后面的看不到。任何「每帧强制整屏刷新」的补丁（我们早先的 B 组：`0x4489D8` 的 `je` 改成 `nop`）都会每帧抢先清零，于是**地图覆盖层（选中单位的移动范围阴影、高亮）拿不到刷新信号**——实机表现正是「选中单位后鼠标不动，阴影出现一下又消失；拖动鼠标/单位才稳定显示」。B 组已因此关闭（实测：阴影出现一下即消失 → 关 B 后仍会消失，说明还有第二重原因，见第 2 条）。

2. **重绘范围由「已绘格数 extent」决定，而不是由内容变化决定**。`0x41FA85` 只重画 `extent_w × extent_h` 个格；`extent` 每帧 +1 直到 45/40 上限，之后不再变化。因此覆盖层是否被重画，取决于「它所在的格是否落在本帧的重绘循环里」——选中单位、开火范围这类**事件驱动的覆盖层**没有独立的失效机制，只能搭 extent 的车。这是阴影「只闪一下」的结构性原因。

3. **地图上屏的源矩形与滚动范围解耦**。`0x41FF8A` 的源矩形宽度恒等于视口宽度（宽屏后 1920），而地图面只有 `mapW` 宽（如 1631）。任何 `scrollX < 0` 或 `scrollX > mapW − vpW` 都会让 `src.left/src.right` 越界；原生 DirectDraw 对越界源矩形是**整笔拒绝**，且代码路径只写日志、不做夹取——于是那一帧地图区域保持陈旧（黑/残留）。母本 800×600 视口天生有 1120 像素余量，宽屏后余量归零。实测证据：引擎把 scrollX 钳成 `max = mapW − vpW − 1 = −202`，`diag_watch.py` 两次实机都读到负数。

4. **屏幕尺寸是一组散落的立即数，没有统一几何中心**。同一个「屏幕」概念分散在：视口裁剪组、顶栏/底栏绘制函数、站点/布局表、截图缓冲（`{800,600,1,24}`）、像素寻址步长（`imul …, 0x320`）、鼠标坐标换算（`add …, 0x258 / 0x226`）等处。每改一处都要单独验证语义——底栏那次 `572→h−28 / 600→h` 直接导致**游戏无法启动**（这两个数极可能同时参与底栏源面的尺寸/索引），已回退。

5. **软件光标（保存/恢复背景）**。鼠标拖影说明「保存鼠标下方区域并在移动后恢复」的逻辑仍在按 800×600 记账：鼠标移出该区域后保存的矩形无效，恢复时把旧内容贴回，形成永久残留黑块（实测：简报/菜单画面尤为明显）。

6. **代价**：M 组把两个地图面都做成 4096×4096×16bpp ≈ 32 MB/面，两面共约 64 MB，且整块重绘一次最多 45×40 格。

## 四、优化建议（可落地，按性价比排序）

1. **给 `0x41FF8A` 的源矩形加夹取**（推荐先做）。在计算完 src 之后插入 clamp：`left = max(0, left)`、`top = max(0, top)`、`right = min(面宽, right)`、`bottom = min(面高, bottom)`，并把 `dstX/dstY` 相应平移。这样负滚动/越界再也不会整笔被拒——比「跳过钳位（N 组）」更本质，而且能同时消除「进入场景瞬间整片黑」「滚动到边缘后地图不更新」这一类症状。落地方式：在 `0x41FF8A` 附近找空闲字节或复用现有栈局部变量做补丁；先用 `diag_watch.py` 记录 scroll 与 extent，改完对比。

2. **给覆盖层独立的失效信号**。不要再动 B 组。做法二选一：(a) 在选中/移动/开火等事件处理里直接置 `[0x498d74]=1`；(b) 把「移动范围阴影」这类覆盖层的绘制挂到 `0x41F685` 的逐格调用里（每格一次判断），使其随 extent 重绘。先定位阴影的真实绘制点（从 `0x41F685` 向下追，或对 `BltFast` 的源矩形做一次 trace 定向采样）。

3. **建立几何中心**。把「屏幕宽/高」统一到视口变量（`[0x498d40]−[0x4af300]+1` 等），或在补丁层把所有形态的屏幕尺寸常量集中登记到启动器 `CODE_EDITS`（登记 + `--dry-run` + `--selftest` 是本次已验证的安全流程）。鼠标坐标换算与软件光标优先接入。

4. **鼠标坐标换算与软件光标**：把 `add …, 0x258`（600）类偏移改成「视口高」，把光标保存矩形改成视口矩形；或评估在 DDrawCompat 层改用硬件光标（若能解决光标 sprite 不显示的问题）。

5. **底栏/顶栏**：先反汇编 `0x47047A` 的参数语义（5 个参数究竟哪个是 x/y/w/h/surface），再一处一处改，一次只改一个立即数并实机验证。

6. **内存占用**：把 4096 改成「`mapW` 向上取整到 512 的倍数」的动态尺寸，或做分块/懒分配，避免固定 64 MB。

## 五、现状与验证方法

- **显示层**：DDrawCompat 0.7.1，`FullscreenMode=exclusive(0)`、`LogLevel=info`。⚠️ `LogLevel=trace` 会让鼠标完全失效（逐调用同步写盘饿死输入轮询），禁用。
- **入口**：`D:\Program Files\PeG\进游戏-16比9-DDrawCompat试玩.cmd`（= `work\peg\diag_ddraw.py --play`）；应急 `还原显示层.cmd` / `python work\peg\diag_ddraw.py --restore`。用户直接关控制台会让 `finally` 不执行，层会停在 DDrawCompat。
- **补丁**：274 条 = 站点表/UI 记录/布局表（235）+ M 组 31 处（地图面 1920→4096）+ N 组 8 处（横向滚动钳位守卫）。B 组关闭。每条 `--dry-run` 可列全，`--selftest` 会在挂起进程里写入并回读比对，`--no-*` 可逐组关闭。
- **已解决**：地图全黑（负滚动 → 源矩形越界 → 整笔拒绝）；地图/单位/菜单已在 16:9 下正常显示；输入、GDI 文字、色键（品红）三项由显示层解决。
- **未解决**：①移动范围阴影的重绘（选中后不立即稳定显示）②鼠标拖影/黑块（含简报页超出 800×600 的永久残留）③坐标漂移与点选精度 ④底栏仍在画面中部 ⑤顶栏右侧留白。
- **验证纪律**：一次只改一类；改完先 `--dry-run` 与 `--selftest`；实机结论以用户截图与 `diag_watch.py`/DirectDraw 日志为准；任何「常量猜测」必须先确认语义。
