# docs\66 — PeG 运行期内存补丁启动器（原版 exe 零改动）

> 目标：把「16:9 + 高分辨率」从一个**被改过的 exe**，变成「**原版 exe + 启动器 + 参数**」。
> 动机来自用户提供的《突袭》MultiCAD 思路评估（`m02118`→`m02128`）：通用产物 + 配置选分辨率，
> 用户随后批准（`m02129` 逐字：「可以，按你的建议来。」）。
> 效力：**现行** —— 启动器为当前 16:9 实现路径（`work\peg\peg_launcher.py`，141 处站点）；后续治理方向见 `docs\67`（分层策略与运行时拦截）。

## 1. 一句话

`work\peg\peg_launcher.py` 用 `CreateProcess(CREATE_SUSPENDED)` 挂起启动原版 `PeG030.exe`，
在主线程执行任何指令之前，把我们已经确认的 **141 处**尺寸/描述符/重绘/UI 站点写进它的内存，
**逐项回读校验**通过后 `ResumeThread` 放行。磁盘上的 exe 一个字节都不改。

## 2. 实现机制（五步）

| 步 | 动作 | 关键点 |
|---|---|---|
| 1 | `CreateProcess(..., CREATE_SUSPENDED)` | 主线程挂在入口点，还未执行任何指令 |
| 2 | 读实际模块基址 | 走 WOW64 的 `NtQueryInformationProcess(ProcessBasicInformation)` → PEB → `ImageBaseAddress`；本机读回 `0x400000`，与母本写死基址一致（仍然按 delta 换算，不假设） |
| 3 | `VirtualProtectEx(PAGE_EXECUTE_READWRITE)` | 只解开要动的页 |
| 4 | **先读旧值 → 等于母本旧值才写** → 立即回读 | 任一不符 ⇒ **打印并中止，且不做任何写入**（本次自测就是这样抓到两个地址错误的） |
| 5 | 恢复页保护 → `ResumeThread` | 放行后游戏正常运行，Python 进程退出不影响它 |

## 3. 补丁站点清单（1920×1080 共 141 条）

| 来源 | 条数 | 说明 |
|---|---|---|
| 尺寸站点表 `out\res_diff_v4.tsv` | 96 | `va` = **立即数地址**；按 tag（`w`/`w-1`/`w-4`/`h`/`h-1`/`h-28`/`h-30`）重算；跳过 163 条 `dx`（由 UI 记录位移负责）；`idx14.y`/`idx14.bottom` 与尺寸表覆盖值一致，自动合并 |
| 代码侧 imm32 | 10 | 与 `patch_res_wh.py` 的 `CODE_EDITS` 完全一致（面板矩形、屏幕边框、视口裁剪组 ×3） |
| A 组 屏幕描述符 | 4 | `0x4421D4/0x4421DE/0x442219/0x442223` 是**指令 VA** ⇒ 写 **VA+6** 的立即数地址 `0x4421DA/0x4421E4/0x44221F/0x442229`（799→w-1、599→h-1） |
| B 组 强制重绘 | 1 | `0x4489D8` `74 1B` → `90 90`（`je` → nop，每帧都走整屏刷新 `0x44AC45`） |
| D 组 UI 记录位移 | 29+1 | `out\ui_layout_v9.tsv` 的 `dy` 记录按 `h−600` 重算；`0x45696D` 的 `mov word [0x4A42EC], 799` 的 imm16 在 **`0x456974`**（`66 c7 05 <abs32> <imm16>` 的前缀把 `c7 05` 的 2+4 顶到 +7） |

## 4. 用法

```
python work\peg\peg_launcher.py --w 1920 --h 1080 --dry-run    # 只打印方案，不启动
python work\peg\peg_launcher.py --w 1920 --h 1080 --selftest   # 挂起启动→打补丁→回读校验→杀掉
python work\peg\peg_launcher.py --w 1920 --h 1080              # 正常启动游戏（用户自己跑）
```

可选参数：`--exe <路径>`（默认母本 `D:\Program Files\PeG\PeG030.exe`）、`--cwd <目录>`（默认 = exe 所在目录）、
`--no-ui`、`--no-repaint`、`--no-canvas`（用于以后做 A/B 隔离）。

## 5.5 双击进游戏与排错（2026-10-14 修「点 .cmd 启动不了」）

* **症状**：用户双击 `启动-16比9-内存版.cmd` 没有任何效果（游戏没起来，PeG 目录里 `PEOPLES.INT` 等文件时间戳也没变 ⇒ 确实没走到启动那一步）。
* **根因（批处理本身）**：最初那个 `.cmd` 是用 UTF-8（无 BOM）＋**只有 LF** 写出来的。`cmd.exe` 解析批处理依赖 CRLF，
  LF-only 文件遇到跨行的 `if errorlevel 1 ( … )` 块会解析失败、窗口一闪而过（连 `pause` 都执行不到）。
* **修法**：`.cmd` 重写为 **cp936(GBK) 编码 + CRLF 换行 + 命令全 ASCII（中文只出现在 `echo` 文本里）**，
  显式 `chcp 936`，结尾**无条件 `pause`**（窗口永不一闪而过）。
* **加日志**：启动器新增 `--log`（默认 `work\peg\out\launcher-log.txt`，UTF-8 追加写入，每次带时间戳与命令行），
  控制台输出与控制台编码无关地留档 ⇒ 以后再出问题直接看这个文件即可。
* **再加一个双击目标**：`D:\Program Files\PeG\进游戏-16比9宽屏.lnk`（指向同一个 `.cmd`，图标取 `PeG030.exe`）。
  用它是为了绕开「`.cmd` 关联被改成用记事本打开或损坏」这类系统侧问题。
* **已验证的链路**（都用 `--selftest` 版临时副本，**没有真正启动游戏**）：`cmd /c <临时.cmd>` ✅、
  `Start-Process <临时.lnk>` ✅、日志文件 ✅。

## 5.6 E 组：悬停「小说明框」的品红面板（2026-10-14 加）

* **现象**：1920×1080 下把鼠标移到右侧工具列按钮上，屏上出现一条**品红带**（实测 y=120..179 高正好 60、x=800..1818 宽 1019，单一实心矩形），带内左侧仍有提示文字；鼠标横移会拖出一整条品红轨迹。同一份 exe 在 800×600 下没有品红（用户确认原版汉化版悬停会弹出小说明框且无品红）。
* **机制（只读逆向 + 实机像素实测）**：悬停说明框的面板是 `[0x62CE10]`——**300×60**，`CreateSurface` 在 `0x441E88`，`SetColorKey` 在 `0x441F02`（`push 8` = `DDCKEY_SRCBLT`，键值 `word[0x6769B0]` = 品红 0x7C1F(555)/0xF81F(565)）。绘制函数 `0x44CD3A`：`0x47DFA0(面板, 色键色)` 整面涂成品红 → `0x47170C` 画立体边框 → `0x47010B` 把文字画到**后台缓冲** `[0x676904]`（`0x470151 mov ecx,[0x676904]` → `GetDC`）→ 再用 `call 0x41EB70`（flags `0x1008000` = `DDBLT_WAIT|DDBLT_KEYSRC`）把面板抠图贴到后台缓冲。
* **为什么母本 800×600 没这毛病**：面板目标位置 `x = 800` 正好等于母本屏宽；`0x41EB70` 的裁剪分支 `0x41EBF8 cmp dword [ebp+8], 0x320`（`x ≥ 屏宽 ⇒ mov al,1; ret`）**命中并放弃这次位块** ⇒ **这两处面板位块在 800×600 下从不执行**。我们把判定常量补到 1920（`0x44C863/0x44C86A/0x44C880`，以及 `0x44C8AA/0x44C8B1/0x44C8C7` 的 600→1080）之后，这条位块开始执行，而它依赖显示层真正执行 `DDBLT_KEYSRC` 抠图，当前显示层（Svens 包装）在这条路径上没有抠掉 ⇒ 品红整块露出（宽 1019 = 鼠标横移时 300 宽面板的并集）。
  * 旁证：用户回忆**原版英文版**「所有文字都有一圈品红轮廓」，说明 Svens 包装对色键抠图本来就不完全可靠（汉化版做过处理）。
* **E 组补丁**：把这两处 `call 0x41EB70`（`0x44C929` = `e8 42 22 fd ff`、`0x44CD27` = `e8 44 1e fd ff`）各改成 5 个 `90`（nop）。这**等价于恢复母本 800×600 的行为**（母本里它们被裁掉）。
* **实测结论（重要，2026-10-14 更新）**：nop 掉面板位块之后，拖影消失，但**按钮说明文字也没了**，而且保存/恢复那套机制还在跑，会沿鼠标轨迹把旧内容反复盖回屏幕 ⇒ **E 组默认不打**（默认保留面板，才有说明文字与按钮反馈）。要复现 A/B 才加 `--no-tooltip`。

## 5.7 F 组：通用位块助手的裁剪算术（2026-10-14 修「画面破碎」）

* **症状**（用户 m02665 截图 + 像素实测）：鼠标在地图上扫过之后右侧出现大片撕裂——损坏区 **x=800..1918、y=580..821**，横向锯齿步长 ≈101 px、纵向周期 7 px，品红与地图绿色交替。
* **根因**：通用位块助手 `0x41EB70` 内部按「硬编码屏宽」裁剪请求矩形，它的**外层判定常量**早被我们的补丁改成新值（`0x41EBF2`/`0x41EBF9` = `0x780`、`0x41EC75`/`0x41EC7C`/`0x41ECA7` = `0x438`），但**真正的减法仍是旧基准**：
  * `0x41EC11`、`0x41EC2C` = `e0 fc ff ff`（−0x320 = −800）
  * `0x41EC94` = `a8 fd ff ff`（−0x258 = −600）
  于是任何 `x+w > 1920` 的矩形会执行 `w -= (x+w−800)` ——减数远大于宽度本身—— 宽度变成负数、右边界倒退到 800，位块把一大片内存斜着搬运；而 `x+w ∈ (800,1920]` 的矩形则被这道减法钳在 800，**右侧 x>800 的区域永远得不到重绘**，只剩脏数据 ⇒ 「画面破碎」。
* **F 组补丁**：`0x41EC11`/`0x41EC2C` → `80 f8 ff ff`（−1920）、`0x41EC94` → `c8 fb ff ff`（−1080）。裁剪边界与新屏宽一致后，`x+w>1920` 的矩形被正确裁到 1920，不再产生负宽度。
* 站点总数：**144 条**（96 尺寸 + 10 代码侧 + 4 A + 1 B + 30 D + 3 F），`--selftest` 已通过（144 条写入并回读一致、exe 未改动）。

## 5.9 I 组：`0x4A96E8` 布局表的右对齐记录（37 条 × 2 word）

「更多选项」这类弹出的面板，矩形不在代码里，而在一张 **272 条记录（stride 15 字节）的布局表** `0x4A96E8`。逆向报告 `work\peg\out\report-panel-table.md` + 机器可读清单 `panel_table_manifest.tsv`（272 行，含 role/dx 列）：

* **静态可打（关键证据）**：全 exe 对该表基址只有 **1 处写**（`0x45E4AE`，函数 `0x45E334`），而它的 idx 只可能是 **264/265/266**（`0x45E487`/`0x45E49D`/`0x45E495`），偏移 +2/+4/+6 的绝对引用也全在同一写入块 ⇒ **idx 0..263 的 `(x1,y1,x2,y2)` 运行期不会被任何代码触碰**。
* 运行期 x 偏移 `[0x4AF320]` 取值域只有 `{0,7,8}`（19 写 7 读），只是几像素状态抖动，不影响锚定。
* **本轮只打 37 条**：`role=RIGHT(+1120)` 且**宽度 ≤ 500**（右边缘的小元素：菜单、标签、提示框；含 idx97 `(345,23)-(778,585)`）。它们必须与已补的工具栏按钮**一起 +1120** 才对齐。宽度 > 500 的跨屏长条（idx2/7/9/112、idx203）不动；`MID(+560)` 93 条、`PANEL(+560)` 3 条也不动（它们与面板内部的按钮成组，单独移背景会把按钮从面板上拆下来）。
* 每条记录改 2 个 word：**`x1 @VA`、`x2 @VA+4`**（表布局：VA=x1、+2=y1、+4=x2、+6=y2）。
