## 1. 结论速览

1. 引擎**没有**「渲染分辨率」这个概念，它只有 **DirectDraw 表面尺寸** + 一堆写死的 800/600 立即数。我们把 SetDisplayMode 与各处尺寸立即数改成 1920×1080，等于真的把画布放大 —— 所以「一屏更多地图」成立。
2. **`[0x676904]` 不是主面**，它是 `GetAttachedSurface` 取回来的 **Flip 后备缓冲**；主面是 `[0x61F900]`。全 exe **只有一处 Flip**（`0x41FE4C`，在 `PresentFrame 0x41FE12` 里）。
3. 引擎本来就创建了两个 **1920×1920 的 SYSTEMMEM 离屏面**（`[0x655574]`、`[0x622A10]`，caps `0x840`）—— 地图平面本来就能装下 1920×1080 视口，**这是 16:9 能成功的物理前提**。
4. 唯一「整屏级且带色键」的离屏面是 **`[0x675538]`**（母本 800×600，我们已改成 1920×1080）。**品红 = 这一层的色键底色露出**，是最可疑的一处。
5. 我们之前漏改的一处是 **DrawTarget 裁剪框**（`0x676980` / `0x676960` 的 right/bottom 写死 799/599）。v10a/v10b 补上后黑区消失 ⇒ 与实测吻合。
6. 恢复链路 `RestoreAllSurfaces 0x456070` **依次 Restore 10 个面，任一失败立即中止** ⇒ 半恢复状态 ⇒ 大片黑/花屏，这是「某个显示层下地图完全不画」的强候选机制。

## 3. DirectDraw 管线：对象与初始化顺序

函数 `0x4416FF–0x44219E`（`sub esp, 0xF4`）：

| 顺序 | VA | 动作 |
|---|---|---|
| 1 | `0x441753` | `LoadCursorA` |
| 2 | `0x441785` | `RegisterClassA` |
| 3 | `0x4417B7` | `CreateWindowExA`（**1600×900 以外**：`0x441796`=600、`0x44179B`=800；句柄存 `[0x676134]`） |
| 4 | | `ShowWindow` / `UpdateWindow` |
| 5 | `0x4419BC` | **`DirectDrawCreate`**（全 exe 唯一；thunk `0x47E690` → `jmp [0x6AA3CC]`）→ `[0x6768FC]` |
| 6 | `0x441A02` | `SetCooperativeLevel(hwnd, 0x11)`（`DDSCL_FULLSCREEN|DDSCL_EXCLUSIVE`） |
| 7 | `0x441A47` | `QueryInterface(riid=0x48C040)` → `[0x6761E0]`（**之后 SetDisplayMode / CreateSurface 全用它**） |
| 8 | `0x441A91` | `SetDisplayMode(800, 600, 16, 0, 0)`（立即数 `0x441A79`=600、`0x441A7E`=800） |
| 9 | `0x441B03…0x441FD3` | **9 次 `CreateSurface`** + 1 次 `GetAttachedSurface` |
| 10 | `0x441E07 / 0x441F02 / 0x441F9B / 0x442034` | 4 次 `SetColorKey` |
| 11 | `0x442037` | `memset(0x675720, 0xFF, 0x14)` |
| 12 | `0x44212E` | `Blt(..., DDBLT_COLORFILL)` 清屏（`0x47DFA0`） |

要点：**全 exe 没有 `SetClipper`、没有 `SetPalette`**（`vtcalls 0x70` 零命中）⇒ Blt 只受「目标表面边界 + 代码里的裁剪矩形」约束，没有 clipper 可依赖。

> 名词纠正：任务书里的「第二个 IDirectDraw `[0x4AF26C]`」是**判断错误**。`[0x4AF26C]` 的调用全落在 surface 专有槽位（`+0x18` BltBatch、`+0x50` GetPalette、`+0x58` GetSurfaceDesc、`+0x60` IsLost、`+0x64` Lock、`+0x74` SetColorKey），它是 **IDirectDrawSurface**，由 `0x41BB00–0x41C200` 模块管理（守卫 `[0x4AF268]`），其创建点未证实。

## 4. Surface 表（母本值 / 我们的产物值）

所有描述符都是 `DDSURFACEDESC2`（`dwSize=0x7C`，先 `memset` 归零 `0x47F190`）。

| 全局 | 创建点 | 母本尺寸 | flags / caps | 色键 | 角色 |
|---|---|---|---|---|---|
| `[0x61F900]` | `0x441B03` | 800×600 | `0x21` / `0x218` PRIMARY\|FLIP\|COMPLEX，`dwBackBufferCount=1` | 无 | **主面**（Flip 用） |
| `[0x676904]` | `0x441B53` `GetAttachedSurface(caps=4)` | 同主面 | 后备 | 无 | **Flip 后备缓冲**（不是独立主面） |
| `[0x655574]` | `0x441C22` | **1920×1920** | `7` / `0x840` SYSTEMMEM\|OFFSCREEN | 无 | 地图平面 A（母本原样，我们未改） |
| `[0x622A10]` | `0x441CB4` | **1920×1920** | `7` / `0x840` | 无 | 地图平面 B |
| `[0x686528]` | `0x441D44` | 90×70 | `7` / `0x40` | 无 | 80×60 局部存档面 |
| `[0x6633FC]` | `0x441DA6` | 90×70 | `7` / `0x40` | `0x441E07` | 同族 |
| `[0x61F3E0]` | `0x441E3F` | 300×60 | `7` / `0x40` | 无 | 面板/条 |
| `[0x62CE10]` | `0x441EA1` | 300×60 | `7` / `0x40` | `0x441F02` | 面板/条（带键） |
| `[0x681D0C]` | `0x441F3A` | 420×200 | `7` / `0x40` | `0x441F9B` | 对话框/提示（带键） |
| `[0x675538]` | `0x441FD3` | **800×600**（描述符立即数 `0x441FAF`/`0x441FB6`，**我们已改成 1920×1080**） | `7` / `0x40` | `0x442034` | **整屏离屏画布（带色键）** |

**色键统一约定**：`flags=8`（`DDCKEY_SRCBLT`），键值取 `word[0x6769B0]`；`0x441BA1–0x441BCC` 按主面 `GetPixelFormat` 的 `dwRGBBitCount` 二选一 —— `0x3E0`(992) 时用 `0x7C1F` 并把 `[0x62666C]=1`，否则用 `0xF81F` 并把 `[0x62666C]=0`。
（品红实测 RGB(240,0,240) ≈ 16bpp `0xF01E`/`0xF81F` 族 ⇒ 与这里同一个色域。）

## 5. 一帧怎么上屏 / 丢失与恢复

```
PresentFrame 0x41FE12
  → call 0x44C66E        帧合成：把后备缓冲 [0x676904] 的 80×60 块 Blt 到存档面 [0x686528]，clamp 后回填
                         （恢复路径在 0x44C5F0，同参数反向 Blt 回 [0x676904]）
  → Flip([0x61F900], NULL, DDFLIP_WAIT)   @0x41FE4C  ← 全 exe 唯一 Flip
      成功 → 翻转双缓冲索引 [0x4AF32C] + call 0x423473 切绘制目标
      失败 → 0x887601C2 DDERR_SURFACELOST   → call 0x456070 RestoreAllSurfaces
             0x8876021C DDERR_WASSTILLDRAWING → jmp 0x41FE2E 重试
```

**`RestoreAllSurfaces 0x456070`**：依次 Restore 10 个面 —— `[0x61F900] 0x456084`、`[0x655574] 0x4560A6`、`[0x686528] 0x4560C8`、`[0x6633FC] 0x4560EA`、`[0x622A10] 0x45610C`、`[0x686528] 0x45612E`（重复）、`[0x62CE10] 0x456150`、`[0x61F3E0] 0x456172`、`[0x681D0C] 0x456194`、`[0x675538] 0x4561B6`；**任一失败立刻返回 HRESULT 并中止后续恢复**。全部成功后置 `[0x498D38]/[0x498D34]/[0x498D3A]/[0x498D36]/[0x498D70] = 0xFFFF` 并 `call 0x41F0D6`（**引擎自带的「全屏重绘」入口**）。
`IsLost`（`+0x60`）全 exe 只有 2 处，都在 `[0x4AF26C]`（`0x41BD4E`/`0x41BFE3`）：主链 Flip **不先探 IsLost**。

## 7. 症状机制归因

| 症状 | 机制 | 证据强度 |
|---|---|---|
| 16:9 基线右/下大片黑区 | DrawTarget 裁剪框仍 799/599 ⇒ 超出 800×600 的绘制被裁掉 | **已证实**（v10a/v10b 改后黑区消失，实测截图） |
| 底栏不显示（y≥1056） | 底栏绘制只在 `0x44AC45`（顶栏+底栏+控件循环）里，受 `word[0x498d74]` 脏标志驱动；该标志未置位就不重绘 | **已证实**（v10 B 组强制每帧走 `0x44AC45` 后底栏出现） |
| 品红（说明框/拖影/y≈600 横带） | **显示层未实现 Blt/BltFast 的 `DDCKEY_SRCBLT`**：引擎的浮动面（提示框 `[0x681D0C]`/`[0x62CE10]`、光标面 `[0x6633FC]`、整屏画布 `[0x675538]`）以品红为透明键（键值取自 `[0x6769B0]`，565=0xF81F / 555=0x7C1F；SetColorKey 调用点 0x441E07/0x441EF1/0x441F8A/0x442034），Svens Wrapper 不做抠图 ⇒ 键色原样上屏（截图实测 RGB(240,0,240)） | **已证实**（同一 exe：Svens 有品红 / cnc-ddraw 无 / 键色与截图一致） |
| 地图完全不画（无包装） | `0x41EB33 call 0x41FF8A` 每帧把 1920×1080 的视口窗口（x=`[0x4af2f8]`, y=`[0x4af2fc]`）从常驻地图面 `[0x655574]`（1920×1920 SYSTEMMEM）BltFast 到后备缓冲；一旦滚动，源矩形 (x,y,x+1920,y+1032) 就**越出该面**，原生 DirectDraw **整笔拒绝**（代码只记日志 @0x42000B，不回退） | **机制已定**（夹取 vs 拒绝的行为差异；实机未二次验证） |
| cnc-ddraw 黑色空洞（斑块 + y≈595 横带） | ①**增量重绘**：只重画「变化过的」区域，新暴露区域从未初始化（v10 B 组强制每帧走 `0x44AC45` 后大面积黑消失）②视口源矩形越界被显示层**夹取**，缺的部分是未初始化内存（拖动地图改变 x ⇒ 夹取范围变 ⇒ 「黑区自动补上地形」） | **主因已实测**（v10b/v10c/v10d 对照） |

## 8. 下一步的单点修改候选（按性价比排序，等地图合成报告定稿）

1. **强制「引擎自带全屏重绘」**：`0x41F0D6` 是引擎自己用的整屏重绘入口（`RestoreAllSurfaces` 成功后调用）。若能在地图首次绘制/视口变化时走到它（或让它依赖的 `[0x498D38]/[0x498D34]/[0x498D3A]/[0x498D36]/[0x498D70] = 0xFFFF` 在开局被置位），黑空洞应当消失。**风险低、改动小**，是最符合「机制驱动」的一处。
2. **色键一致性**：核对 `[0x675538]` 画布的**填充色**与**色键值**是否同一来源（`word[0x6769B0]`）。若填充用的是另一个常量，品红就有了代码级解释，且可以单点修好（改填充常量或改键值）。
3. **恢复链的中止语义**：`0x456070` 任一失败即中止 —— 可考虑让它失败也继续尝试其余面（把「失败即 return」改成「记录并继续」），这是「某显示层下地图全黑」的兜底修法。
4. 显示层选择：见 §10 —— 已按引擎实际用到的三项 DirectDraw 语义选定 **DDrawCompat v0.7.1** 作为下一步的单点验证（详见 §10 的对照副本）。

## 10. 显示层能力矩阵与 DDrawCompat 决策（本轮的机制结论）

| 显示层 | DDCKEY_SRCBLT 抠图 | 源矩形越界 → 夹取 | 16bpp 面 GetDC/GDI 文字 | 实机表现 |
|---|---|---|---|---|
| Svens Wrapper（游戏自带，159,232 B） | ✗ | ✗（拒绝） | ✓ | 地图可画、**品红抠底失效**、黑区 |
| cnc-ddraw 7.1.0.0（411,648 B） | ✓ | ✓ | ✗（文字不显示） | 黑空洞明显、无品红、悬停无文字 |
| 原生 DirectDraw（无 ddraw.dll） | — | ✗ | — | **地图完全不画** |
| **DDrawCompat v0.7.1（3,612,672 B）** | ✓ | ✓（`SurfacePatches` 给面内存加安全垫） | ✓ | **待实机验证** |

引擎对 DirectDraw 的三项依赖（均有静态证据）：①浮动面的透明键（`SetColorKey` 6 处，vtable 槽 +0x74，键值 `[0x6769B0]`）；②视口 BltFast 的源矩形必然越界（地图面 1920×1920 vs 视口 1920×1080，滚动后越界）；③提示框文字走 GDI（16bpp 面的 DC 路径）。
