# 60 · PeG 原生 16:9 宽屏构建（参数化尺寸补丁）与剩余问题

日期：2026-10-14　　（承接 `docs\58` §九–§十二 的三路线决策，与 `docs\59` 的换引擎评估）

## 一、目标收敛（用户 m01250 定调）

用户原话：

> 这么搞没啥意义啊。。。。我扩大适配的分辨率，就是想看更多地图啊，而且能宽屏看地图，让游戏支持16：9的画面是最好的。

⇒ **正解＝引擎原生 16:9（横向视口变宽→一屏更多地图）**；
⇒ **显示层缩放（cnc-ddraw / dgVoodoo2 / Magpie 那一类）不是正解** —— 它把 800×600 放大铺满，地形永远只有原来那么多；
⇒ 换引擎（OpenGen＋EFILE_OPENPEG，见 `docs\59`）仍是备选，但成本 6–10 人日且不是原版引擎手感，暂缓。

## 二、为什么「更多地图」对 PeG 是可行的（回顾）

PeG 的地图是**可滚动的大位图**，视口矩形、裁剪矩形、控件记录都由 800×600 这些数字算出来（`docs\54`/`docs\55` 已定位 259 个相关站点）。
把 `w-1`/`w-4`/`h-1`/`h-28`/`h-30` 这类「尺寸类」站点按新分辨率重算，视口就变大 ⇒ **看到更多地形**（v4/v5a/b/c/d 四版实机都已证明「地图铺满 ~1016」成立）。

真正难的是**界面重排**（工具列/底栏要挪到新边缘），它与「更多地图」**互相独立**：地图能不能变宽，不取决于界面搬不搬得动。

## 三、新的参数化构建器 `work\peg\patch_res_wh.py`

旧的 `patch_resolution.py` 把 1024×768 的值**写死**在站点表里，无法改成别的分辨率；新脚本把语义重新算一遍：

```
python patch_res_wh.py --w 1920 --h 1080 --out out\PeG030-1920x1080.exe          # 干跑
python patch_res_wh.py --w 1920 --h 1080 --out out\PeG030-1920x1080.exe --apply  # 落盘
```

- 站点来源：`work\peg\out\res_diff_v4.tsv`（S1 由「母本 ↔ v4 产物」逐字节 diff 反推的 259 条真实改动点，含 `section/va/file_off/width/old/tag/note`）。
- 语义重算：`w/w-1/w-4` → 新宽；`h/h-1/h-28/h-30` → 新高；`dx/dy` → **旧值 + (新宽−800) / (新高−600)**。
- **默认跳过全部 163 条 `dx`（控件记录横向位移）**＝沿用 **v5c 配方**；加 `--keep-dx` 才是 v4 配方（已知会把工具列拉成横向拉伸带）。
- 代码侧 10 处（imm32 地址，非指令地址）：`0x41C4D7`(h−28) `0x41C4DE`(w−1) `0x44C5CD`(h−30) `0x44C5D2`(w−4) `0x44C731`/`0x44C86A`/`0x44CC68`(w) `0x44C778`/`0x44C8B1`/`0x44CCAF`(h)。
- 纪律：母本 md5 断言（`c462e897b3aa1c384870c857ce9e01df`）→ 逐站点「当前值必须等于记录旧值」断言 → 改内存 → 回读校验 → 写临时文件 → 读回校验 → `os.replace` → 中文补丁三处复核（charset `0x070CE3`、`__mbcodepage` `0x0A948C`、LCID `0x07BE86`）。

## 五、已知局限（交付时必须讲清）

1. **界面仍在 800×600 的老坐标上**：工具列画在内容 x 762..787、底栏仍在旧 y。地图宽了，但 UI 没有跟着挪到新的右缘/下缘 ⇒ 1920×1080 下工具列会停在大约屏幕中间偏右。
2. **原因**：能挪动工具列的记录（`0x4A22F8` 组6 的 13 条）一旦 `x +1120`，绘制链里的 `dx = 751 − rec.x` 变成极大的负数，`0x47E0A0`/`0x47E4E0` 的裁剪算法就把 26 px 按钮画成一条 `800..9xx` 的横向拉伸带（v4/v7a/v8a/v8b 四轮实测；`docs\58` §九/§十）。
3. **v8 结论**：`751` 不是位置锚点，而是源图/裁剪坐标系里的量；`mov edx,0x2ef`（2 处）与 `push 0x2ef`（3 处）语义相反（v8a 把拉伸从 186 px 缩到 95 px，v8b 又还原）。**要把 UI 真正摆正，必须把 `0x47E4E0`/`0x47E050` 的裁剪算术读透**（或在运行期 hook 掉它）。

## 六、判读清单（用户跑完看什么）

1. **画面是否真的变成 1920×1080 / 1600×900**（进游戏后的地形细节多少、是否需要滚动更多次才能看到地图边缘）。
2. **地图是否铺满整屏**（右侧是否出现大片未绘制黑区或彩条 —— v7b/v7c 那种「改成别的组」会黑）。
3. **是否有未初始化花屏**（注意 v4 起就一直存在的 800..985 拉伸带是否出现）。
4. **点击是否对得上**（工具列按钮的命中区 vs 画出来的位置；地图拖拽/选单位是否正常）。
5. **稳定性**：能否进战役、能否存档读档（大分辨率 = 更大的后备缓冲与地图表面，先确认不崩）。
6. 哪一版手感好（1920×1080 更清晰，1600×900 下 UI 相对更靠边）。
