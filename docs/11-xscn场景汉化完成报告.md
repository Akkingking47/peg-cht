## 四、⚠️ 本轮三个坑（都已修复，务必记住）

### 坑 1：`Object[]` 交给 `BinaryWriter.Write()` 会**静默只写 1 个字节**
```powershell
$tb = if ($c) { [byte[]]$a } else { [byte[]]$b }   # ← 错！if 表达式把数组重新包成 Object[]
$bw.Write($tb)                                     # ← 于是只写入 1 字节
```
- PowerShell 的 **if 表达式会对数组做枚举/重打包**，`[byte[]]` 的强转在表达式求值后失效
- `BinaryWriter.Write(Object[])` **不报错**，只写 1 字节 —— 文件从此错位
- **正解**：① 用 **if/else 语句**分别赋值，不用 if 表达式；② **每个 `Write()` 都显式 `[byte[]]` 强转**
- 本项目已被这个坑伤过两次（`.xscn` 前缀被截断、标题只写 1 字节）

### 坑 2：脚本里出现中文 ⇒ 无 BOM 时 PS 5.1 按 GBK 误读
- `xscn-patch.ps1` 原本「纯 ASCII」但**参数默认值里写了中文备份路径** ⇒ 路径变乱码 ⇒
  **备份写进了乱码目录，真正该备份的地方是空的**（断言还查不出来，因为 `Test-Path` 查的也是乱码路径）
- **正解**：**脚本彻底纯 ASCII，中文路径一律作为必填参数从命令行传入**（命令行参数的中文不会被误读）
  —— 这比「补 BOM」更稳，因为它不依赖任何人记得存 BOM

### 坑 3：写完再回读太晚
- 第一版是「写盘 → 回读校验」，结果校验失败时**文件已经被写坏了**
- **正解**：**先重建到临时文件 → 在临时文件上回读校验（条目数 + 标题一致）→ 通过了才写正式文件**
  （`xscn-patch.ps1` 已内置此 preflight）
