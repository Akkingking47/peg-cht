# 23 · 原文侧「乱码」诊断与修复报告

> 触发：用户提问「有乱码的原文看看是不是因为德文编码，如果是，看看能不能反推词句是什么，从而进行汉化。」
> 结论：**是德文（及法/西/意/匈/葡等）的变音符，但文件编码没坏** —— 乱码源于**两类编码混用**。
> 本轮**未启动游戏**；exe md5 保持 `2f4a4ba783d9c0cfd708475677c92ad2`。

---

## 一、根因：不是「编码坏了」，是「两类编码混用」

原文侧文件（`<efile>\equip.txt` / `names.txt` / `nations.txt` / `SCENARIO\*.txt`）**应为 cp1252 单字节**。

实测（未汉化 efile 根级）：

| 文件 | 特征 | 判定 |
|---|---|---|
| `EFILE_KAISER\equip.txt` | `hi=0.006`、GBK 失败、UTF-8 失败 | **纯 cp1252** ✅ 正常 |
| `EFILE_ATOMIC\equip.txt` | `hi=0.002`、GBK 失败、UTF-8 失败 | 纯 cp1252 |
| `EFILE_SON\equip.txt` | `hi=0.014`、GBK 失败、UTF-8 失败 | 纯 cp1252 |
| `EFILE_ROI\names.txt` | `hi=0.013`、GBK 可解、**UTF-8 可解** | **cp1252 + UTF-8 混合** ⚠️ |

**由此得两类乱码**：

| 类 | 机制 | 显示样子 | 真值 | 游戏内是否乱码 |
|---|---|---|---|---|
| **A** | 少数条目被写成 **UTF-8**，引擎按单字节读 | `BarrÃ³n` | `Barrón` | **是** → 需修 |
| **B** | 原文是 **cp1252**，被 **GBK** 解码（中文编辑器/工具打开时） | `L間ion Etrang鑢e` | `Légion Etrangère` | **否**（引擎按 latin-1 读正常） |

> **关键判据**：cp1252 文件 `GBK解码失败`；UTF-8 文件 `GBK可解` 且解出的高位字符是 `Ã`/`Â`/`Å`。
> GBK 把 `0xE9 0x67` 当**一个汉字** `間`，于是 `Légion` → `L間ion` —— 这是「假汉字」，**不是文件坏了**。

## 四、刻意不动（附理由）

`EFILE_OPENPG\strings_efile.txt`（70 行）、`EFILE_OLGWW2\strings_efile.txt`（66 行）**被历史写成中文**（违反「不动原文」）。

## 六、方法论沉淀（已写入技能库）

**判别原文侧编码**（三行判据）：

```python
hi = sum(1 for b in data if b >= 0x80)
如果是 UTF-8：data.decode('utf-8') 成功 且 结果里没有 Ã/Â/Å/Æ
如果是 cp1252：data.decode('gbk') 失败（中文系统下"假汉字"的源头）
二者都能解 ⇒ 混合文件，必须逐行判
```

**反推**：cp1252 解码（B 类）或 UTF-8 解码（A 类）即得真值；再 `NFKD` 折写成 ASCII 供中文侧使用。

**中文侧装不下西文变音符**：GBK 编码 `Légion` 会抛 `UnicodeEncodeError` ⇒ 写入中文侧前**必须折写或翻译**（本轮 `Fallschirmjäger` → 「伞兵」、`Léopard` → `Leopard`、`Zsadányi-Nagy` → `Zsadanyi-Nagy`）。
