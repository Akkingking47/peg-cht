# 72 · PeG030.exe 坐标与画面呈现普查（只读静态反汇编）

- 对象：`D:\Program Files\PeG\PeG030.exe`（734,720 字节 = 0xB3600，md5 c462e897b3aa1c384870c857ce9e01df）
- 性质：**纯只读静态普查**。未修改目标文件、未启动游戏、未写任何进程内存。
- 换算：文件偏移 → VA = `offset - 0x400 + 0x401000`（.text）。

## 0. 节表与「磁盘上根本没有」的地址（一切结论的前提）

由 `work\_scratch\peg\_secs.py` 解析 PE 头得到权威节表：

| 节 | VA | VSize | FO | RAWSize |
|---|---|---|---|---|
| .text | 0x401000 | 0x8A136 | 0x400 | 0x8A200 |
| .rdata | 0x48C000 | 0x1017 | 0x8A600 | 0x1200 |
| .data | 0x48E000 | 0x21BF3C | 0x8B800 | 0x21400 |
| .idata | 0x6AA000 | 0x1434 | 0xACC00 | 0x1600 |
| .rsrc | 0x6AC000 | 0x52DC | 0xAE200 | 0x5400 |

**关键推论**：.data 在磁盘上只有 0x21400 字节，即真实数据止于 VA `0x48E000 + 0x21400 = 0x4AF400`。**VA ≥ 0x4AF400 全部是 BSS（运行时零填充，磁盘上读出来全是 0）**。

因此下列地址**在磁盘上不存在初值**，其结构只能靠代码引用（IMM/DISP）反推，本次报告对它们一律标注「BSS，初值未证实」：

`0x4AF45C`、`0x4AF460`、`0x498D74`、`0x498D78`、`0x4CCE2C`、`0x4CCE40`、`0x53D640`、`0x5ADE40`、`0x622D4A`、`0x6268A0`、`0x65AA00`、`0x67E83A`、`0x7C…`。

判据：`0x4A0200`（有初值）→ 0x4AF3FF；`0x4AF45C`（无初值）→ BSS。本次实测 `python work\_scratch\peg\_w.py 0x4A0200 --bytes 48` 有数据、`0x4AF45C` 报「不在任何节内」。

> 工具链教训（本次踩过）：capstone 的 `md.disasm(blob, va)` 遇到第一个非法字节会**静默停止**。必须用「每次只喂 ≤16 字节、失败则 off+=1」的稳健循环，否则 .text 只能解出 ~30,803 条而不是 168,881 条。

## 2. 布局数据表

### 2.1 六角格参数表 @ 0x4A0200（有磁盘初值）

- 基址 `0x4A0200`（在 .data 盘上，真实存在），**步长 0x18 = 24 字节**。
- 实测字节：`0F 00 2C 00 2C 00 3B 18 3B 19 2C 31 2C 31 0F 31 0F 31 00 19 00 18`，随即在 `0x4A0218` 原样重复一次（表至少 2 项，本次只证实前 2 项）。
- 字段（由换算器 0x43D5AE/0x43D5F2 的取用方式反推）：

| 偏移 | 类型 | 值（第 0 项 / 第 1 项 @0x4A0218） | 含义 |
|---|---|---|---|
| +0x00 | u8 | 0x0F=15 | 其他参数 |
| +0x02 | u8 | 0x2C=44 / 0x2C=44 | **格高 − 1**（⇒ 45 px） |
| +0x06 | u8 | 0x2C=44 / 0x2C=44 | **行高 − 1**（⇒ 45 px） |
| +0x0B | u8 | 0x2C=44 / 0x2C=44 | **列宽 − 1**（⇒ 45 px） |

- 项选择器：`word [0x4AF45C]`（**BSS，初值 0**）。全 exe 中 0x4AF45C 共 **44 处引用，全部是 `movsx … , word ptr [0x4af45c]` 读取，没有任何写入**（已用 `_refs2.py 0x4AF45C` 全列验证）。⇒ 运行时它保持 0，即**永远取第 0 项**。
- 引用者分布：0x43CE6E…0x43D63C（换算/几何族，40 处）、0x43DA48 / 0x43DA76（逐格写入器内）、0x43F86D / 0x43F89B / 0x43FCFF / 0x43FD2D。
- **0x4A0202 字段**：9 处引用 —— 0x43CE78、0x43CF7D、0x43CFC5、0x43D182、0x43D287、0x43D2CF、**0x43D5CB（行→y 换算器）**、0x43F96B。
- **0x4A0206 字段**：8 处引用 —— 0x43CF94、0x43CFDC、0x43D29E、0x43D2E6、**0x43D5E2**、**0x43DA52（逐格写入器写 y 处）**、**0x43F877**、0x43FD09。
- **0x4A020B 字段**：29 处引用 —— 0x43CEB3…0x43D00E（22 处）、0x43D625 / 0x43D643（**列→x 换算器**）、0x43DA76（逐格写入器写 x 处）等。
- 0x4A0200..0x4A0203 还被 `movsx eax, byte ptr [edx*4 + 0x4A0200]`（0x43F96B、0x43F99B、0x43FE0A、0x43FE1D、0x43FE30）以 **步长 4** 索引 —— 这是**六角格顶点偏移表**（见 2.2）。

### 2.2 六角格顶点偏移表 @ 0x4A0200（步长 4 视图）/ 0x4A0238 角点表

- `movsx eax, byte ptr [edx*4 + 0x4A0200]` 出现在 **0x43F99B** 与 **0x43FE30**（六角描边绘制器 0x43FCB2 尾段）。
- 描边绘制器在 0x43FE0A…0x43FE3B 连续四次取 `byte[edx*4 + 0x4A0202]`（y 加数）、`byte[edx*4 + 0x4A0201]`（x 加数）、`byte[edx*4 + 0x4A0200]`，配合 `[ebp-4]` = 顶点号（0..3），算出四个角点后：
  ```
  0x43FE3B  mov ecx,[0x655574]      ; 地图面
  0x43FE42  call 0x425817            ; 画线/画点
  ```
  ⇒ **0x4A0200 起同时充当「按步长 4 索引的 4 顶点×4 分量」的小表**，与 2.1 的 24 字节项视图是同一块数据的两种解读方式（第 0 项 24 字节 = 6 组 4 字节）。
- 另有 `0x4A0238` / `0x4A023A` 被 `0x43DB16 movsx eax,[edx*4+0x4A0238]`、`0x43DB4D movsx ecx,[ecx*4+0x4A023A]` 索引，用于逐格写入器的 50 次循环取角点 —— 即**格边/圆角偏移表**。
- `0x4A0230` 处是一个**函数指针 `0x43F68F`**，指向「清空三层 1bpp 缓冲」的函数（0x43F64E 附近）；该 dword 也会被 `0x43F647 mov [0x4A0230], eax` 改写 ⇒ 该槽位是**可替换的绘制回调**。
- `0x4A0300` / `0x4A030C` 由 `push 0x4A0300` / `push 0x4A030C`（0x43FD8B / 0x43FDAF）传给 `0x4383FD`，用作取角点偏移的基址。

### 2.3 界面右列按钮矩形表 @ 0x490470（有磁盘初值）—— 任务书偏移的订正

**记录步长 = 0x24 = 36 字节**（与 `docs\55` / `docs\56` 记载的 `imul eax,eax,0x24` 一致），第一条记录基址 = `0x490486`，第二条 = `0x4904AA`：

### 2.6 地图格表 @ 0x6268A0（BSS，**两层，各 65 字节/格**）

- 基址 `0x6268A0`，**步长 0x41 = 65 字节**。

```
0x410EDB  movsx edx, word[ebp-8]           ; 列
0x410EDF  imul  edx, edx, 0x1964            ; 45 × 65 × ... 见下
0x410EE5  movsx eax, word[ebp-4]            ; 行
0x410EE9  imul  eax, eax, 0x41              ; ×65
0x410EEE  mov   cl, byte[edx+eax+0x6268A1]  ; 层 2

### 3.2 六角格 → 屏幕坐标换算器（反汇编原文核实）

**0x43D5AE–0x43D5F1（19 条）**：参数 = 行索引 n，返回该行格心的像素 y。

```
push ebp / mov ebp,esp / mov ax,[ebp+8] / sub ax,1 / mov [ebp+8],ax
movsx eax,[ebp+8]
movsx ecx,word[0x4AF45C] / imul ecx,ecx,0x18
movsx edx,byte[ecx+0x4A0202] / add edx,1 / imul eax,edx      ; (n-1)*(格高)
movsx ecx,word[0x4AF45C] / imul ecx,ecx,0x18
movsx edx,byte[ecx+0x4A0206] / add edx,1 / sar edx,1 / add eax,edx
pop ebp / ret
```

**0x43D5F2–0x43D65C（34 条）**：参数 = (列 m, 行 n)，返回像素 x。

```
mov ax,[ebp+8] / sub ax,1                       ; 列-1
movsx eax,[ebp+8] / cdq / xor eax,edx / sub eax,edx / and eax,1 / xor eax,edx / sub eax,edx
test eax,eax / je 0x43D61E                      ; (m-1) 的奇偶
  偶数: movsx ecx,[0x4AF45C] / imul ecx,0x18 / movsx edx,byte[ecx+0x4A020B] / add edx,1 / sar edx,1 / mov [ebp-4],dx
  奇数: [ebp-4] = 0
movsx eax,[ebp+0xC]                             ; 行
movsx ecx,[0x4AF45C] / imul ecx,0x18
movsx edx,byte[ecx+0x4A020B] / add edx,1 / imul eax,edx

### 3.3 逐格像素写入器 0x43D67F（本次核心解剖）

**函数 0x43D67F–0x43EA8B**（入口 `push ebp` @0x43D67F，`mov ebp,esp` @0x43D680，结束 `jmp 0x43EA8B`）。
参数：**arg1 = 列 col（byte [ebp+8]）、arg2 = 行 row（byte [ebp+0xC]）、arg3 = 模式（dword [ebp+0x10]，只用低 8 位）**。

1. **范围剔除**（0x43D68A–0x43D6BC）：`col ≥ [0x622D42]` 或 `row ≥ [0x622D44]` 即 `jmp 0x43EA8B` 返回。
2. **锁定地图面**（0x43D6C1–0x43D6F0）：`push 0 / push 1 / lea eax,[ebp-0x7C] / push eax / push 0 / mov ecx,[0x655574] / push ecx / … call [eax+0x64]` —— 对地图面 A `[0x655574]` 调 IDirectDrawSurface 接口 +0x64（Lock）。锁返回指针存 `[ebp-0x90]`。
3. **取格心**（0x43D6F6–0x43D71F）：
   - `0x43D6F6 mov dx,[ebp+8] / push edx / call 0x43D5AE` → `word [ebp-0x80]`
   - `0x43D707 mov ax,[ebp+0xC] / push eax / mov cx,[ebp+8] / push ecx / call 0x43D5F2` → `word [ebp-0x84]`
4. **1920 屏幕剔除**（0x43D720–0x43D74D）：`[ebp-0x84] < 0` 或 `≥ 0x780`，或 `[ebp-0x80] < 0` 或 `≥ 0x780` → `jmp 0x43EA75`（解锁后返回）。**1920 宽屏语义硬编码进逐格绘制就在这里。**
5. **模式分流 1**（0x43D752）：`arg3 & 0xFF == 1` → 分支一（双层循环 x∈[x0-2,x0+2)、y∈[y0-2,y0+2)，**三层位全 0 才绘制** = 「地形底层」）；否则 → 分支二（同样循环，**非三层全 1 才绘制** = 「覆盖层」）。
6. 两分支汇入 **0x43DA38**：重算格心并各减去 `(byte[+6]+1)/2`、`(byte[+0xB]+1)/2` ⇒ 得到**格子左上角**。
7. `0x43DA92 cmp dword[0x62666C],0 / je 0x43E28C` —— **全局开关 [0x62666C]**（BSS）决定是否走 1bpp 展开路径。
8. **模式分流 2**（0x43DA9F）：`arg3 & 0xFF == 1` → 0x43DBxx 段；否则 → 0x43DE74 段。
   - 底层分支：循环 **i < 0x32（50）**，每步 `[ebp-0x84] += 1`；
     `0x43DB81 imul ecx,ecx,0x780` → `mov edx,[ebp-0x90]`（面基址）→ `lea eax,[edx+ecx*2]` → `lea edx,[eax+ecx*2]` ⇒ **`[ebp-0x8C] = 面基址 + y×1920×2 + x×2`，即 16bpp 像素地址**。
   - 覆盖层分支：对应 0x43DE74 起的对称实现，含 `0x43DF46`、`0x43E36F`、`0x43E734` 三处 `imul …,0x780` 与六处 `cmp …,0x780`。
9. **三层 1bpp 掩码缓冲**（本次最关键的架构发现）：以 `imul r,r,0xF0`（**240 字节/行 = 1920/8**）为行步长，以 `(x&7)` 做位选择（`mov eax,0x80 / sar eax,cl`）、`x/8` 为字节偏移，访问三块：

   | 层 | 基址 | 站点 |
   |---|---|---|
   | A | **0x5ADE40** | 0x43D7F8 等（`mov dl,byte[ecx+eax+0x5ADE40]`） |
   | B | **0x4CCE40** | 0x43D890、0x43D9FC、0x43DD95、0x43DE38/0x43DE5E、0x43E190、0x43E250/0x43E276、0x43E583、0x43E626/0x43E64C、0x43E97E、0x43EA3E/0x43EA64 |
   | C | **0x53D640** | 0x43D846、0x43D9B2 等 |

   位清除：`not eax` + `and cl,al` 后写回（0x43DE38/0x43DE5E 为层 B）。位设置：对称路径（层 C 0x43DD49/0x43DD6F、0x43E144/0x43E16A、0x43E537/0x43E55D、0x43E932/0x43E958；层 B 0x43DCxx、0x43E250/0x43E276、0x43E626/0x43E64C、0x43EA3E/0x43EA64）。
   ⇒ **层 B/C 的位 = 「本格已绘制了某类覆盖物」的标记**；层 A = 另一类。

10. **三层清零** 由 `push 0x70800 / push 0 / push <base> / call 0x47F190`（memset）完成，3 组共 9 个调用点：
    - 0x43F651 清 0x5ADE40、0x43F665 清 0x4CCE40、0x43F679 清 0x53D640（函数 0x43F64E–0x43F68E）
    - 0x43FAC7、0x43FADB、0x43FAEF（函数 0x43FAB0–0x43FB08）
    - 0x43FC66、0x43FC81、0x43FC95（函数 0x43FC09–0x43FCB1）
    - `0x70800 = 460800 字节`，按 240 B/行 = **1920 行**（远超 40 行地图）⇒ **三层是整屏图层**。三层总占用 `0x4CCE40 → 0x53D640 → 0x5ADE40 → 0x654040`，每层 0x70800。

11. **18 个调用者**（全部 `call 0x43D67F`）：0x42CC93、0x42D17C、0x42D192、0x42D38A、0x42DACE、0x42E270、0x43EAF4、0x43EBE2、0x43EC55、0x43EC8D、0x43ECA3、0x43F70D、0x43F78A、0x43F7D6、0x43FBE0、0x43FBF6、0x468D21、0x46A47E。

### 3.5 六角格描边绘制器 0x43FCB2–0x43FE6B（选中/目标高亮框）

参数 = 列 [ebp+8]、行 [ebp+0xC]。步骤：

1. `call 0x43CDCE(col,row,&x,&y)`（0x43FCCA），失败即返回；
2. `call 0x42311B`、`call 0x43EA91`（先重绘全图）、`mov byte[0x498D78],1`；
3. `call 0x43D5AE(col)` → 格心 y；`imul ecx,0x18 / movsx edx,byte[ecx+0x4A0206] / sar edx,1 / sub eax,edx` → 改为 格心y − 行高/2；
4. `call 0x43D5F2(col,row)` → 格心 x，减 `byte[+0xB]/2`，再 `sub edx,1`；
5. `[ebp-0x20]` 循环 4 次（`cmp eax,4 / jge 0x43FE5B`）：`push i / push 0x4A0300 / call 0x4383FD`；`((i-2)&3)!=0` 时再 `push i / push 0x4A030C / call 0x4383FD`；`call 0x43C920` 判可见；可见则 `call 0x425817` 画一段；
   尾段 0x43FE0A–0x43FE3B 以 `movsx …, byte[edx*4 + 0x4A0200/0x4A0201/0x4A0202]` 取顶点偏移（步长 4），最后：
   ```
   0x43FE3B  mov  ecx,[0x655574]
   0x43FE42  call 0x425817
   ```
6. `0x43FE5B push 1 / push 1 / call 0x421B61`（上屏）。

**注意**：0x43FCB2 本身**不是 `call` 目标**（`_callers2.py 0x43FCB2` 命中 0 处）⇒ 它通过指针/跳转进入，进入点未证实。

          call 0x4235E5

再 `and edx,1`（bit21）非 0 时用同表、硬编码 id **3** 再调一次 `0x4235E5`。

`0x4235E5` 的头：`push 0 / push 0x1008000 / push [ebp+0x18] / push [ebp+0x14] / push [ebp+0x10] / push [ebp+0xc] / push [ebp+8] / call 0x47E0A0`，随后检查 `[ebp+8]→+0x10 == [0x676904]`（后备缓冲）以决定是否走额外路径。

## 4. 重点：移动范围阴影（半透明六角格覆盖层）到底由谁绘制

### 4.1 结论（是/否）

**是** —— 「按格把覆盖物画到地图面并做层次遮挡」的代码就是 **`0x43D67F`（逐格像素写入器）**，置信度 **高（约 0.85）**。

**否 / 未证实** —— 我**没有**在静态代码里找到「按单位移动力做可达格集合（BFS/距离场），然后把这个集合交给 0x43D67F」的那段生成器。也就是说：**阴影的「像素落点」已定位，「可达格集合的来源」未定位**。置信度：生成器不在我已核实的清单内（高置信），但它具体在哪（中置信以下）。

### 4.4 「阴影只闪一下」的机制解释（有代码依据）

1. `[0x498D74]` 是**单标志多消费者**：30 个清 0 点，每个消费者「读到 ≠0 → 重绘自己那部分 → 清 0」。本帧更早的消费者（如 `0x4489EA`，就在每帧分发器里）会先把信号吃掉 ⇒ 地图覆盖层拿不到重画信号。
2. 即使拿到信号，覆盖层也依赖 `0x43D67F` 的层 B/C 位图决定「哪些格还需要重画」；而层 B/C 由**成组整体清零**（0x43F651/0x43F665/0x43F679 等 3 组）恢复，与 `0x4AF324` 开关（0x42CF82 / 0x42CF8D 写 1）联动。任何「每帧强制整屏刷新」的补丁都会抢先清 `[0x498D74]`，使 `0x43F71D`/`0x42D0F2` 不再被触发，于是**阴影出现一帧后消失**。
3. 由于 `0x4CCE2C + 0x14 == 0x4CCE40`（层 B 基址），**按 0x24 步长越界遍历控件数组会直接踩图层 B** —— 宽屏补丁若扩大了控件数组的遍历范围，会破坏覆盖层的遮挡标记。这是可解释「阴影错乱/残留」的机制之一。

## 5. 未解疑问（明确标注「未证实」）

1. **移动范围（可达格集合）的生成器未定位。** 已排除 0x43FCB2（描边）、0x41F685（单位/标记精灵）、0x42D0F2（只按 `0x622D4A` 的格值与 `[0x686FD4]` 相等性分流，不是距离场）。**未证实**：谁读单位移动力/行动力并做 BFS。
2. **`0x622D4A` 表的字段语义未证实。** i16 值出现 1、2、9…17 的比较（0x42F991、0x42FDBA、0x42FE40：`sub eax,9 / cmp eax,8 / ja`），也出现与 `[0x686FD4]` 的相等比较（0x42D16C）。是「单位 id」「占据值」还是「类别」未定。
3. **`0x6268A0` 的 65 字节/格的字段布局未证实。** 只证实了 `+0` 与 `+1` 两层各为 u8，以及 `0x1964 = 100×65` 的分类步长；65 个字节里其余字段未展开。
4. **`0x65AA00` 单位表的字段布局只证实了一部分**：`+0x04` bit25 = 占用、`+0x52` = 列、`+0x54` = 行、`+0x38` 被读（移动力候选，**未证实**）、`0x6268A1` 处需为 1 才继续（0x410EF5 `cmp ecx,1 / jne`）。其余 88 字节未展开。
5. **`0x4C90A0` 索引表语义未证实。** 该地址及整个 0x4C9000 段在磁盘上全 0（BSS），且 **0x4C90A0 本身在 .text 中无任何直接引用**；邻近被引用的 0x4C90C0（0x453B19）、0x4C90D4（0x450356）、0x4C90E0（**0x41C4B3**，即 0x490470 记录表绘制函数内）、0x4C90F0（0x442158）、0x4C9120（12 处，0x445E69–0x4470B2）、0x4C91A0（6 处，0x446759–0x447997）。⇒ 只能确认「0x41C4B3 与 0x445xxx–0x447xxx 绘制族引用它附近」，**结构与项数未证实**。
6. **`0x4A2DF8` 坐标/矩形阵的项数未证实**；「个数在 0x4A2DD8」经实测**不成立**（该处是 i16 `255,0,-1,0`）。
7. **`0x4AF460`（控件边界表）的写者未找到。** 该地址在 BSS，且本次未取得写者。
8. **`0x4AF45C`（六角格参数选择器）无任何写者。** 44 处引用全为读 ⇒ 运行时恒为 0。若确实没有写入，则六角格几何**永远用第 0 项**；这既是「800×600 语义固化」的证据，也意味着**改这一个 word 就能换一套格尺寸**（仅 2 项已在盘上证实，更多项未证实）。
9. **`0x43FCB2`（描边）的入口方式未证实**：它不是 `call` 目标，可能经函数指针/跳转进入。
10. **`[0x499150]`/`[0x499154]`（视口宽高对）的完整写者集合未证实**，只确认 0x4523F9/0x45247E/0x46C999/0x46CA13 等 500 相关点。
11. **0x676314 / 0x676310 / 0x676120 / 0x61FB44 / 0x61FB40 这几张资产表的实际内容未证实**（BSS 或外部资源）；字段 +8/+0xC 的「锚点/热点」语义由绘制点用法推断，非直读。
12. **1bpp 层 A（0x5ADE40）对应哪一类覆盖物未证实**；层 B/C 只确认是「已画覆盖物」标记位。
