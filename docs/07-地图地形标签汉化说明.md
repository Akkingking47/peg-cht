# 07 · 地图地形标签汉化说明（`hex_text.png`）

> 结论先行：**地图上的地形标签不是文字，是位图。**
> 它来自 `OPENGUI\hex_text.png`（或各 efile 自带的 `EFILE_xxx\OPENGUI\hex_text.png`）。
> 任何改 exe 字符串 / `strings-XX.txt` / `strings_efile.txt [terrain]` 的做法都不可能影响它。

---

## 一、问题现象

- 顶部状态栏的地形名早已汉化（`strings_efile.txt` 的 `[terrain]` 段生效）。
- **鼠标悬停时地图上出现的那个地形标签始终是英文**，且历经以下尝试均无效果：
  - `strings-zh.txt` 第 22–41 行（已汉化）→ 无效果
  - exe 内置地形名表 `0x5842A0`（已汉化）→ 无效果
  - 新建 `TEXT-ZH\TerrainEx.txt` → 无效果（`TerrainEx.txt` 是**力学数据**，不含显示名）
  - efile 根目录 `strings_efile.txt` `[terrain]` → 只影响顶部状态栏

## 二、排查过程与关键证据

| 步骤 | 结论 |
|---|---|
| 全 exe 搜 `Escarpment` / `Bocage` / `Swamp` / `Ocean` | 只命中 `0x5842A0` 那张 21 项、步长 `0x100` 的表 |
| 该表原始内容 | `Clear / City / Airfield / Forest / Bocage / Hill / Mountain / Sand / Swamp / Ocean / River / Fortification / Port / Stream / Escarpment / Impassable River / Rough / Rubble / Roads / Rails / Shallow Sea` |
| 该表已被汉化，且**运行时内存中确认一致** | 它是「地形数据 / 工具提示」用的内置名表，**但地图标签不读它** |
| `.data` 里 0x100 步长的大表（`0x5857A0` 起，916 项） | 与 `strings-XX.txt` 的**行号一一对应**（第 22–41 行 = 地形名，已汉化） |
| 各 `strings-XX.txt` / `strings-en-template.txt` | 第 22–41 行为 `Clear…Rails`，即**文本**地形名（只喂状态栏等文本位） |
| **内存级排查**：全进程扫描 `scarpment`/`SCARPMENT`/`Bocage`/`Shallow Sea`/`UNDERBRUSH` | **0 命中** —— 进程里根本没有任何英文地形名文本 ⇒ **标签必然是图形** |

**决定性线索**：exe 的图形资源名清单里与 `hex_blend` / `hex_grids` / `hex_types` / `hex_marks`
同组出现 `hex_text` —— 即 `OPENGUI\hex_text.png`。

## 三、位图结构（已逐像素解析）

| 项 | 值 |
|---|---|
| 尺寸 | `60 × 950`（全局）或 `60 × 900`（部分 efile） |
| 分格 | 每格 **50 px** 高，共 19 格（900 高的是 18 格） |
| 索引 | 第 i 格 ↔ 地形 ID i，与 `TerrainEx.txt` 的 `0=clear … 17=custom, 18=shallow waters` **完全一致** |
| 第 0 格 | 官方设计为**空**（Clear 不标注） |
| 标签位置 | 每格内距顶部 +4…+15 px，水平居中 |
| 背景 | 全局 `#F8E4D8`（粉），OPENPG 等 `#FF00FF`（品红）——**都是色键（colorkey）**，两份原图都**没有 tRNS 块**，靠 `SDL_SetColorKey` 实现透明 |
| 原始风格 | 全局：彩色底牌 + 黑/白文字；OPENPG 等 4bpp 版：**带黑边的彩色文字**（无底牌），按地形配色（植被黄、水蓝、断崖/不可通行红） |

## 四、汉化方案与实施

工具：`work/gfx/redraw-hextext.ps1`（纯 ASCII 脚本）
标签表：`work/gfx/terrain-labels-zh.txt`（UTF-8，按地形 ID 顺序）

做法：

1. 逐格统计原图主色与填充率（`主色像素数 / 外接矩形面积 ≥ 0.55` ⇒ 该格是「底牌型」，否则是「文字型」）。
2. **底牌型**（全局 atlas）：沿用原底牌颜色，按对比度自动选黑/白文字，重绘为「底牌 + 中文」。
3. **文字型**（OPENPG 等）：沿用该格原文字色与黑描边，重绘为「黑边 + 中文」；字数 ≤3 时字号放大到 15 px 保证可读性。
4. 输出**同尺寸、同步长、8bpp 索引 PNG**，**调色板 index 0 的 RGB 与原图完全一致** ⇒
   不管游戏是按调色板索引还是按像素值做色键，透明都继续有效。
5. 第 0 格（Clear）保持为空，与官方设计一致。

已处理（**8 份**）：

| 文件 | 尺寸 | 原风格 | 现风格 |
|---|---|---|---|
| `OPENGUI\hex_text.png` | 60×950 | 彩色底牌 + 黑/白字 | 底牌 + 中文（**OLGWW2 等多数 efile 用这份**） |
| `EFILE_OPENPG\OPENGUI\hex_text.png` | 60×900 | 黑边彩字 | 黑边 + 中文 |
| `EFILE_COMWW2\OPENGUI\hex_text.png` | 60×900 | 黑边彩字 | 同上 |
| `EFILE_OPENPEG\OPENGUI\hex_text.png` | 60×900 | 黑边彩字 | 同上 |
| `EFILE_KAISER\OPENGUI\hex_text.png` | 60×950 | 黑边彩字 | 同上 |
| `EFILE_OPENAK\OPENGUI\hex_text.png` | 60×950 | 黑边彩字 | 同上 |
| `EFILE_OoB\OPENGUI\hex_text.png` | 60×950 | 黑边彩字（字号更大） | 同上 |
| `EFILE_SON\OPENGUI\hex_text.png` | 60×950 | 同全局图 | 同全局图 |

**例外（故意不动）：`EFILE_Clu\OPENGUI\hex_text.png`** —— 它这一格不是文字，而是
**16×16 的图标**（灰底圆形象形图：城镇格网、树木、山峰、水波…）。图标无需翻译，
脚本的外接矩形平均宽度 < 20 px 时会自动识别为**图标型 atlas 并跳过**。

脚本另有一道护栏：成品 PNG 的调色板有 256 项，原图只有 8–17 项，
所以对**已汉化的文件**再跑一次会直接 `SKIP: already converted`，
要求先从备份还原（或显式加 `-Force`）—— 防止在成品上二次转换把画面搞乱。

## 六、备份与还原

| 备份 | 对应 |
|---|---|

| `EFILE_OPENPG__OPENGUI__hex_text.png` | `D:\OpenPG2\EFILE_OPENPG\OPENGUI\hex_text.png` |

```powershell
Copy-Item 'D:\DSH\军事游戏汉化\backup\hextext-orig\OPENGUI__hex_text.png' `
          'D:\OpenPG2\OPENGUI\hex_text.png' -Force
```

```powershell
& 'D:\DSH\军事游戏汉化\work\gfx\redraw-hextext.ps1' `
  -Labels 'D:\DSH\军事游戏汉化\work\gfx\terrain-labels-zh.txt' `
  -BackupDir 'D:\DSH\军事游戏汉化\backup\hextext-orig' `
  -Include 'OPENGUI\hex_text.png'
```

## 八、验证方式

改动生效需要**重启游戏**（`OPENGUI` 里的贴图在进入/载入场景时加载）：

- 打开「附加选项」勾上 **Show Terrain labels and data**（显示地形标签与数据）
