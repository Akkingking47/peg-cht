# PeG-WW2 DOCS 面向玩家文档汉化 · 经验总结

> 项目：《PeG-WW2》（People's General 二战合成 MOD，SSI *modgen* 1998 引擎）**面向玩家说明文档**的汉化
> 范围：`D:\Program Files\PeG-WW2\DOCS\` 下**面向玩家**的说明文档（排除扫描版 PDF、MOD 作者向指南、版权资料）
> 产出：`pegww2\docs-zh\`（**不在游戏目录就地替换**）
> 分批：**D1 入门 5 份 · D2 战役安装说明 20 份 · D3 战役情报评估 6 份 · D4 旧 readme 15 份 · D5 战役路径表 27 份**

---

## 一、结论先行：这类活儿的成败点只有三个

1. **键约定**（段号/行号）在「抽取」和「回写」两侧必须同一套，且**中途绝不可变**——它是全流程的骨架。
2. **"名字"永远不要自动翻译**——人名、文件名、地图 stem、URL、版本号。凡"看起来像词"的标识符，盲查表/盲译都会制造**跨全库的一致性错误**。
3. **子代理"零产出"≠"没干活"**——先翻它的临时文件与工作目录，再决定重跑。

## 二、五道质量门（每份产物都过）

| 门 | 判据 | 实现 |
|---|---|---|
| **G1 段数/行数一致** | 与原文一一对应，不增不删 | `doc_translate.py verify` / `doc_rtf.py verify` |
| **G2 结构完整** | 标记/控制字未坏：RTF 用**控制字计数 + 花括号总数 + 未译文本序列**；TXT 用制表符个数 | 同上 |
| **G3 保护串零漂移** | 文件名/路径/URL/版本号/人名逐字符不变 | 抽取时替换为 `\x01N\x02` 占位符，回写还原；清单**记进 `_src` 表** |
| **G4 术语命中** | 对照 `_翻译须知与术语.md` | 人工抽查 + 术语一致性扫描（成对词并存检查） |
| **G5 无残留整段英文** | 段级扫描，专名/型号/URL/文件名白名单除外 | `verify` 的"疑未译"告警，逐条人工归因 |

## 三、⚠️ 十四个坑（都真实踩过，附证据）

### 编码/格式类

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| **T1** | RTF 回写用 `latin-1, "replace"` | **所有中文变成 `?`** | 自写 `to_rtf_bytes()`：ASCII 原样；`≤0xFF` 按裸字节；cp1252 特殊区写 `\'xx`；**CJK 写 `\uN?`** |
| **T2** | `\'xx` 转义当控制字 | 重音字母丢失、**URL 被切碎** | 解析时把 `\'xx` 还原成字符 |
| **T3** | 无 BOM 的 `.ps1` | Windows PowerShell 5.1 按 **GBK** 解析中文注释 ⇒ 语法崩 | `.ps1` 一律**带 UTF-8 BOM** |
| **T4** | Word 生成的 RTF 里 `{\*\…}` **可忽略目标组**（SmartTag/factoid） | `PlaceType`/`place`/`PlaceName` 被当正文译 ⇒ 损坏元数据 | **按字节区间**屏蔽 `{\*…}` |

### 键约定/偏移类（最危险）

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| **T5** | 为识别 `\*` 而**改解析词法** | **段号空间整体位移 ⇒ 毁掉所有既有译稿**（同 W21 教训） | 立刻回退；改用**不动词法**的区间屏蔽。**段号是抽取↔回写的键约定，绝不可变** |
| **T6** | 偏移量用「chunk 长度累加」 | 遇 `\'xx`（4 字节→1 字符）**漂移**，区间屏蔽只生效一半 | `parse_off()` 记录每段的**真实字节偏移** |
| **T7** | 保护串清单**每次重算** | 改一次规则 ⇒ 旧译文占位符错位 | 清单**写进 `_src` 第 4 列**，回写以它为准 |

### 数据/流程类

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| **T8** | 清理动作删了**未合并**的中间产物 | `_task-D201-02.tsv` 93 段译文丢失 | ① 让原代理**凭上下文重写恢复**（93/93 成功）；② **先合并、后清理**：`prune_fills.py` 裁剪前自动 `merge_one()` |
| **T9** | 子代理**自建合并/清洗脚本** | 它卡在自己的脚本里 ⇒ **整轮零产出**（407 段、204 段两次） | 提示词**明令禁止写脚本**；要求**分 3–5 次增量落盘**（每次 ~50 行） |
| **T10** | 词库**自动命中无护栏** | `Robert Mary` → 「罗伯特·马里」**跨 20 个文件一致地错**；`Don`(Don't 碎片) → 「顿河」 | `NEVER_AUTOFILL` 名单（人名/厂牌**永不自动翻译**）；命中后**抽检** |
| **T11** | 一次写 400+ 段 | 大写入卡死/超时 | 单片 **≤250 段**；大文件切 2 片 |

### 校验本身出错（最隐蔽）

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| **T12** | `verify` **重新解析自己的成品字节** | 中文以 `\uN?` 写出，兜底字符 `?` 被解析成**新的文本段** ⇒ 「未译文本逐字节」**必然误报**；而且我**只看了输出的最后一行**，把失败当通过看了好几轮 | **索引对齐**：拿「写出的 chunk 序列」与「原文 chunk 序列」逐位比较（译文段只校验它带 `\fCJK` 前缀），再比 `\par` 计数与花括号计数。**成品编码会骗过重新解析的校验** |
| **T13** | 只看日志最后一行 | 前 3 列是 ❌ 而我只看到末行的「疑未译」计数 | 校验输出**整体看**；关键门写成一行内的多个 ✅/❌，且**返回非零码** |
| **T14** | 合并靠**任务表首行注释**里的源文件名匹配 | 子代理"顺手规范化"了首行（`PeGWW2`→`PeG-WW2`）⇒ 匹配失败，**整片 35 段译文没并进去**（同 W21 键约定漂移） | 生成分片时登记 **`_chunks-index.tsv`（tag→rel）**，合并**按 tag 定位**，不再依赖可被人改写的注释；并给任务表加"不要改首行"的提示 |

> 🔑 **教训（已入台账）**：**"自己的校验器"是头号风险点**。
> ① 校验应由"我写了什么"推导，而不是"重新读我写了什么"（后者会被输出编码骗）；
> ② 校验结果必须**整体判读**，不能只扫末行；
> ③ 校验器改动后要**用已知通过/已知失败两组样例各跑一次**。

## 四、可复用判据（本项目"挣"来的）

1. **动手改文本前，先问英文原版是否本来就放得下**（避免把"原版就存在的缺陷"当成自己的锅去改）。
2. **忠实包含信息密度**：压缩到"看得懂"但丢信息，不算忠实。
3. **批量改写脚本必须带回归断言**（本项目：36 条断言 + 区间占用检查）。
4. **apply 侧与 consume 侧必须共用同一套键约定**（大小写、分隔符、转义）——本项目因"覆盖文件名大小写"与"段号空间"两度吃亏。
5. **跨语言审计要有同语言基线**（拿中文译文去比英文关键词 ⇒ 假阴性）。
6. **词库自动命中必须带"永不自动译"护栏**，且命中后抽检。
7. **先合并、后清理**：删任何中间产物前，确认内容已并入正式产物。
8. **零产出先查临时文件**：子代理"没交付"往往意味着"交付到了别处"。
9. **校验器由"我写了什么"推导，不要重新读成品**——输出编码会骗过重新解析的校验。
10. **校验结果整体判读**，别只扫最后一行；关键门压在一行里并返回非零码。

## 五、工具链（`work\pegww2\`）

| 工具 | 用途 | 关键设计 |
|---|---|---|
| `doc_translate.py` | TXT：抽取 / 回写 / 校验 | `_staging` 优先；保护串占位符；首行 BOM |
| `doc_rtf.py` | RTF：抽取 / 回写 / 校验 | `parse_off()` 精确偏移；`mask_heads()` 屏蔽元数据；`to_rtf_bytes()` 安全编码；**CJK 字体条目**注入 `{\fonttbl…}` 组尾 |
| `doc_xls.ps1` | `.xls`：抽取 / 回写（Excel COM） | 另存副本，原件零改动；**带 BOM** |
| `verify_xls.ps1` | `.xls`：逐格核验 | **只开副本**（同实例开两个 workbook 会 `E_FAIL`） |
| `make_chunks.py` | 大译表切 ≤N 段任务片 | 每份独立 tag，避免撞名覆盖 |
| `merge_tasks.py` | 分片译文按段号合回主表 | `merge_one(rel)` 可被其他脚本调用 |
| `prune_fills.py` | 按当前可译判定裁剪译表 | **裁剪前先合并** |
| `autofill_docs.py` | 词库自动命中 | 真源 + 表头表 + 基名回退 + **`NEVER_AUTOFILL` 护栏** |
| `merge_d5_remain.py` | D5 余量按原文精确回填 | — |

**单一真源**：`doc_rtf.eligible()` 是"可译判定"的唯一实现，抽取/回写/校验/切片脚本都调它。

## 六、子代理编排纪律（实测定稿）

| 项 | 定稿 | 依据 |
|---|---|---|
| 并发 | **≤2** | 用户原话「不要一次并发太多」；场景层曾因 3 并发压死宿主 |
| 单片段数 | **≤250** | 407 段一次性失败 |
| 落盘 | **分 3–5 次编辑，每次 ~50 行** | 一次大写入卡死 |
| **禁止** | **自建辅助/合并脚本** | 两度因它卡在自己脚本里 ⇒ 零产出 |
| 提示词必带 | 术语表 + **保护串红线**（人名/文件名/地图 stem） + **RTF 断句片段**说明 | 保证跨片一致 |
| 交付后 | 立即 `merge_one` → `prune` → 再开下一个 | 避免未合并的中间产物被清理掉 |

## 七、RTF 处理要点（本作 DOCS 多为 Word 生成 RTF）

1. **段 = 两个控制字之间的裸文本**；段内换行/制表折叠为空格（RTF 空白不参与排版）。
2. **中文必须换字体**：往 `{\fonttbl…}` **组内末尾**插 `{\fCJK\fnil\fcharset134 SimSun;}`，并在每段译文前加 `\fCJK`。
   ⚠️ **不能按位置比对控制字**——插条目会让其后全部错位（校验改用**计数**）。
   ⚠️ `{\fonttbl{…}}` 的**组深度**要把「控制字后紧跟的 `{`」只算 1 层。
3. **必须屏蔽**：`fonttbl/colortbl/stylesheet/info/listtable/…`（17 个元数据组）、`\fldinst` 字段指令、含 `HYPERLINK/PAGEREF/…` 的段、`{\*…}` 可忽略目标组。
4. **byte 级保真**：`parse_off` 精确偏移 + 未译文本**序列相等**校验。

---

## 八、Excel（`.xls`）要点

1. 本机 Excel COM **同实例开两个 workbook 会 `E_FAIL`** ⇒ ① 回写只开原件；② 核验**只开副本**、靠译表里的原值反查。
2. 回写另存副本（`xlExcel8`），**原件零改动**。
3. 表格内容大量是**场景名/地名/表头** ⇒ 优先用**已有真源词库**（本项目命中 53%+），人名词条必须走护栏。
4. **地图文件名 stem 保留拉丁原文**（它们是文件引用，译了反而对不上）。
